# Stlkr level12: умеренный профиль дальности

18.10.2026. База: `d8b99a3632b1eb07828f3ba2638e7483e2dc3ae7`.

## Что изменено

В `configs/stlkr/level12.txt` **только одна замена** относительно одноимённого
файла из `Stlkr by ebk.jar (1).zip`:

```diff
-DIST=39000
+DIST=30000
```

Это **компромисс по дальности**, а не оптимизация с идентичной картинкой.
Дальние поверхности исчезают раньше; это может быть заметно на фоне неба.
`FOGD=26000`, `DMODE=3`, RGB тумана `40,40,40`, панорама, дождь
(`WEATHER_PARTICLES_COUNT=10`), NPC, скрипты, предметы и геометрия не изменены.
Код движка не менялся. Параметр DIST общий для M3G и Software: сокращение
дальности относится к обоим, но приведённые ниже счётчики измерены только M3G.
Исходный архив не перепаковывался и не редактировался.

## Выбор параметров

Сначала проверены `CHUNK_SIZE=20000/40000/50000` с исходной дальностью.
Во всех трёх случаях все 320 строк замеров совпали с исходными: выигрыша нет.
Более мелкие render chunks не включены: текущий Room.render посещает только
соседние ячейки, а полигоны назначаются первой пересекающейся ячейке. Это не
универсальное безопасное frustum-разбиение и может обрезать видимую карту.
`CHUNK_COLLISION_SIZE` также не трогали.

После этого проверены умеренные варианты DIST. Одинаковый текущий движок,
туман включён; 80 прогретых поз с фиксированными idle-объектами:

| DIST | Сумма D | Максимум D | Сумма native треугольников |
|---|---:|---:|---:|
| 39000, оригинал | 2412 | 105 | 7981 |
| 32000 | 2267 | 93 | 7281 |
| **30000, выбран** | **2217** | **93** | **7026** |
| 28000 | 2131 | 92 | 6698 |

30000 даёт дополнительный выигрыш относительно 32000, сохраняя запас 4000
за концом LINEAR Fog. Вариант 28000 агрессивнее сокращает дальность, но
уменьшает максимум всего ещё на один draw, поэтому не выбран.

## Результат и ограничения

- С объектами: суммарные D **2412 → 2217 (−8,1%)**, максимум **105 → 93**.
  В прежней пиковой позе — **105 → 78**, но это не новый максимум по набору.
- С объектами: native треугольники **7981 → 7026 (−12,0%)**.
- Только мир: D **2027 → 1841**, максимум **99 → 73**.
- В обоих наборах: 24/80 поз улучшены, 55 неизменны, **одна ухудшилась на 1 D**
  (north-zombie, yaw 270, pitch 45: 24 → 25). Удаление дальних поверхностей
  может менять границы пакетов, поэтому draw count не обязан убывать в каждой позе.
- Level13: все **320 строк** контрольного набора совпали с базой, максимум 75.
- В полной сборке **149 class entries побайтно прежние**, из 442 ресурсов
  изменён только `level12.txt`. Все остальные 441 ресурса побайтно прежние.
- CLDC preverification и audit пройдены. 10 Python resource-тестов; M3G suite
  с level12 и level13 пройдена, включая fallback без JSR-184. Из конечного
  JAR перед тестами извлечён resource-only JAR (runner не принимает игровые классы).

Это API-double fixture: 240×320, пять точек × восемь yaw × два pitch,
мир отдельно / мир с объектами, cold/warm, фиксированный дождь. NPC не
выполняют AI, спавнеры не активируются; физика, крыши и молнии не моделируются.
Суммы — по 80 отдельным прогретым ракурсам, **не по 80 последовательным кадрам**.
Полноценный визуальный прогон и FPS на телефоне не измерялись. Сокращение DIST
не устраняет CPU-преобразование всех вершин видимой комнаты, поэтому −8,1% D
нельзя пересчитывать в +8,1% FPS.

Машиночитаемые результаты и все проверенные варианты:
[`diagnostics/level12-config.json`](diagnostics/level12-config.json).

## Воспроизведение и откат

Overlay включается **только явно**. Обычный движок и сборки с другими архивами
не получают Stlkr level12 автоматически:

```sh
python scripts/build_cldc.py \
  --java "$JAVA" --ecj-jar "$ECJ_JAR" \
  --api-dir build/sdk/lib --proguard-jar build/sdk/proguard/lib/proguard.jar \
  --resource-archive 'Stlkr by ebk.jar (1).zip' \
  --resource-overlay configs/stlkr \
  --output-dir artifacts/stlkr-level12

python scripts/game_resources.py \
  --archive artifacts/stlkr-level12/Quantum.jar --output-dir build/stlkr-level12
QUANTUM_RESOURCE_JAR="$PWD/build/stlkr-level12/resources.jar" \
  QUANTUM_LEVEL12_PROBE=1 python tests/m3g/run.py
python tests/resources/test_resources.py
```

Для baseline убрать `--resource-overlay` и подготовить ресурсы из оригинального
архива. Для level13 заменить `QUANTUM_LEVEL12_PROBE=1` на
`QUANTUM_LEVEL13_PROBE=1`. Переменные JAVA/ECJ_JAR должны указывать на установленные
Java и ECJ. `--resource-overlay` применяется после архива и `res/`, запрещает
подмену `.class`/`META-INF` и записывает SHA-256 overlay-файлов в build-report.

Откат: убрать overlay при сборке либо вернуть в level12 `DIST=39000`.
Готовая полная сборка сохраняет имя `downloads/Quantum_Stlkr_FogBatch_ARM9.jar`;
движок `downloads/Quantum.jar` остаётся прежним и не содержит этого профиля.
