# Подготовка native M3G: нормали и сборка пакетов

Дата: **18 октября 2026**. Это продолжение [CPU-оптимизаций](cpu-optimizations.md).

## Изменения

- `M3GMode5Lighting.packNormals`: один ограниченный кэш квантованной нормали.
  Ключ — компоненты normal, наличие eye-space и все 9 компонентов вращения
  камеры. Translation не влияет на нормали. Нулевая/вырожденная преобразованная
  нормаль дополнительно зависит от fallback lightdir. Кэш общий для native
  pipeline, значения проверяются, идентичность mutable Matrix не используется.
  Это только скалярные поля: нет кэша на каждую грань и массивов на каждый кадр.
- `M3GPolygonBatch.appendVertices`: для обычного triangle целые XYZ/UV/RGBA/
  normals копируются одним `arraycopy` на канал вместо трёх маленьких.
  Оба существующих quad-порядка разбираются на три последовательных участка,
  без сортировки или смены диагонали. Необычный порядок обрабатывается старым
  повершинным циклом; изменение массива индексов на месте учитывается.
- Размер пакета **не менялся**: 192 вершины / 64 треугольника. Порядок painter,
  прозрачность, light/fog state, draw/texture/barrier boundaries сохранены.

**Прямая запись компонентов проверена и отвергнута.** На этом KVM она медленнее
маленьких `arraycopy`: triangle unlit 1.004 → 1.484 мс, quad lit 2.016 → 2.891 мс
на 1000 упаковок. В релизе прямой записи нет; выбрано блочное копирование.

## Замеры

Неизменённый x86 KVM 1.1 из `klaxons1/j2me_cldc` commit
`9363b7152b3f3b367eb17a97195ebf035595fed1`, Xeon 2.60 GHz, heap 4 MiB.
Для каждой нагрузки отдельный процесс, калибровка ≥250 мс, прогрев, 5 samples.
Процессы измерялись последовательно, без параллельного benchmark.

Ниже медиана **в миллисекундах на 1000 вызовов**, не время игрового кадра.

| Ядро подготовки | До, мс | После, мс | До / после |
|---|---:|---:|---:|
| Нормали без OMNI, одна нормаль | 2.312 | 0.590 | 3.92× |
| Нормали в eye-space, одна нормаль | 4.109 | 0.820 | 5.01× |
| Нормали без OMNI, постоянно разные | 2.562 | 2.789 | 0.92× |
| Нормали в eye-space, постоянно разные | 4.359 | 4.859 | 0.90× |
| Копирование triangles, unlit | 1.004 | 0.623 | 1.61× |
| Копирование triangles, lit | 1.145 | 0.654 | 1.75× |
| Копирование quad, unlit | 1.762 | 1.332 | 1.32× |
| Копирование quad, lit | 2.016 | 1.539 | 1.31× |

**Кэш не бесплатный при промахах.** В constantly-varying тесте нормаль меняется
на каждом вызове: дополнительное время составляет около 9% без eye-space и
11% в eye-space. Ускорение 4–5× относится только к повторяющимся нормалям,
не ко всем мешам. Это выгодный случай для плоских повторяющихся граней,
но на полностью уникальных/анимированных нормалях выигрыша нет.

При benchmark нормалей количество выходных вершин — 3; eye-space использует
фиксированную камеру с yaw=37°. Нулевые нормали/изменение камеры покрываются
тестами корректности, а не отдельными строками времени. Копирование измеряет
1000 вызовов packing kernel, с lit/unlit каналами и переиспользуемыми массивами;
quad соответствует порядку `0,1,3,1,2,3`. Вторая диагональ проверена на равенство.

Baseline использует старую формулу нормалей и старый per-vertex `arraycopy`.
Для сравнения исходный цикл append механически выделен в API-free static
`appendVertices` с той же сигнатурой, что у оптимизированного ядра. Поэтому
сравнение относится к **ядру упаковки**, а не ко всему `add/flush` pipeline;
дополнительный wrapper-call в интегрированном batch и native submission
не входят в эти времена.

Несмотря на имя M3G-классов, измеряемые static-методы не создают Material/Light
и не вызывают JSR-184. Они реально выполняются в KVM без заглушек graphics API.
Это **не замер GPU, draw/upload/readback, игрового FPS или телефона 220 МГц**.
В этом runtime по-прежнему нет M3G, MIDP entry point не загружается и ресурсов
уровня в текущем JAR нет. Число draw-вызовов этой оптимизацией не сокращается.

- SHA-256 JAR определяет измеряемый бинарник; checkout в момент замера dirty,
  `quantum_commit` в JSON не следует принимать за build commit.

`NativePrepTest` сравнивает с прежними формулами: 14000 наборов normal/camera/
light и последовательные изменения всех компонент, переключение null/другой
камеры, нулевые/сингулярные случаи, cache hits и разные выходные counts.
12000 packing-fixtures проверяют оба quad-порядка, нестандартные и меняемые
индексы, исходные массивы, XYZ/UV/RGBA/normals, неизменный prefix/suffix и
нетронутые normals для unlit.

Production SDK/preverification, полный M3G suite (включая отсутствие API),
оригинальный framebuffer и настройки/RMS проходят. Software и форматы ресурсов
не менялись. Native helper/tests не включены в JAR как отдельные тестовые классы.

Для повторного измерения — [среда из исходного отчёта](cldc-performance.md), затем:

```sh
JAVA=/path/to/java ECJ_JAR=/path/to/ecj.jar \
python tests/cldc_perf/run.py --suite native-prep \
  --cldc-root /path/to/j2me_cldc --app-jar downloads/Quantum.jar \
  --output build/native-prep/repeat
```

Если нужен локальный 32-bit loader, добавить `--loader` и `--library-path`, как
в исходной инструкции. `--tasks` позволяет выбрать отдельные workloads.
