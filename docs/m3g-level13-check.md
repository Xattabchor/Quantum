# Level13 Stlkr: проверка draw-вызовов

18.10.2026. Проверен `Stlkr by ebk.jar (1).zip`, добавленный пользователем
в `8eee325`. SHA-256 архива:
`3c77d2fe5db203e4571cdb12aea5d26721058fca327e2a39edce733492719f19`.

**Это исходная диагностика до оптимизации: Quantum M3G из `1e326c5`,
не старые классы архива.** На этапе этой проверки production-код,
готовый `downloads/Quantum.jar` и ресурсы не изменялись.
Последующая [точная оптимизация Fog batching](m3g-fog-exact-rebase.md)
сравнивается с этим baseline; исходный CSV сохранён без изменений.
Использованы реальные модели/текстуры/конфиги, production decoders,
House/порталы, MeshObject, SpriteObject и idle-render NPC. Вызовы M3G
перехватываются API doubles: это не GPU raster и не FPS на OMAP1710.

## Что находится в уровне

- Мир `/gamedata/maps/kordon/kordon.3d`, WORLD_SCALE=6, оптимизация модели ON.
  После неё: **15 комнат, 2322 вершины, 2125 полигонов / 3800 треугольников**,
  не считая отдельной модели порталов.
- Два material slots: 420 и 1705 полигонов. Оба ссылаются на **один RawImage**
  `/gamedata/maps/kordon/kordon.png`, 256×256. Это не две загрузки текстуры.
- `DMODE=3`, native LINEAR Fog; `FOGD=22000`, RGB=47,16,40; `DIST=30000`.
- `CHUNK_SIZE=29000` закомментирован; реально **render chunk size=0**.
  Портальное отсечение House сохранено, а не заменено отправкой всех комнат.
- Небо — **2D panorama**, `/sky/ksk.png` 64×64, repeat 4×2,
  `SKYBOX_2D=...,0.6,-18,64`, `SKYBOX_ALWAYS=1`.
- Начальный видимый набор конфигурации: **5 MeshObject, 23 SpriteObject,
  5 idle NPC**. Все эти NPC — **спрайтовые**, не MeshImage.
  Четыре NPC-spawner группы не активировались в этой проверке.
- `WEATHER` отсутствует и в level13, и в общих настройках: **дождь/снег не
  добавлялись искусственно**. В generic sky-contract tests есть отдельный
  искусственный дождь; их строки PASS не входят в результаты L13 ниже.

## Условия

240×320, обычный FOV конструктора 74, full texture quality, PERSQ=4,
Fog quality HQ, M3G perspective ON, mipmaps OFF. Точки: start, лагерь,
рядом с Ржавым, бандиты, военные. В каждой 8 yaw (0…315 с шагом 45) ×
2 pitch (0,45) = **80 ракурсов**. Для каждой камеры определяется собственная
комната через House.calcPart, затем вызывается House.getParts/render.

Для каждого ракурса сравниваются:

1. Мир + исходная панорама, без видимых объектов.
2. Та же сцена с MeshObject/SpriteObject и начальными idle NPC.

На каждый вариант новый renderer, четыре последовательных кадра;
в CSV сохранены первый (cold) и четвёртый (warm). Текстуры предварительно
не загружаются в native cache искусственным прогревом. Анимации спрайтов
перезапускаются перед render для snapshot кадра 0; AI, физика, скрипты,
бои, спавн и сохранённое состояние прохождения не моделируются. Без оружия,
HUD, damage/death overlays, погодных эффектов и замера heap телефона.

Проверка восстанавливает level globals перед **каждой** новой камерой:
DirectX7.destroy сбрасывает fDist/drawmode/drDist/fogc. Иначе следующие
измерения mode3 ошибочно ушли бы в CPU при fDist=1. Утверждения теста
проверяют значения конфигурации и native LINEAR Fog в каждом кадре.

|---|---:|---:|---:|---:|

Самый большой D в выборке — лагерь, камера
`(-110001,-2254,-115102)`, yaw=0, pitch=0, room=5:

| Состав кадра | Draw |
|---|---:|
| Небо | 2 |
| Полигональный мир | 74 |
| Отдельные меши | 13 |
| Спрайты, включая idle NPC | 6 |

pitch=45 в 6 из 40 ракурсов есть также настоящий CPU recovery одного полигона:
clipping не может безопасно представить его диапазон/точность. В остальных
34 наклонных ракурсах B=0. Прогретая выборка не вызвала отключение M3G.

## Почему много draw: дробление по Fog scale

В тяжёлом кадре лагеря:

- **77** разбиений по несовместимому Fog depth scale;
- 9 по текстуре, 7 по другим state differences;
- 0 по заполнению 64-triangle capacity.

Счётчики причин могут пересекаться: один flush может иметь несколько причин;
их нельзя складывать как взаимоисключающие категории.

В мире без объектов **texture splits=0 во всех ракурсах**, но scale splits
доходят до 71. Следовательно, основной источник дробления пакетов здесь —
не множество картинок мира, а eye-space масштаб для native Fog 3.

ProjectedGeometry.packFog сохраняет реальные единицы глубины для тумана,
используя бинарную depth lattice. Разным полигонам могут понадобиться разные
шаги этой решётки. В тяжёлом кадре 154 упаковки проходят shared-lattice путь,
одна — legacy pack, но переходы между разными shared scales всё равно
разбивают пакет. M3GPolygonBatch правильно требует одинаковый scale при Fog:
простое удаление этой проверки изменило бы туман. Сортировка по texture/scale
также не является безопасным решением для текущего painter/transparency order.

### Контрольный опыт, не правка игры

Отдельный прогон тех же 80 камер с `Main.fogQ=0` убирает native Fog у world/mesh
полигонов. Он нужен **только для диагностики**: изображение/туман меняются.
Поведение уже установленных sprite.fog не подменялось. Результат не является
обещанием такого же D при сохранении тумана или множителя FPS.

## Вывод

Следующая цель для уменьшения draw именно здесь — улучшение совместимой
упаковки/batching **Fog 3** с сохранением глубины, UV, точности и порядка.
Текстурный кэш после прогрева не выглядит источником лишних загрузок.
Оптимизация MeshImage из 1e326c5 не устраняет это дробление: NPC этого мода
спрайтовые, а отдельные модели идут через MeshObject. Дождь здесь не причина:
он не включён. Какие расходы доминируют во времени кадра, проверяется только
на устройстве: уменьшение API-вызовов не заменяет FPS/CPU profiling.

В setting.txt также есть CPU_PROFILE, FAST_LIGHT, PERSPECTIVE_STEP,
ARM9_QUALITY, AI_LOD/AI_LOD_DIST. Текущий исходный Quantum их не читает;
само наличие этих строк не включает дополнительную оптимизацию ARM9.
Этот диагностический проход не добавлял их поддержку и не менял конфиг.

## Данные и воспроизведение

[CSV всех 480 сэмплов](../tests/m3g/reports/level13-stlkr-draws.csv):
320 с исходным Fog (80 poses × 2 scene variants × cold/warm) и
160 контрольных (80 poses × objects × cold/warm).

После обычной CLDC-сборки, с JAVA/ECJ_JAR из инструкции сборки:

```sh
python scripts/game_resources.py --archive 'Stlkr by ebk.jar (1).zip' \
  --output-dir build/level13/assets
QUANTUM_RESOURCE_JAR="$PWD/build/level13/assets/resources.jar" \
QUANTUM_LEVEL13_PROBE=1 python tests/m3g/run.py
# Необязательный изменяющий картинку контроль, не конфиг игры:
QUANTUM_RESOURCE_JAR="$PWD/build/level13/assets/resources.jar" \
QUANTUM_LEVEL13_PROBE=1 QUANTUM_LEVEL13_FOG_OFF=1 python tests/m3g/run.py
```

Level13Probe и counters hooks — только тестовые. Instrumentation применяется
к временным копиям исходников; классы старого JAR исключаются из classpath.
300 PNG предварительно декодируются для desktop fixture Asset cache: это не
стратегия загрузки игры на телефоне и не оценка её потребления памяти.
Source-pixel snapshots проверены на неизменность.

- **166 PASS** default M3G; **177 PASS** Stlkr resources + level13,
  **177 PASS** отдельный контроль Fog OFF.
- Старый level41: **256 строк + 86 sky streams** полностью совпали с 1e326c5.
- Исходный архив и `downloads/Quantum.jar` byte-identical; новой игровой
  сборки в этой проверке нет. SHA-256 движка остаётся
  `d7a03d96d0855d4d7103d11a67b12da10a68478073414a2f21c1b6491e707374`.
- Локальные логи: `build/level13/{diagnostic,fog-off-control,default,
  level41-regression}.log`. Ни телефон, ни полный gameplay loop не запускались.
