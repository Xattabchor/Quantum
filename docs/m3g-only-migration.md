# M3G-only: контракт совместимости и начало переноса

**Текущий этап: [4a — native Canvas foreground](m3g-canvas-foreground.md).**
Оружие, реальные muzzle images, scope/crosshair, reload и timed overlay идут M3G;
остальные HUD/text/icons, меню и sampler Benchmark ещё не перенесены.
[Этап 3](m3g-required-path.md) требует native Scene без CPU replay/backup и
Software-переключателя, с явной диагностикой. Samplers пока физически в JAR.
[Этап 2 — depth bands](m3g-depth-bands.md) также в коде.
Ниже сохранены контракт и **исторический** аудит этапа 1 (`f566f7e`):
его 448 CPU dispatches в текущем Stlkr world-наборе устранены; strict gate проходит.

18.10.2026. Пользователь одобрил работу в текущей ветке с возможностью отката.
**Точка возврата — `b0ee49b`**: прежний движок с Software и агрессивными
конфигами всех 13 уровней Stlkr. История не удаляется; последующий откат
оформляется отдельным коммитом, а не переписыванием опубликованной ветки.

## Статус этого этапа

**Этап 1 — аудит и тестовый барьер. M3G-only движок ещё не готов.**
Код игрового рендера, форматы, ресурсы и downloads не менялись. Все 149 классов
заново собранного движка побайтно совпадают с опубликованным engine JAR.
Добавленная диагностика работает только в тестовых копиях исходников.
Нельзя объявлять перенос законченным, просто убрав Software из меню.

## Что необходимо сохранить

- Исходные `.3d`, `.vla`, PNG/QCT и остальные ресурсы должны загружаться
  прежними декодерами, по прежним путям. Конвертация пользовательских архивов
  или замена world-моделей новым форматом M3G не требуется.
- Сохраняются level/setting ключи, пресеты, имена предметов, скрипты, спавнеры,
  переходы, CP1251-текст, переводы строк и существующие сохранения. Перенос
  рендера не должен менять игровую логику, коллизии, AI или формат RMS.
- Совместимые режимы сохраняют **текущую M3G-семантику**, включая ранее
  одобренные отличия от Software. Не требуется воспроизведение старой
  программной картинки пиксель-в-пиксель.
- Без скрытого пропуска полигонов/спрайтов и без молчаливой подмены режима,
  например ADD → ALPHA, EXP → LINEAR или static RGB → динамическое освещение.
- Порядок прозрачных/аддитивных поверхностей, UV, cutout/alpha, зеркалирование,
  анимации и порталы должны оставаться покрыты проверками.
- CPU-декодирование ресурсов, физика, подготовка/отсечение геометрии и загрузка
  текстур **не являются софтрендером**. Их нельзя вырезать только из-за работы
  на CPU. Цель — убрать программную растеризацию и композицию сцены, а не CPU
  из всего приложения.

## Материалы: сохраняем уже реализованное M3G-поведение

| Режим | Нативное поведение, которое нельзя потерять |
|---|---|
| 0 | обычная текстура, исходный cutout |
| 1 | ALPHA |
| 2 | аддитивное смешивание |
| 3, 6 | native LINEAR Fog, настройки FOGD/FOGC и fog quality |
| 4 | текущая обработка RGBA/cutout по признаку alphaMixing |
| 5 | Texture2D BLEND, `M3G_BLEND_COLOR`, чёрный по умолчанию, без OMNI |
| 7 | MODULATE |
| 8 | исходный цвет заливки треугольника; без замены на текстурированный режим |
| 9, 13 | только исходный baked vertex light/RGB, без Fog и динамического света |
| 10 | MODULATE_X2 |
| 11 | DECAL |
| 12 | native EXP Fog, `M3G_EXP_FOG_COLOR` / `M3G_EXP_FOG_DENSITY` |

Для MUL-спрайтов сохраняется текущий MODULATE, для остальных — обычные
cutout/ALPHA/ADD и исходный порядок. Нативные небо, дождь/снег, sky-only
lightning и M3G post-effects сохраняются. BLOOM по прежнему контракту относится
к Software: в M3G-only версии он не должен внезапно включаться.

Не обещается работа на аппаратах без JSR-184 или с неподдерживаемыми native
возможностями. Размеры текстур, особенности Image target и лимиты реального
устройства необходимо проверить отдельно; «M3G API» не гарантирует аппаратный
GPU или рост FPS. Неизвестные/неподдерживаемые эффекты требуют реализации либо
явной диагностики, а не незаметной потери содержимого.

## Обнаруженный блокер: растеризация при сложном clipping

Проверено на текущей опубликованной Stlkr-сборке с агрессивными конфигами.
Тесты реально вызывают существующие декодеры/House/portals и M3G adapter через
инструментированные API doubles. Это не GPU/визуальный эмулятор.

Добавлен `NativeFallbackAudit`: временная копия DirectX7 регистрирует входы в
`drawSoftwareObject` при выбранном M3G. Причина отказа берётся из уже имеющейся
инструментации M3GSceneRenderer. Native upload/readback barriers сами по себе
**не** считаются CPU-растеризацией.

Все 13 миров, 2384 ракурса × 4 cold/warm прохода = 9536 проходов:

| Уровень | CPU dispatch calls за все 4 прохода | Режим / причина |
|---|---:|---|
| 1 | 68 | 3 / geometry-clip |
| 2 | 0 | — |
| 3 | 20 | 0 / geometry-clip |
| 4 | 0 | — |
| 5 | 68 | 3 / geometry-clip |
| 6 | 68 | 3 / geometry-clip |
| 7 | 0 | — |
| 8 | 68 | 3 / geometry-clip |
| 9 | 4 | 6 / geometry-clip |
| 10 | 16 | 3 / geometry-clip |
| 11 | 68 | 3 / geometry-clip |
| 12 | 0 | — |
| 13 | 68 | 3 / geometry-clip |

Итого **448 CPU dispatch calls**. Во всех случаях это Polygon4V и отказ
нативного geometry clipping, не отсутствие поддержки номера материала.
Этот результат указывает на место отказа, **не устанавливает окончательную
первопричину** каждого геометрического случая. Нельзя удалять CPU fallback,
пока эти случаи не покрыты корректной нативной отрисовкой.

Прежние level12/13 object-inclusive fixtures (по 80 поз, world/objects,
четыре прохода): level12 — **0**, level13 — **48** CPU dispatch calls,
также mode3 Polygon4V / geometry-clip. Это не уникальные полигоны и не FPS.

Strict gate:
- Набор всех миров **ожидаемо отклонён** уже на level1: скрывать fallback нельзя.
- Level12 object-inclusive прошёл strict gate в имеющемся наборе поз.
- Negative control с намеренным CPU dispatch корректно вызывает AssertionError;
  zero/disabled controls тоже проверены.
- Native material/fallback suite и 14 Python resource/frame-profile tests прошли.

Ноль в fixture не означает готовность всего приложения к M3G-only: audit
пока не учитывает прямые pixel writes GameScreen, HUD/оружие/меню LCDUI,
паузы/скриншоты, другие архивы, всевозможные камеры, runtime caps и OOM.
Следовательно, **никакой полной совместимости M3G-only пока не заявляется**.

## Порядок дальнейшего переноса

1. **Сделано:** зафиксировать контракт, измерить CPU fallback, добавить strict
   gate, убедиться, что старый движок/ресурсы/режимы ещё не менялись.
2. **Сделано в этапе 2:** исправить нативные near/viewport clipping и представление сложных полигонов;
   сохранить порядок, UV/цвета и Fog. Добавить регрессии для фактических отказов,
   не ослабляя точность/тесты только ради зелёного статуса.
3. **Runtime-путь сделан в этапе 3:** required Scene без whole-frame CPU replay,
   backup и выбора Software; отсутствие JSR-184 — явная ошибка. Физическое
   удаление samplers/legacy API ещё впереди: общий guard не заменяет аудит
   прямых pixel writes и оставшихся 2D consumers.
4. Перенести оставшиеся pixel effects, оружие/HUD/bitmap text и presentation;
   проверить паузу, скриншоты, resize, недостаток памяти и смену уровней.
5. Отдельно переносить CPU-проекцию world/model geometry на native
   Transform/Camera. Не смешивать это с простым удалением scanline renderer:
   текущий adapter ещё реконструирует геометрию из уже спроецированных вершин.
6. Проверить реальные устройства и только после этого публиковать новую
   M3G-only сборку как замену прежней. До этого downloads остаются прежними.

## Воспроизведение аудита

После обычной CLDC сборки и подготовки ресурсов:

```sh
python scripts/game_resources.py \
  --archive downloads/Quantum_Stlkr_FogBatch_ARM9.jar \
  --output-dir build/native-compat/resources
QUANTUM_RESOURCE_JAR="$PWD/build/native-compat/resources/resources.jar" \
  QUANTUM_STLKR_LEVELS_PROBE=1 QUANTUM_NATIVE_COMPAT_AUDIT=1 \
  python tests/m3g/run.py
```

JAVA/ECJ_JAR указывают на установленные Java/ECJ. Заменить probe-флаг на
`QUANTUM_LEVEL12_PROBE=1` или `QUANTUM_LEVEL13_PROBE=1` для набора с объектами.
`QUANTUM_REQUIRE_NATIVE=1` включает audit и завершает probe ошибкой при первом
ненулевом CPU dispatch count. На этапе 1 all-worlds gate ожидаемо падал. После этапов 2/3 он проходит;
REQUIRE_NATIVE теперь включает также реальный обязательный runtime-путь в probes.
Все hooks добавляются во временные тестовые копии; в published classes их нет.
