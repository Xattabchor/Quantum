# Quantum PolyFill — полигонаж и fillrate

Отдельный CLDC-1.1 / MIDP-2.0 / JSR-184 MIDlet. Это **синтетический тест
native M3G-пути Quantum**, а не новая локация и не паспорт видеочипа.
Используются engine `RawImage` / `Texture`, cached M3G VertexArray +
TriangleStripArray, непрозрачный текстурированный MODULATE без света/тумана,
рендер в offscreen `Image`, затем `LCDUI.drawImage`, как в текущем viewer.
Игровая загрузка карты, видимость комнат, NPC и скрипты в тест не входят.

- [JAD](../downloads/Quantum_PolyFill_Test.jad)

## Как запустить на телефоне

1. Установить `Quantum_PolyFill_Test.jar`. Имя MIDlet отличается от Tex3:
   основную сборку не требуется заменять.
2. Нажать **5** — полный автопрогон, сначала POLY, затем FILL.
3. Не нажимать клавиши и не сворачивать приложение до таблицы результатов.
   Около минуты, на очень медленном уровне — дольше.
4. Прислать фото/скрин таблицы **вместе с размером viewport из заголовка**.
   На небольшом экране страницы переключаются **4/6**.
5. Для проверки разброса повторить **5** ещё 2–3 раза при одинаковых условиях.
   Ориентироваться на устойчивый результат, не на лучший одиночный прогон.

Результаты хранятся в памяти и теряются при выходе; после каждой успешной
пробы также печатается строка `POLY_FILL_RESULT` в stdout (для эмулятора/лога).
Телефонные результаты пока **не получены**.

### Клавиши

| Клавиша | Действие |
|---|---|
| **1** | Ручной POLY, запоминает последний выбранный уровень |
| **3** | Ручной FILL, запоминает последний выбранный уровень |
| **2 / 8** | Увеличить / уменьшить нагрузку |
| **0** | Заново прогреть и измерить текущую нагрузку; после ошибки — повторить |
| **5** | Начать новый полный автопрогон / остановить текущий и открыть частичную таблицу |
| **7** | Таблица / вернуться к ручному тесту; останавливает автопрогон |
| **4 / 6** | Предыдущая / следующая страница таблицы |
| **#** | Выход |

Вручную после смены нагрузки: 1 секунда прогрева, затем окно не менее 3 секунд.
Первый кадр после прогрева только задаёт границу окна; считаются последующие
полные интервалы. До первой готовой пробы FPS показан как `-`.
Далее ручной тест обновляет результат примерно раз в 3 секунды без повторной
загрузки геометрии. Пауза/возобновление сбрасывает незавершённое измерение и
повторяет прогрев; время в фоне не попадает в FPS. hideNotify/showNotify также останавливают
отрисовку и сбрасывают окно, даже если платформа не вызвала pauseApp. Изменение размера Canvas
останавливает auto и очищает таблицу, чтобы не смешивать разную площадь.

## POLY: постоянная площадь, растёт число треугольников

Одна ортографическая плоскость закрывает весь измеряемый viewport. Увеличивается
только её сетка: shared vertices, один strip на строку, **один render call**.

| Сетка | Треугольников/кадр | Загруженных вершин |
|---:|---:|---:|
| 8×8 | 128 | 81 |
| 16×16 | 512 | 289 |
| 24×24 | 1152 | 625 |
| 32×32 | 2048 | 1089 |
| 48×48 | 4608 | 2401 |
| 64×64 | 8192 | 4225 |
| 96×96 | 18432 | 9409 |
| 120×120 | 28800 | 14641 |

Все треугольники невырожденные, CW, фронтальные, внутри clip volume; нет
сшивающих вырожденных треугольников. Суммарная покрываемая площадь неизменна.
Точность координат — signed short с scale 1/16384, UV — short с scale 1/256.
Число вершин ниже прежнего engine packet budget 16384. Depth test/write ON.

Это нагрузка на native обработку геометрии/индексов/strip-ов и растеризацию,
не чистый счётчик аппаратных triangle setup operations. CPU-отсечение и сборка
видимых индексов игровой карты здесь специально отсутствуют.

## FILL: постоянный viewport, растёт число слоёв

**1 / 2 / 4 / 8 / 16 / 32** полноэкранных слоя. Каждый — 2 треугольника и
4 вершины; все слои собраны в **один TriangleStripArray и один render call**.
Число Java-вызовов render не растёт со слоями. **Depth test и depth write OFF**,
поэтому одинаковые Z не дают Z-тесту отвергнуть последующие слои.

В обоих тестах:

- один процедурный непрозрачный checker 64×64 через engine Texture/RawImage;
- NEAREST / BASE_LEVEL, WRAP_REPEAT, MODULATE, REPLACE, без mipmaps;
- vertex RGBA=(220,220,220,255), все texel alpha=255;
- **alpha threshold 0.5 всегда ON**, клавиши/кода отключения нет;
- CULL_BACK / WINDING_CW, smooth shading, perspective correction ON;
- нет lighting, normals, fog, blend/transparency, игровой погоды;
- один Image target с depth buffer, color+depth clear каждый кадр;
- геометрия/индексы строятся только при смене нагрузки, texture — один раз;
  в измеряемых кадрах нет VertexArray.set или Image2D-перезагрузки.

Это **текстурированный opaque nominal fillrate** с указанными состояниями,
а не максимальный untextured fillrate и не скорость alpha-blending.
Текстура маленькая/кэшируемая; другой размер, фильтрация, alpha, свет или
материал могут сильно изменить результат.

## Что означают цифры

Viewport: **ширина Canvas × (высота Canvas − 90)**; верхние 60 и нижние 30 пикселей
заняты HUD. Например, при Canvas 240×320 измеряется 240×230=55200 пикселей.
В формуле используется фактический размер, он указан в таблице.

- **FPS** — число законченных paint-проходов / время полного steady-state окна.
  Входит вызов вывода Image, HUD, ожидание repaint, планировщик/паузы GC.
  Это не аппаратный VSYNC-счётчик. Низкие нагрузки могут упереться в вывод или
  планировщик раньше, чем в обработку геометрии/пикселей.
- **Ktri/s** = `trianglesPerFrame × completedFrames × 1000 / elapsedMs / 1000`.
- **Mpix/s nominal** = `viewportW × viewportH × layers × completedFrames × 1000
  / elapsedMs / 1000000`. Это заданное пиксельное покрытие, **не аппаратный
  счётчик реально обработанных фрагментов/записей**. Внутренние оптимизации
  драйвера не измеряются отдельно.
- **N** — среднее время Java/native участка: bind, viewport/camera/state,
  lights reset, clear, render, release. **Не GPU timestamp**: M3G может работать
  асинхронно, а release/copy — синхронизировать выполнение.
- **C** — среднее время вызова LCDUI.drawImage, не время физической развёртки.
- **I** — средний интервал между началами кадров. N/C/I в целых миллисекундах;
  у коротких участков из-за дискретности часов возможен ноль.

В ручном HUD есть FPS, N/C/I и throughput. В компактной таблице:

```text
P <треугольников/кадр> <FPS>fps <Ktri/s>K N<мс>
F <слоёв>             <FPS>fps <Mpix/s>M N<мс>
```

`OOM` = не хватило Java/native памяти, `ERR` = другой сбой, `not measured` =
проба не завершена. Auto отмечает ошибку, освобождает текущий workload,
запрашивает GC **вне измерения** и переходит дальше. Вручную ошибка не запускает
бесконечные повторные аллокации: **8** уменьшает нагрузку, **0** повторяет.
Native target освобождается через finally; CPU-растеризации/fallback нет.

**Нельзя** по этим цифрам обещать FPS игровой локации или приписывать телефону
«аппаратные X млн полигонов/пикселей»: игровой кадр имеет другую CPU-работу,
геометрию, материалы, глубину, overdraw и draw calls.

## Изоляция и проверки

Immutable baseline: Tex3 commit `b9b477f3de65e2a2ecc2e0f88ad10a09244f22fa`,
SHA-256 `8617f348e04f4b10c03b0049e60f2e92c41532d6939546ad96f6e44d11aa6880`.
Все **182 старых class-файла и все assets сохранены побайтно**. Добавлены только
5 benchmark-классов и новый manifest. Карта/WTEX/PNG/река/свет/конфиги/прежние
рендереры не менялись. Tex3 JAR сохранён для обычного запуска и отката.

Сборка: ECJ source/target1.3 + CLDC preverification, class47.0. JAR/JAD/SHA,
source и builder hashes находятся в build-report. SDK-классы в JAR не включены.

```sh
JAVA="$PWD/build/tools/jdk4py/java-runtime/bin/java" \
  python scripts/build_poly_fill.py --output-dir downloads
JAVA="$PWD/build/tools/jdk4py/java-runtime/bin/java" ECJ_JAR="$PWD/build/tools/ecj.jar" \
  python tests/poly_fill/run.py
JAVA="$PWD/build/tools/jdk4py/java-runtime/bin/java" ECJ_JAR="$PWD/build/tools/ecj.jar" \
  python tests/poly_fill/run.py --packaged
python -m unittest discover -s tests/resources -p 'test_poly_fill.py'
python scripts/verify_render_checkpoints.py
```

Source и packaged JAR: по **431417 контрактных/аналитических проверок**, все
14 workloads, winding/невырожденность/площадь/clip/индексы/состояния, hot-cache,
контролируемые часы/64-bit throughput/пауза, auto/table/keys/resize, native
ошибки и OOM/recovery, освобождение target и lifecycle worker. Независимый
resource audit подтверждает byte-identical baseline, manifest/JAD/class47,
SHA и source provenance. Исторические checkpoints проверяются отдельно.

**Desktop doubles не растеризуют сцену и не измеряют телефонный GPU/FPS.**
Аналитически проверена геометрия и контракт M3G-вызовов; видимость checker,
ограничения конкретного драйвера и реальные скорости проверяются на телефоне.
