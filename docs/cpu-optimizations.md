> **Архив: изменения отменены 18.10.2026 по запросу пользователя.**
> Текущая сборка восстановлена до KVM; оставлен только последующий Image presentation.
> Числа ниже относятся к прежним экспериментальным JAR, не к текущему релизу.
> [Состав отката](m3g-pre-kvm-rollback.md).

Дата: **17.10.2026**. Изменения не меняют формулы освещения, изображение,
формат ресурсов или исходный выбранный Software.

## Что ускорено

1. **Подготовка метрических позиций OMNI**: глубина реконструируется один раз
   на вершину, параметры проекции читаются в локальные переменные, убраны
   повторные helper-вызовы и float-преобразования глубины. Сохранены деления,
   округление и границы четверть-единичной short-решётки. Это CPU-подготовка
   настоящего native OMNI, не возвращение удалённого additive-спрайта.
2. **CPU recovery освещения режима 5**: кэшируется длина lightdir и последний
   результат базового света. Для OMNI отдельно кэшируются преобразованная нормаль
   и её длина. Ключ учитывает компоненты нормали и **все 9 элементов вращения
   камеры**, а не только идентичность объекта Matrix. Смена normal/lightdir/
   камеры не оставляет старое освещение. Для полностью насыщенного базового
   света и обратной стороны лишние вычисления point light пропускаются.
3. **CPU recovery виньетки/урона/смерти**: маленькая точная таблица tint заменяет
   повторную RGB-арифметику каждого пикселя. Коэффициент маски читается один раз
   на пару в полном восьмипиксельном префиксе. Хвост, короткая/пустая маска,
   alpha и прежний порядок округления сохранены. Область без маски обрабатывается
   отдельно, без её проверок на каждом пикселе.

Таблица `int[512]` занимает **2048 байт данных** плюс заголовок массива. Она
создаётся только при первом **CPU recovery** и переиспользуется. Нормальный
native MODULATE не выделяет эту таблицу. При OOM остаётся старый арифметический
цикл; повторные попытки выделения для этого FrameEffects прекращаются.
Произвольный tint с разными G/B также сохраняет арифметический путь.

Native ambient/directional/OMNI, длительность 120 мс, Fog 3/6, статические
цвета 9/13 без дистанционного тумана, обычные ADD-спрайты, исходный Software,
погода и единая sky/world/post/weather транзакция сохранены.

## Честное сравнение до/после

Обе версии последовательно прогнаны **одним и тем же обновлённым harness** на
готовом неизменённом KVM 1.1 из `klaxons1/j2me_cldc`. Использованы разные production
JAR; тесты не компилируют копии игровых методов и не подменяют графический API.

Среда и ограничения — как в [исходном отчёте](cldc-performance.md): Xeon 2.60 GHz,
32-bit x86 KVM на Linux, heap 4 MiB, калибровка ≥250 мс, прогрев и пять samples
на нагрузку. Ниже **медиана, миллисекунды на указанную нагрузку**. Коэффициент —
отношение этих медиан, не прирост игрового FPS.

| Нагрузка | До, мс | После, мс | До / после |
|---|---:|---:|---:|
| 1000 вершин: transform + project (контроль) | 0.824 | 0.824 | 1.00× |
| 1000 Matrix.mul (контроль) | 1.715 | 1.711 | 1.00× |
| Упаковка 1000 треугольников для OMNI | 8.562 | 4.812 | 1.78× |
| 1000 базовых CPU shade, одна нормаль | 3.133 | 0.272 | 11.50× |
| 1000 CPU OMNI shade, одна нормаль | 10.094 | 4.297 | 2.35× |
| 1000 базовых CPU shade, меняющиеся нормали | 3.477 | 3.133 | 1.11× |
| 1000 CPU OMNI shade, меняющиеся нормали | 10.406 | 10.219 | 1.02× |
| CPU post-effect 240×320 | 51.750 | 20.562 | 2.52× |
| CPU post-effect 176×220 | 26.125 | 10.750 | 2.43× |

«Одна нормаль» — благоприятный для кэша случай; его нельзя выдавать за ускорение
каждой грани. В новых varying-тестах нормаль меняется на каждом вызове: для OMNI
выигрыш около 1.8% в этом прогоне, а не 2.3×. Контрольные transform/matrix не
оптимизировались; небольшая разница — вариация измерений.

В post-effect повторно умножается переиспользуемый framebuffer, который со
временем становится чёрным; отрисовка мира/LCDUI в нагрузку не входит.
Таблица tint уже прогрета: первый CPU recovery дополнительно выделяет/строит её.
Новые тесты не измеряют холодный запуск, пиковую память или GPU.

**Это не замер M3G FPS и не прогноз для телефона 220 МГц.** В этом KVM нет
JSR-184, MIDP entry point не загружается; игровые ресурсы также отсутствуют.
Draw/upload/readback и скорость реального native OMNI/постэффекта не измерены.

## Проверки

- Production SDK build / CLDC preverification.
- Полный M3G contract suite, включая отсутствующую JSR-184.
- Новый `CpuOptimizationTest`: исчерпывающие пары 256 коэффициентов/256 значений
  каналов для четырёх tint-состояний, alpha, короткие/нечётные/длинные маски,
  переходы tint, принудительно недоступная таблица и произвольные G/B.
- 12000 сравнений упаковки с **прежней формулой**, включая частично заполненный
  буфер при отказе, отрицательную/слишком большую глубину и крайние координаты.
- Сравнение целочисленного результата света с прежней формулой при изменениях
  всех компонентов camera/lightdir/normal и нулевых/крайних входах.
- Original MIDP framebuffer и настройки/RMS: PASS.

Тестовые классы и KVM/сторонние библиотеки не включены в игровую сборку.
