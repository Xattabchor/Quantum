# Оптимизация поиска целей NPC без изменения поведения

18.10.2026. Исходная версия: `8c33787` (после batching спрайтов).
Изменены только `src/code/AI/Bot.java` и `NPC.java`. Это **CPU-оптимизация**,
не объединение draw-вызовов. Общий ИИ ускоряется независимо от выбранного
рендера; код Software и M3G, исходные игровые файлы и конфиги не меняются.

## Что убрано

- NPC ищет врага и объект следования одним проходом вместо двух. У каждой
  роли собственный минимум расстояния; при равенстве остаётся первый объект.
- Один `Vector.elementAt` на объект. Несовпадающие фракции отбрасываются
  до вычисления расстояния и поля зрения; Player по-прежнему имеет фракцию 0.
- Расстояние не вычисляется второй раз внутри FOV. Ближняя зона остаётся
  строго `< 2500²`, с исходным **трёхмерным** расстоянием.
- Нет двух временных `Vector3D` на FOV-запрос. Направление наблюдателя
  нормализуется максимум один раз за поиск, только если действительно нужно.
- Для большинства далёких целей знак FOV проверяется целочисленно без
  `sqrt` и double-делений. Это **не** простая замена нормализации сырым dot:
  пограничные направления сохраняют исходное округление.

### Почему целочисленный FOV сохраняет границу

Сначала точно воспроизводится исходное направление наблюдателя. Для цели
сохраняются исходные int-проверка длины и деление координат пополам.
В безопасном диапазоне координат используется сертификат знака:

```text
D = lookX*x + lookZ*z
B = (abs(lookX) + abs(lookZ) + 2) * (abs(x) + abs(z))
4096*D >  B  => visible
4096*D < -B  => not visible
otherwise   => original sqrt/division/int truncation
```

L1-длина ограничивает сверху L2-длину. Ошибка усечения нормализованных
компонент ограничена суммой модулей компонент look; добавлен запас.
Проверки диапазонов исключают переполнение fast path. Пограничные и
необычные векторы сохраняют исходную математику, нулевой look даёт тот же false;
исходное int-переполнение, включая особый случай точной длины, сохранено.
Например, look `(1,4096)` и цель `(3000,0)` по-прежнему **не** видимы вне
ближней зоны, хотя простой ненормализованный dot дал бы другой ответ.

## Что намеренно не менялось

Частота `update`, `reacttimer`, `attacktimer`, damage sleep, ближний бой,
старые/уникальные враги, friendly fire, максимальные дистанции, время и
результат visibility raycast, маршруты через порталы и физика. Нет LOD ИИ,
нового расписания, задержек дальним NPC или новых настроек/полей на NPC.

`Dijkstra.getNext` уже читает заранее построенную таблицу: дополнительный
«кэш поиска пути» в этой правке не добавлялся. Оригинальные ресурсы подходят
без конвертации. На многих Stlkr NPC `VISIBILITY_CHECK=0`: там основная
выгода — один проход и ранняя фильтрация фракций, а не FOV fast path.

## Счётчики работы, не FPS

Один цикл поиска двух ролей для **96 NPC** в детерминированной тестовой
сцене. Цели до/после одинаковы. Полные числа: [results.json](../tests/ai/results.json).

| Сценарий / операция | Было | Стало |
|---|---:|---:|
| Все три сценария: проходы списка | 192 | 96 |
| Все три сценария: `Vector.elementAt` | 36 864 | 9 216 |
| Нет нужных фракций: расстояния | 18 240 | 0 |
| Четверть NPC нужной фракции, FOV off: расстояния | 18 240 | 2 280 |
| То же, FOV on: расстояния | 32 744 | 2 280 |
| FOV on: временные `Vector3D` | 29 008 | 0 |
| FOV on: `Math.sqrt` | 29 008 | 264 |

Это **−75% чтений списка** и более 99% убранных sqrt в конкретном FOV-тесте,
не процент ускорения всего ИИ/кадра. `vectorSetLength=0` в отчёте означает
отсутствие вызовов этого метода, а не отсутствие скалярной нормализации.
Настольная рефлексия/инструментация не используется как секундомер.
Физический телефон, ARM9 wall time и FPS не измерялись.

## Регрессии

`tests/ai/run.py` компилирует временные инструментированные **реальные**
Bot/NPC/Character/House/Scene/Vector3D. Независимые старые поиск/FOV хранятся
в `AIReference.java`, исходный NPC action — в `reference-action.txt`.
LegacyNPC использует этот action и старый поиск; остальные неизменённые
методы NPC общие. Часы решений фиксируются только во временных копиях.
Тестовые классы и счётчики никогда не включаются в MIDlet.

- 250 000 seeded FOV-сравнений: обычные и полные int-координаты/направления,
  переполнения, нули и усечение; ещё 19 117 проб около перпендикуляра,
  явные overflow-примеры, радиус 2500 и вертикальная дистанция.
- 16 000 проверок выбора обеих ролей и общего `Bot.findBot`: одинаковые
  расстояния, ignore/self, мёртвые/неакторы, Player, null/пустые/пересекающиеся
  маски фракций, дубликаты объектов и экстремальные координаты.
- 7 200 пар настоящих NPC updates с frameTime 16/50/100/33: сравниваются
  цели/состояния/кадры/направление/полная матрица/скорости/выбор спрайта,
  HP, уникальные враги, награды и содержимое очереди death scripts.
  Совпали также **170 visibility rays, 495 portal lookups, 20 блокировок
  видимости** и 10 death scripts. Физический шаг в этом fixture **явно
  отключён**: это не полный интеграционный тест движения/коллизий уровня.
- M3G: 172 PASS; диагностическая сборка: 235; level13: 183; level41: 179.
  Все 320 level13 и 256 level41 counter/triangle-stream witnesses, а также
  86 sky streams в level41-наборе (32 непосредственно level41) совпали
  с версией до AI-правки.
- Framebuffer/settings/frame timing и 9 Python resource/profile tests PASS.
- CLDC 1.1: 149 классов, version 47.0, 1904 code methods, 1025 StackMaps.
  **147 classfiles побайтно прежние**; изменены только Bot/NPC.
  Engine/game имеют одинаковые classfiles; все **442 ресурса** Stlkr и их
  имена побайтно сохранены. SDK, AI tests и profiler в release не входят.

## Воспроизведение

После обычной сборки `scripts/build_cldc.py` с настоящими Java ME API:

```sh
export JAVA=/path/to/java ECJ_JAR=/path/to/ecj.jar
python tests/ai/run.py
python tests/m3g/run.py
python tests/framebuffer/run.py
python tests/settings/run.py
python tests/frame_profile/run.py
python -m unittest discover -s tests/resources -v
```

AI runner использует `build/cldc/Quantum-unverified.jar` и `api.jar` от сборки.
Нужен desktop JDK; при отсутствии ECJ можно задать `JAVAC`. Для native
ресурсных probes — команды из [тестов Sprite batching](m3g-npc-sprite-batching.md).
