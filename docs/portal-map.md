# Новая карта: порталы ON/OFF без BSP

Отдельный native M3G просмотрщик:
[JAR](../downloads/Quantum_PortalMap_Test.jar) ·
[JAD](../downloads/Quantum_PortalMap_Test.jad) ·
[отчёт / SHA-256](../downloads/Quantum_PortalMap_Test.build-report.json).
Основная игра и прежние сборки не заменены, BSP не возвращён.

## Источник и проверка карты

Получен пользовательский `lightmap.zip.txt` (на самом деле ZIP), сохранён как
[`fixtures/portal-map/lightmap.zip`](../fixtures/portal-map/lightmap.zip).
272211 bytes, SHA-256
`16beaa29fe143cc4010b66e21d90c729a0f83c5f2f3f282b04c17c96577b1ddf`.

Внутри6 исходных файлов: level1.txt, kordon.3d, kordon.png, kordon.vla,
skybox5.3d, n.png. Все байты, включая исходный CP1251-конфиг, сохранены в JAR
под `/portal-map/`; старые файлы по старым путям не заменяются. Пути конфига
только дополняются namespace при загрузке, сам конфиг не переписывается.

- **15 геометрических комнат**, последний16-й mesh — **18 порталов**, не мир.
- Каждому порталу однозначно соответствуют2 комнаты, граф связен.
  Связывание проверено по правилу настоящего HouseCreator: хотя бы одна общая
  координата с допуском25 world units. В engine graph36 направленных связей.
- **3761 мировой треугольник / 7955 face corners**;36 треугольников portal mesh
  в эти числа не входят и никогда не рисуются.
- VLA25956 bytes полностью покрывает все16 meshes:2085 RGB faces и30 gray faces.
  RGB читается в оригинальном формате: R-сэмплы, bool, optional G/B-пары.
  Gray остаётся R=G=B, без потери цветного освещения других граней.
- Сохраняются **DMODE13, WORLD_SCALE6, DIST40000** и исходный START.
  Камера в START+1503 по Y, как в предыдущих диагностических просмотрщиках.

Это **другая версия карты**, не pixel-identical прежнему Tex3: другая геометрия,
материал/освещение и дальность. Нельзя приписывать разницу FPS между разными JAR
одним порталам. Основной замер — ON/OFF **внутри этого JAR**.

## Режимы и телефонный замер

При запуске **PORT ON**.

- **0** — ON↔OFF, **1** — всегда ON, **3** — всегда OFF.
- **5** — исходная камера/yaw0.
- **4/6** — поворот, **2/8** — вперёд/назад, **7/9** — вбок, **#** — выход.

Снять **ON → OFF → ON** в одной неподвижной позе. После переключения ждать
числового FPS и ещё одного обновления окна; обычно около8секунд, при низкой
скорости дольше. Повторить у проёма/после перехода в соседнюю комнату.
При смене режима поза и Image target сохраняются, ввод движения останавливается,
статистика сбрасывается. Pause/hide/resize также сбрасывают прогрев.

При OFF подаются все15 комнат. При ON — комнаты, достижимые через проекции
порталов в текущем viewport. При неопределённой комнате безопасно подаются
**все15** и HUD явно пишет **OUT -> ALL15**, а не показывает быстрый пустой кадр.
Это свободная диагностическая камера, без игровой физики/коллизий: не сравнивать
замеры внутри карты с замерами после выхода за её границы.

Окно:1секунда прогрева, первый завершённый anchor-кадр, затем≥3секунды и≥2 интервала.
Проверять **не только FPS**, но и отсутствие пропавших домов/стен при ON.
Физическую полноту разделения геометрии порталами задаёт сама карта.

## Что именно рендерится

**Только мировая геометрия с оригинальной текстурой и baked RGB**, без sky/weather/
NPC/скриптов/игровой логики **в обоих режимах**. Это измеритель карты, не полный
игровой билд. Skybox/небо/RAIN/WEATHER_LIGHTING и остальные строки не удалены из
архива или конфига. n.png512×512 сохранён без ресайза, но этот geometry viewer
его не загружает. Небо — одинаковый constant clear в ON/OFF. Поэтому этот FPS
не прогноз полного игрового FPS с дождём/небом.

В обоих режимах near128/far40000/FOV74, одинаковые native projection/camera,
полный Canvas/Image viewport, depth test/write/clear ON, alpha thresholds ON,
исходные UV/baked RGBA, perspective ON с политикой материала, noFog13.
Освещение не генерируется повторно, дополнительные динамические источники не
добавляются. Полигоны не разрезаются и не квантуются с потерями.

## Буферы, выбор комнат и число вызовов

**По одному resident VertexBuffer и index buffer на комнату**, одна общая
загруженная atlas256×256. Все XYZ/UV/RGBA/strip indices создаются при загрузке.
Даже при движении, смене комнаты и ON/OFF **не строятся новые vertex/index buffers
и не вызываются uploads атрибутов/текстуры**. Внутренние действия драйвера этим
не измеряются. Один bind/clear/release на весь кадр, не на каждую комнату.

OFF специально сохраняет те же15 per-room buffers, а не заменяет их одним
большим FULL buffer: меняется только выбор комнат. Это контролируемое сравнение
портального отсечения, не доказательство превосходства над отдельно слитой
одновызовной геометрией. Сохраняется исходный порядок комнат/граней/диагоналей.

Desktop API-счётчики для START/yaw0,240×320/focal212 (**не FPS телефона**):

| Режим | Комнат | Треугольники | Draw calls | VB capacity |
|---|---:|---:|---:|---:|
| ON | 1 (room6) | 1384 | 1 | 2990 |
| OFF | 15 | 3761 | 15 | 7955 |

В других ракурсах/разрешениях числа изменятся. VB — вместимость поданных буферов,
не измерение реально обработанных драйвером вершин.

### Консервативный native selector

Используются исходные порталы карты и House.calcPart с floor-test для текущей
комнаты, но **не вызывается старый CPU painter**. Projection порталов согласован
с фактической сдвинутой/квантизованной камерой M3G; inverse — настоящий inverse
той же3×3 матрицы, не предположение об идеальном ортонормальном повороте.

Портал клипуется относительно eye-plane и4 боковых плоскостей, затем берётся
screen rectangle с2px guard. **Не режем портал по near128**: дверь между глазом
и near всё равно должна открывать комнату за ней. При глазе на плоскости проёма
есть4-world-unit guard. Двусторонние порталы, без ненадёжного backface rejection;
порталы дальше far могут дать лишние комнаты, но не ложное исчезновение.

Viewport-окна комнат монотонно расширяются. Поздний/перекрывающийся путь повторно
ставит комнату в заранее выделенную очередь. Используется настоящее containment,
а не overlap-проверка `Room.viewportContains`, иначе можно потерять второй проём.
Union rectangles может выбрать лишние комнаты — это намеренная консервативность.

Для статической карты закэширован **один точный результат** camera16/seed room/
разрешения/focalX/focalY. Пока реальная native camera не изменилась, projection/
обход не повторяются; никакого hash-only совпадения. При движении результат
пересчитывается, но geometry/indices всё равно не меняются.

## HUD

- `FPS` — десятые FPS; `N` — вся native-транзакция, `C` — Image→Canvas, `I` — интервал.
- `T/DC/VB` — поданные треугольники, вызовы, вместимость буферов.
- `Rooms x/15 at n P k` — выбранные комнаты, стартовая комната, число проверок
  направленных portal edges в текущем обходе. Без cache-hit проецируются все18
  исходных порталов. Суффикс `C` — результат selector взят из кэша, поэтому P=0.
- `J/B/K/R/E` — подготовка/selector, bind, camera/state/clear, render loop, release.

N и стадии — coarse Java API wall time, **не GPU timestamps**. При ошибке явный
`Failed`, без тихого пропуска неподдержанной геометрии/другого renderer.

## Воспроизведение и проверки

Обычный toolchain: ECJ4.8, Java, Java ME API/ProGuard; подмодули Room/StringTools.
Для desktop harness нужен `build/cldc/api.jar` SDK union CLDC/MIDP/JSR135/
JSR184/JSR75_file. Если нет javac, задать JAVA/ECJ_JAR.

```sh
python scripts/audit_portal_map.py
python scripts/build_portal_map.py --output-dir downloads
python tests/portal_map/run.py
python tests/portal_map/run.py --packaged
python -m unittest tests/resources/test_portal_map.py
python scripts/verify_render_checkpoints.py
```

Source и готовый preverified CLDC JAR: **57142 assertions / 448 camera cases**.
В432 случаях проверены6 позиций×3 pitch×24 yaw, в16 — odd/landscape viewport/
разные focalX/focalY. Внутри карты выбиралось1..6 комнат, проверен выход за карту.

- OFF payload каждого room побайтно сравнен с immutable native mesh renderer;
  ON — точная подпоследовательность OFF с теми же буферами/атрибутами/состоянием.
- Граф сопоставлен настоящему HouseCreator, каждый RGB/gray sample проверен
  независимо по оригинальной VLA; truncation/trailing данные отвергаются.
- Независимые simple-path traversal и ray/portal intersections проверяют отсутствие
  потерянных проёмов/достижимых комнат. Отдельно eye-on-door, before-near128,
  behind-eye и cyclic overlapping-window/requeue regression.
- Проверены cold buffers/indices при движении, точный stationary cache,
  UI→renderer, freeze/hide, target release при ошибках, warmup/window clocks.
- 190 CLDC47.0 classes/1222 StackMaps:182 baseline classes и все прежние assets
  неизменны, добавлены8 классов и6 оригинальных файлов в namespace.
- Детерминированные JAR/JAD/report воспроизводятся побайтно. Native doubles не
  растеризуют M3G и **не измеряют E65**; телефонных ON/OFF результатов ещё нет.

Отдельные resource-аудиты StaticRoom/PolyFill/Software/L2D/PortalMap: **29 PASS**;
7 rollback checkpoints PASS. Общий discovery ресурсов также зависит от старого
отсутствующего fixture `Stlkr by ebk.jar (1).zip`; новый пользовательский архив
не подставляется вместо него.
