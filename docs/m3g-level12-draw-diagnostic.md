# Stlkr level12: откуда берутся draw-вызовы

18.10.2026. Движок `03d3540`, после точного Fog batching, Sprite batching
и CPU-оптимизации ИИ. **Это диагностика, не новая оптимизация рендера.**
Production Java, JAR/JAD, игровые ресурсы и настройки на этом диагностическом
этапе не менялись. Последующая [оптимизация насыщенного Fog](m3g-saturated-fog-batching.md)
снижает тяжёлую позу D108 → 105.
[Машиночитаемый результат](diagnostics/level12-m3g-draws.json).

## Методика и ограничения

Расширен существующий `tests/m3g/Level13Probe.java`: тем же кодом можно
запустить level12. Реальные PNG/модели/конфиги из `Stlkr by ebk.jar (1).zip`,
реальные House/порталы и загрузчик NPC; инструментированные M3G API doubles.
Текстуры мира атрибутируются по RawImage identity для всех трёх материалов,
а не по одному имени atlas. Непрозрачные untextured mode8-полигоны OCID
считаются как mesh, не как sky. Незатекстуренная погода RGB отделена от
RGBA-панорамы/ground. Полная сумма категорий проверяется против D.

Уровень: 9 комнат, 2137 вершин, 1621 полигон / 3178 треугольников;
материалы мира — `pripyat.png`, `grass.png`, `asphalt.png` (1321/90/210 полигонов).
Статические объекты: 6 meshes, 1 sprite, 5 idle NPC. Один soldier spawner
не активируется; ИИ, физика и игровые скрипты не исполняются.
Mesh presets учитывают MODEL_SCALE/SCALE, DRAW_MODES и ADDSZ.

240×320, 5 точек × 8 yaw × 2 pitch = **80 поз**. Точки ног: START,
`1607,0,-35579`, `34507,0,6122`, `76610,0,-36271`, `5676,0,13025`;
высота камеры +1503, pitch 0/45, yaw с шагом 45°. Каждая поза — четыре
одинаковых snapshot renders, выводятся cold и последний warm. Отдельно
проверяется мир без объектов (sky/weather остаются в обеих версиях).
Дождь: все настроенные **10** частиц активны, фиксированные координаты и
глубины; без симуляции крыши/молний. Это не запись полного игрового кадра,
не универсальный максимум уровня и **не замер FPS телефона**.

## Результат с исходным native LINEAR Fog

DMODE=3, DIST=39000, FOGD=26000, FOGC=40,40,40, CHUNK_SIZE=0.

| Warm, 80 поз | Min D | Max D | Средний D |
|---|---:|---:|---:|
| Мир + статические объекты + idle NPC + sky + rain | 4 | **108** | 30.7375 |
| Мир + sky + rain, без объектов | 4 | **101** | 25.95 |

Наиболее тяжёлая поза первого набора: ноги `76610,0,-36271`, yaw=0,
pitch=0, room=6, 163 queued objects, 306 submitted culled triangles:

| Категория | Draws |
|---|---:|
| Мир | **102** |
| Mesh-объекты | 2 |
| Спрайты (NPC и SpriteObject вместе) | 1 |
| Небо/ground | 2 |
| Дождь | 1 |
| **Итого** | **108** |

Здесь warm T=0, B=1. Во всех 80 нормальных warm позах повторных загрузок
текстур нет и capacitySplits=0. **Повышение лимита вершин пакета само по
себе не устраняет это узкое место.**

Причины разрывов в тяжёлой позе:

- **56 scale-only splits**: материал совместим, но пакет с native Fog не
  удалось точно привести к общему масштабу координат в short-диапазоне.
  Текущий rebase допускает только точные двоичные преобразования, не
  округление глубины ради объединения.
- **47 texture splits**: смена текстуры среди соседних полигонов/объектов.
  40 state splits и 96 scale splits — независимые, **пересекающиеся**
  счётчики причин; складывать их как число draw-вызовов нельзя.
- В этой позе capacitySplits=0, native rejects пусты.

Основная проблема снимка — **пакеты геометрии мира с Fog и тремя материалами**,
а не количество поз анимации NPC или отдельные draw на каждую каплю.
Сортировать весь мир по текстурам нельзя без изменения painter order:
текущий M3G renderer не использует depth test/write для этого пути.

## Контрольный тест Fog OFF — только диагностика

В той же тяжёлой позе: **D108 → D52**, world **102 → 46**, остальные
категории остаются 2/1/2/1. Во всём Fog-OFF наборе max D=57, средний=13.5875.

**Туман в игре не отключён.** Эта версия меняет картинку/материальные
состояния и не является ни готовым исправлением, ни обещанием достичь D52
с исходным Fog. Она показывает стоимость ограничений Fog batching.
Без Fog в нескольких других позах уже встречается capacity split — вывод
про нулевые capacity splits относится к исходной Fog-ON конфигурации.

Дальнейшие оптимизации следует проверять на этом уровне, сохраняя
настроенный туман, порядок, повторение UV и исходные файлы. Простая замена
NPC на модели или увеличение пакета проблему этого снимка не решает.

## Воспроизведение

После обычной CLDC-сборки с JAVA/ECJ_JAR:

```sh
python scripts/game_resources.py --archive 'Stlkr by ebk.jar (1).zip' \
  --output-dir build/stlkr
QUANTUM_RESOURCE_JAR="$PWD/build/stlkr/resources.jar" \
  QUANTUM_LEVEL12_PROBE=1 python tests/m3g/run.py > level12.log 2>&1
# НЕ настройка игры; другой child JVM, только контрольная диагностика:
QUANTUM_RESOURCE_JAR="$PWD/build/stlkr/resources.jar" \
  QUANTUM_LEVEL12_PROBE=1 QUANTUM_LEVEL12_FOG_OFF=1 \
  python tests/m3g/run.py > level12-fog-off.log 2>&1
```

Level12/13/41 probes запускаются по отдельности. Обычные тесты не включают
этот замер без явного флага. После расширения fixture **все 320 level13,
256 level41 counter/triangle-stream rows и 86 sky streams** level41-набора
совпали с предыдущим baseline. Изменения диагностики не входят в MIDlet.
