# Alpha test OFF / ON — отдельный тест деревни для E65

Цель: проверить предположение пользователя, что alpha test может быть причиной
тормозов. **Не подтверждённая причина, не обещание FPS и не патч полной игры.**
База — неизменённый `Quantum_StaticRoom_Depth.jar` из commit
`1cc9663e22a7aa3753b780570fb34f839b3208ea` (SHA256
`053252da302fa8e9c8661617e6b4985b20887c57af942fb8e10939a8f0079316`).

## Скачать и переключить

- [JAR](../downloads/Quantum_StaticRoom_Alpha.jar)
- [JAD](../downloads/Quantum_StaticRoom_Alpha.jad)
- [Состав, хеши и preverify](../downloads/Quantum_StaticRoom_Alpha.build-report.json)

По умолчанию **A alpha OFF**: `CompositingMode.setAlphaThreshold(0)`.
**0** переключает в **B alpha ON**: исходный порог конкретного изображения
(0,5 для cutout, 0 для непрозрачного), затем обратно в A. Переключение сбрасывает
окно FPS/таймингов. Это не переключатель alpha blending.

- `4/6` — поворот, `2/8` — движение, `7/9` — вбок, `#` — выход.
- Near фиксирован **128**, far **60000**, как в базовом Depth по умолчанию.
  **5 здесь ничего не меняет.** В старом Depth `0` меняет near, а `5` — far;
  это другие значения клавиш в другом JAR. Переключать проекцию одновременно
  с alpha test в этом тесте нельзя, чтобы не смешивать причины.
- Для возврата прежнего поведения достаточно нажать `0` (B alpha ON).
  Старый Depth и остальные JAR не перезаписывались, доступны для отката.

## Что меняется, а что нет

Меняется только alpha threshold у существующих `CompositingMode`. Не меняются:

- модель, её полигоны, XYZ/UV/цвета baked-света, исходная `.vla`;
- RGBA-пиксели и размеры текстур, `Image2D.RGBA`, фильтрация и анимация реки;
- blending (`REPLACE` / исходный `MODULATE`), depth test / depth write;
- near/far, поза камеры при неподвижном игроке, culling, порядок примитивов;
- не объединённые source strips, максимум 3 native calls, 10032 загруженных
  угла, 4750 полных треугольников, тот же Image target и LCDUI copy;
- байты `level1.txt`, `setting.txt` и всех 10 ресурсов базового Depth;
- все 172 старых класса. Добавлены только 7 классов изолированного теста.

Порог исходной **текущей** текстуры кэшируется отдельно от включённости теста:
смена анимационного кадра не должна снова включать discard, а ON восстанавливает
правильный порог даже при переключении без смены изображения. Никаких runtime
перезагрузок текстур или vertex buffers при переключении нет. Во время render
setter повторяется с тем же значением и сразу выходит, не перебирая материалы.

Упрощённая модель из нового оптимизатора **не используется**. Это отдельный
эксперимент, чтобы не смешивать изменение геометрии с alpha test.

## Ожидаемые дефекты и ограничения вывода

При OFF ранее прозрачные области cutout-текстур могут стать сплошными
прямоугольниками, часто чёрными, и записывать глубину. Это ожидаемый дефект
теста: листья, деревья и другие вырезанные поверхности могут выглядеть неверно.
Текстуры намеренно не переписываются для маскировки этого эффекта.

Изменяются не только затраты на discard, но и **видимость / occlusion /
overdraw**: заполненный прямоугольник может закрыть дальние поверхности.
Поэтому рост FPS в A доказывает полезность именно этого визуального компромисса
в данном кадре, но **не** измеряет отдельно цену одной операции alpha test.
Если прироста нет, это также не доказывает, что весь RGBA-путь бесплатен:
формат остаётся RGBA, а фактический driver fast path на E65 неизвестен.

Не путать alpha test с alpha blending и не считать этот эксперимент лечением
просвечивания мебели через стены. Точность depth buffer E65 и аппаратное
исполнение M3G по-прежнему не измерены.

## Как сравнить на телефоне

1. Встаньте в одной точке, направьте камеру на деревья / вырезанные поверхности.
2. В **A alpha OFF** не двигайтесь 5–10 секунд. Запишите FPS, N и I или снимите HUD.
3. Нажмите **0**, дождитесь прогрева нового окна 5–10 секунд, запишите те же
   значения для **B alpha ON**, не меняя направление камеры.
4. Ещё раз вернитесь в A и проверьте повторяемость. Повторите у зелёного дома.

N — wall-clock всего nativeRoom.render вместе с Java preparation и release,
не чистое GPU-время. I — интервал кадров с учётом планирования. Устройство с
грубым таймером может показывать 0 ms без нулевой реальной стоимости.

## Выполненные проверки

- Source и packaged suites PASS: **864** реальные комбинации 3 позиций,
  3 pitch, 24 yaw и 4 кадров реки. В ON пакеты точно совпадают с исходным
  Depth near128/far60000. В OFF отличаются **только пороги**.
- **1320** реально отправленных draw-состояний с ненулевым порогом в ON:
  сравнение не вырождается в модель, где alpha test уже был везде выключен.
- XYZ/UV/RGBA/индексы/strips/проекция/остальные состояния сохранены.
  Повторные OFF/ON не загружают vertex/texture/mask buffers.
- Синтетические cutout/opaque кадры в режимах 0/7/9/13: порог после смены
  кадра и восстановления ON правильный, blending/depth не меняются.
- Native failures / OOM освобождают target. Mask OOM сохраняет native whole
  room и переключение порогов, без CPU raster fallback.
- Холодный Viewer загружает все 6 изображений, default OFF, key0 roundtrip,
  key5 no-op, фиксированные near/far, корректный HUD.
- Также проходят прежние 3456 Depth near/far/pose/frame проверок; 8 resource
  tests и 7 исторических rollback checkpoints; preverify CLDC 1.1 / class47.0.

Это проверки контрактов через desktop API doubles, **не растр E65, не телефонный
FPS-бенчмарк и не доказательство аппаратного ускорения M3G**.

```sh
JAVA="$PWD/build/tools/jdk4py/java-runtime/bin/java" \
python scripts/build_static_room_alpha.py --output-dir downloads

JAVA="$PWD/build/tools/jdk4py/java-runtime/bin/java" \
ECJ_JAR="$PWD/build/tools/ecj.jar" \
python tests/static_room/run.py --alpha --packaged \
  --jar downloads/Quantum_StaticRoom_Alpha.jar

python -m unittest discover -s tests/resources -p 'test_static_room_*.py'
```
