# Stlkr: агрессивный профиль всех 13 уровней

18.10.2026. По выбору пользователя «Максимум производительности».
Движок прежний (`d8b99a3` / `619dc39`); меняются только конфиги ресурсов.

## Профиль

Готовые файлы: `configs/stlkr/level1.txt` … `level13.txt`.
План изменений: [`configs/stlkr-profile.json`](../configs/stlkr-profile.json).
В CP1251-файлах сохранены исходные переводы строк и весь остальной текст.

|---|---|---|
| 1, 11 — Кордон | 38000 → **20000** | 28000 → **16000** |
| 2 — промзона | без лимита → **18000** | не добавлялся, DMODE=9 без Fog |

| 10 — Агропром | 40800 → **24000** | 40500 → **20000** |
| 13 — Кордон | 30000 → **20000** | 22000 → **16000** |

В оригинальных уровнях 2–4 DIST отсутствовал, глобального DIST также нет;
LevelLoader использует Integer.MAX_VALUE. Теперь заданы явные лимиты.
Для уровней с туманом его конец сдвинут внутрь новой дальности, с запасом
2000–4000. Цвета тумана, DMODE, статическое освещение, модели, текстуры,
небо, погода, количество частиц, NPC, предметы, спавнеры, задания и переходы
**не менялись**. Исходный архив не редактировался.

**Это заметное ухудшение дальней видимости ради производительности.**
Туман стал плотнее, геометрия и объекты отсекаются раньше. Полностью скрыть
появление/исчезновение на фоне неба не гарантируется; в режимах без Fog
новое отсечение не маскируется туманом. Это не визуально идентичная оптимизация.
DIST/FOGD общие для обоих рендеров: профиль влияет также на Software.

CHUNK_SIZE и сетка коллизий оставлены как в оригинале. Безопасные крупные
render chunks на level12 не дали выигрыша на предыдущем этапе; мелкие в
текущем Room.render могут обрезать близкую геометрию. ИИ и физика не урезались.

Новый `tests/m3g/StlkrLevelsProbe.java`: все 13 настоящих world-моделей,
House/portals, исходные настройки неба, статический свет при наличии файла
и фиксированный native rain. Для каждого уровня — START плюс центр bounding
box каждой комнаты; yaw 0…315 через 45°, pitch 0/45, четыре прогревающих
кадра, записывается четвёртый. Размер 240×320. Центры комнат — точки покрытия
рендера, **не утверждение о проходимости или корректном месте спавна**.

Дополнительно сохранены прежние object-inclusive проверки level12/13:
80 поз, мир с фиксированными idle-NPC/мешами/спрайтами, без активных спавнеров.

На level12 30/80 поз улучшены, остальные прежние. На level13 25 улучшены,
54 прежние и **одна ухудшилась на 2 draws**: soldiers, yaw=180, pitch=0,
D12 → 14. Отсечение геометрии/новая дальность Fog меняют границы пакетов,
поэтому draw count не обязан убывать в каждой сцене.
Сравнение level12 здесь с оригинальным DIST=39000, **не** с промежуточным
умеренным профилем DIST=30000 из коммита `619dc39`.

Все эти тесты используют инструментированные API doubles, **не реальный GPU**.
World-only прогон не моделирует объекты, ИИ, физику, vignette, крыши и молнии;
частицы дождя фиксированные, а не полноценная симуляция. Сокращение DIST не
устраняет преобразование всех вершин видимой комнаты. Из −23,9% D нельзя
выводить +23,9% FPS. Визуальная проверка и FPS на телефоне **не измерялись**.

Известная особенность **исходного архива**: level2 ссылается на отсутствующий
`/gamedata/maps/promzona/promzona.vla`. Fixture сохраняет исходное поведение
загрузчика — default vertex brightness; новый lightmap не выдумывался. DMODE=9
по-прежнему не получает Fog или динамический свет. Level4 содержит LIGHTMAP,
но при исходном DMODE=0 загрузчик его не применяет; это также не менялось.

## Сборка и откат

```sh
python scripts/build_cldc.py \
  --java "$JAVA" --ecj-jar "$ECJ_JAR" \
  --api-dir build/sdk/lib --proguard-jar build/sdk/proguard/lib/proguard.jar \
  --resource-archive 'Stlkr by ebk.jar (1).zip' \
  --resource-overlay configs/stlkr --output-dir artifacts/stlkr-aggressive

python scripts/game_resources.py \
  --archive artifacts/stlkr-aggressive/Quantum.jar --output-dir build/stlkr-all/final
QUANTUM_RESOURCE_JAR="$PWD/build/stlkr-all/final/resources.jar" \
  QUANTUM_STLKR_LEVELS_PROBE=1 python tests/m3g/run.py
python -m unittest discover -s tests/resources -p 'test_*.py'
```

JAVA и ECJ_JAR должны указывать на установленные Java/ECJ. Runner проверяет
только asset-only JAR: классы предварительно удаляет game_resources.py.
Для baseline подготовить resource-only JAR из оригинального архива и запустить
тот же probe. Для object-inclusive проверки заменить флаг на
`QUANTUM_LEVEL12_PROBE=1` либо `QUANTUM_LEVEL13_PROBE=1`.

Overlay включается **явно**, обычный движок и сборки других игр его не получают.
Откат всех настроек: собрать из оригинального архива **без --resource-overlay**.
В ZIP `downloads/Stlkr_Aggressive_Levels.zip` лежат ровно те же 13 конфигов,
что и в полной сборке; их можно использовать для ручной замены в Stlkr JAR.
