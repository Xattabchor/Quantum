# Второй рендер: M3G / JSR-184 (экспериментальный)

Для выбора материалов: [практический гайд по всем режимам M3G](m3g-modes-guide.md).

**Вывод игрового кадра, 18.10.2026:** теперь готовый M3G Image выводится через
`drawImage`, без обязательного финального getRGB. CPU-переходы и снимок паузы
по-прежнему синхронизируют пиксели. Подробные условия, ограничения и проверки:
[Image presentation](m3g-image-presentation.md). Упоминания одного финального
readback в старых разделах/тестах ниже относятся к сохранённым eager API;
GameScreen использует новый image-only entry point.

## Включение

В настройках добавлен пункт **Renderer: Software / M3G (experimental)**.
Переключение клавишами влево/вправо действует со следующего игрового кадра, в том
числе после выхода из паузы. По умолчанию остаётся Software.

В оригинальный `/setting.txt` при желании можно добавить:

```ini
RENDERER=M3G
```

Сохранённый выбор из меню имеет приоритет. Он хранится в отдельном RMS-хранилище
`Quantum.Renderer`; порядок и содержимое полей оригинального файла настроек/RMS
сохранений не менялись. Старые конфигурации без нового ключа работают как прежде.

### Аппаратная перспективная коррекция

После выбора M3G сразу под Renderer появляется **HW perspective: ON / OFF**.
Влево — выключить, вправо — включить; FIRE/SELECT переключает состояние.
По умолчанию **ON**, как в предыдущих сборках. Изменение применяется к следующему
native-проходу, в том числе при возврате из настроек паузы, без перезапуска игры.
При выборе Software строка скрывается, но выбранное значение сохраняется.

Настройка меняет `PolygonMode.setPerspectiveCorrectionEnable` у обычных native
appearance: мир, модельное небо, спрайты, панорама и погодные полосы.
Исключение — специальный affine-UV Fog PolygonMode: он всегда запрашивает OFF,
потому что Fog требует реальный Z, а исходный PERSQ выбрал affine UV.
Драйвер M3G вправе игнорировать этот hint и выполнять перспективную коррекцию. У плоских
экранных примитивов глубина одинакова, поэтому заметной разницы не ожидается.
Кэшированные PolygonMode обновляются только при изменении выбора; геометрия,
UV, исходные цвета освещения, текстуры и буферы не перестраиваются. Общий проход
неба/мира не разделяется и дополнительных upload/readback не добавляется.
OFF разрешает аффинную интерполяцию M3G: на наклонных поверхностях текстура может
искажаться. Реальный результат и скорость зависят от реализации JSR-184;
ускорение на телефоне не измерено.

Это отдельная настройка, не замена исходному **PERSQ**: его значение, подготовка
однородных координат/тумана и Software не меняются. Аварийный CPU replay по-прежнему
использует прежнее качество Software, даже при HW perspective OFF.

Необязательный ключ `/setting.txt`: `M3G_PERSPECTIVE=1` (ON) или `0` (OFF).
Выбор сохраняется при выходе из настроек в отдельной однобайтовой RMS-записи
`Quantum.M3GPerspective`, с приоритетом над конфигурацией. Отсутствующая/некорректная
запись игнорируется. Оригинальные настройки, сохранения и `Quantum.Renderer`
не получают новых полей. Для перевода подписи можно добавить в языковой файл
`M3G_PERSPECTIVE=Аппаратная перспектива`; без ключа используется `HW perspective`.
Исходные языковые файлы не обязательны к изменению.

Для программного выбора:

```java
g3d.setRenderer(DirectX7.M3G);       // или DirectX7.SOFTWARE
```

Игровой экран синхронизирует этот выбор с `Main.renderer` каждый кадр. Программный
benchmark остаётся на Software. `getRenderer()` возвращает запрошенный режим,
`isM3GActive()` — наличие успешно созданного M3G backend, `getRendererError()` —
причину последнего отключения M3G. При ошибке не меняется пользовательская
настройка, но экземпляр рендера продолжает работу программно. Повторную попытку
можно разрешить переключением Software → M3G или изменением размера буфера.

## Что делает M3G

Новый `M3GSceneRenderer` использует `Graphics3D.render` с `VertexBuffer`,
`VertexArray`, `TriangleStripArray`, `Texture2D` и `CompositingMode`. Это отдельный
растеризатор, а не только вывод готовых CPU-пикселей через M3G.

Оставлены исходные загрузчики, преобразования моделей/анимаций, камера,
сортировка и видимость комнат/порталов. Backend получает уже спроецированные
вершины из общей очереди, восстанавливает однородные координаты и передаёт
геометрию в M3G. Благодаря этому сохраняется нестандартная проекция Quantum.
Для текстур с перспективной коррекцией восстанавливаются веса
`1 - rz/TexturingPers.move`, соответствующие знаменателю `move - rz` исходного
`TexturingPers`, а не фокусному расстоянию `distY`. Сохраняются исходные пороги
экранного размера для переключения affine/perspective и режим `persQ=4`;
для fast/affine-пути без Fog используются единичные веса. С native Fog даже affine
UV получают реальные eye-Z, а affine interpolation запрашивается отдельным
PolygonMode, без изменения PERSQ. Преобразования и отсечение
остаются на CPU; растеризация поддерживаемых полигонов выполняется через JSR-184.

Сохраняется исходный painter-order; аппаратный Z-test намеренно выключен.
Это позволяет смешивать M3G-полигоны/спрайты с CPU-материалами без потери порядка.
Для четырёхугольников сохраняется исходный выбор диагонали: обычно ABD/BCD,
но базовый Polygon4V в режимах тумана 3/6 может использовать ABC/ACD в зависимости
от глубин вершин. Lighted/ColorLighted и fast-путь сохраняют ABD/BCD.

### Обратные грани NPC и остальных мешей

В M3G включён аппаратный `PolygonMode.CULL_BACK` для обычных, Lighted и
ColorLighted треугольников/четырёхугольников. Это распространяется на NPC,
Zombie/BigZombie, трупы и другие `MeshImage`, а также объекты/модели через
`addMesh` и полигоны уровня. Используется `WINDING_CW`: при упаковке экранных
координат в M3G ось Y переворачивается, поэтому стандартный CCW скрыл бы лицевые
грани. Проекция и порядок вершин моделей не меняются.

Исходный CPU backface test в `Polygon3V/Polygon4V.isVisible` уже отбрасывал
обратные грани **до сортировки и native draw**; он сохранён для прямого и
вложенного mesh-пути. Новый GPU-флаг дополняет его, в частности отбрасывает
обратную половину согнутого quad, если другая половина остаётся лицевой, и
действует при прямой native-подаче полигона без visibility test. Это не новая
экономия половины draw calls: обычные обратные полигоны и раньше не отправлялись.
Отсечение опирается на текущий winding после трансформации/анимации, а не на
устаревшую нормаль исходного кадра.

Для `SolidSky` используется отдельный переиспользуемый PolygonMode
с `CULL_NONE`. Модельное небо, панорама, спрайты и погодные полосы также сохраняют
`CULL_NONE`; режим восстанавливается при возврате к мешам. Выбор общего
PolygonMode меняется при переходе mesh ↔ экранный эффект, а не на каждом
одинаковом полигоне.
Оба режима поддерживают HW perspective ON/OFF. Z-test по-прежнему выключен,
порядок отрисовки и общий sky/world проход сохранены; новых upload/readback нет.

Software и аварийный CPU replay используют исходное отсечение. Форматы мешей,
анимаций и материалов не меняются. Это backface culling, не occlusion culling:
он не определяет, что целый NPC скрыт стеной или другим объектом.
Визуальный результат и FPS на реальном телефоне не проверены.

### Меньше draw-вызовов: упорядоченные пакеты полигонов

`M3GPolygonBatch` объединяет **только соседние совместимые** полигоны в текущем
painter-order. Пакет вмещает 64 треугольника (192 вершины), то есть до 32 quad.
Треугольники, quad и варианты со статическими RGB/серым светом могут находиться
в одном пакете. Сохраняются выбранные диагонали, порядок треугольников, UV,
цвета/alpha вершин, backface culling и HW perspective. Сортировки по текстурам
нет: геометрия не переносится через другие материалы или прозрачные объекты.

Ключ совместимости включает native-текстуру/mip, texture function/filter,
blending, alpha threshold, PolygonMode и параметры тумана. Для обычных полигонов
без native Fog сохранены исходные целочисленные homogeneous-координаты:
положительный общий масштаб отдельного полигона сокращается при проекции и
перспективной интерполяции. Нового округления весов или смещения общих рёбер нет.
Для native Fog объединяются только полигоны с **точно одинаковым** фактическим
масштабом. Теперь packFog выбирает общую бинарную сетку глубины, поэтому разные
экранные bounds/глубины чаще имеют одинаковый масштаб. Неподходящая сетка возвращает
старую упаковку; несовместимые масштабы всё ещё не смешиваются. Подробнее ниже.

Обычные single-pass материалы, включая alpha/ADD, MODULATE (7) и статическое
освещение, используют пакеты. LQ fog теперь также single-pass native Fog.
Quad-заливка с двумя разными цветами остаётся immediate.
Спрайты, небо и погода пока используют свои отдельные draws.
Перед ними, CPU fallback, загрузкой новой текстуры, изменением HW perspective
и финальным finish накопленная геометрия отправляется в исходном порядке.
Cache miss всё ещё может требовать readback/upload, как до этой оптимизации.

CPU-массивы пакета и native VertexBuffer/VertexArray переиспользуются; индексы
полных/частичных пакетов кэшируются с жёстким ограничением 64 вариантов.
Материал запоминается обычными Java-полями, **без native getter на каждый
полигон**. Загрузка вершин/цветов и установка материала выполняются при отправке
пакета, а не для каждого его полигона. Одиночный несовместимый полигон сохраняет
исходные буферы и точный масштаб. Дополнительных кадровых копий не добавлено.
При dispose незавершённый пакет отбрасывается; при ошибке любого packet draw,
readback или OOM работает прежний полный CPU rollback/replay.

В синтетических контрактных тестах: 100 совместимых triangles → **2 draw**,
100 quad → **4 draw** вместо 100. Вложенный `MeshImage` из 100 подходящих полигонов
также требует 2 draw. Это счётчик вызовов API, **не измеренный FPS на телефоне**.
На реальных ресурсах выигрыш зависит от длины совместимых цепочек, смены
текстур, тумана и CPU-барьеров. Преобразования/анимация остаются CPU-операциями.
Software, оригинальные ресурсы и сохранения не меняются.

### Общая сетка глубины для Fog batching

Раньше scale = max(abs(projected XYZ))/30000 почти всегда отличался у соседних
полигонов. С native Fog эти масштабы нельзя было игнорировать, поэтому даже
одинаковые текстуры давали отдельные draws. Условие равенства scale **не удалено**.

`ProjectedGeometry.packFog` использует engine depth `move-rz` в long и шаг `2^n`:
выбирается минимальный шаг, при котором homogeneous XYZ помещаются с запасом
в short. q = round((move-rz)/step), native scale = step/move. Деление глубины на
step выполняется сдвигом. В одном диапазоне screen/depth величин scale теперь
совпадает, даже когда bounds и глубины меняются. При step=1 исходная целочисленная
глубина представляется без округления depth; остаётся обычная float точность.

X/Y вычисляются **из того же целого q**: (sx-cx)*q, (cy-sy)*q. Конечные экранные
координаты и математические общие рёбра точны, независимо от выбранного масштаба.
Варьирующиеся W не заменяются константой, near-plane и PERSQ не меняются.
Для каждой вершины проверяется прежний предел abs(q*scale - (1-rz/move)) <= W/128,
short overflow, положительность q и видимость rz<=0. Если общая сетка не подходит,
используется старый pack целиком, со старым scale и координатами; новых CPU fallbacks
для ранее представимой геометрии не вводится. Не-Fog packing оставлен прежним.

Пакет сохраняет точные packed XYZ и общий float scale, без повторного округления
при append. Не объединяются разные scale/Fog endpoints/colors/materials/culling,
не сортируются текстуры и не меняется painter order. Fallback/разные lattice bins
могут всё ещё дробить пакет. Новая квантизация **не гарантирует pixel-identical**
текстурную интерполяцию с прежним M3G: возможна небольшая разница в пределах того
же допуска. Это не изменение исходных файлов, mip-порогов или Software.

В независимом тесте 50 000 triangle/quad наборов сверяются точность endpoints,
старый допуск, крайние int/расстояния, shared edges внутри/между bins, отсутствие
нового CPU fallback и побитовое сохранение старой упаковки при fallback. В сценовом
fixture 100 граней с разными depth/bounds имели 100 соседних несовместимых старых
scale, теперь дают **2 native draws** для 3/6 при HW ON/OFF. Режимы 9/13
теперь без Fog, и этот же fixture также даёт 2 draws без Fog-scale ограничений.
Batch stream сравнивается с подачей по одной новой упакованной грани. Это API/
математические тесты, не GPU-снимки и не замер FPS на телефоне.

### Счётчики D / B / T

В выбранном M3G поверх viewport выводится `M3G D:n B:n T:n`; при native failure
префикс меняется на CPU. Строка включена при `DeveloperMenu.showFps` (Show QFPS,
default true), **не требует debugMode**, не показывается в Software. Отдельных
RMS/ресурсных ключей нет. Show QFPS позволяет скрыть диагностический HUD.

- **D**: вызовы Graphics3D.render всех helpers/packet draws, включая sky, sprites,
  post, flash, weather и вызов, бросивший исключение. Это не triangles/objects;
  Graphics3D.clear и LCDUI/HUD не считаются draw-вызовами.
- **B**: промежуточные native->CPU/resource barrier с реальным bound target,
  включая flush ожидающего batch перед CPU-полигоном/холодной текстурой. Финальный
  frame readback, простое завершение packet и finish без target не входят в B.
  Сбой в readback тоже остаётся отмеченным как начатый barrier. После перехода
  GameScreen на image-only вывод сюда также входят попытки отложенного чтения
  Image -> display (сохранение фона следующего кадра, CPU writer, snapshot).
- **T**: успешные создания native Image2D при cache miss, включая отдельные
  LUMINANCE vignette и RGBA flash caches. Это API-уровень, не измерение внутренних
  отложенных GPU/DMA uploads или байтов. Cache hit/vertex uploads не входят в T.

`GameScreen` вызывает beginFrameStats ровно один раз перед подготовкой sky/world.
Счётчики общие для всех частей кадра, не сбрасываются при segment finish, dispose
или аварийном CPU replay; CPU сам их не увеличивает. Публичные getM3GDrawCalls,
getM3GCpuBarriers, getM3GTextureUploads возвращают точные текущие значения с этого
сброса; для внешнего benchmark нужно самому вызвать beginFrameStats перед кадром.

HUD собирает **независимые максимумы за кадр в окне 250 мс**, не сумму вызовов за
250 мс и не обязательно значения одного кадра. Это сохраняет краткий spike T/B.
Кэшированная строка обновляется около 4 раз/сек, либо сразу при смене native/CPU
статуса; нет строк/логов/native getters на каждый draw. Несколько int-инкрементов
и LCDUI HUD не бесплатны, поэтому при замере максимального FPS HUD можно скрыть.
Без JSR-184 счётчики/текст остаются безопасными и показывают CPU/нули после сброса.

### Подготовка материалов после переноса Fog

`M3GMaterialMath` хранит только lazy screen bounds и кэш native Fog far.
Экранные границы вычисляются один раз на текущий полигон и совместно используются
порогом перспективы и mip. Флаг сбрасывается после загрузки каждых вершин;
решения mip/перспективы между кадрами не кэшируются. Screen factor вынесен из
цикла уровней mip, long-разности координат сохранены. `FILTER_BASE_LEVEL` и
исходный выбор `RawImage` не заменяются аппаратным mip-фильтром.

CPU distance visibility, прежний 64-slot fade-кэш (512 байт массивов), делители
flat/additive fog и операция baked RGB × distance fade удалены из native backend.
Остались чтение/clamp публичных baked RGB и LQ grayscale, без кэша изменяемых
цветов. Для серого света читается один канал, тип полигона определяется один раз.
Native Fog far кэшируется при неизменных `fDist`/`TexturingPers.move`, с исходной
float-формулой. Геометрия/анимация, выбор mip и упаковка вершин пока остаются CPU.
Полного переноса подготовки материалов на GPU нет; FPS не измерялся.

### Автоматическое отключение лишнего альфа-теста

При конвертации texture upload в RGBA кэш запоминает, все ли **фактически
загруженные** alpha равны 255. Проверка встроена в существующий цикл, без
второго сканирования исходника. Для opaque/cutout материалов с таким признаком
устанавливается `CompositingMode.setAlphaThreshold(0)` — альфа-тест не нужен.
Если хотя бы один загруженный texel прозрачный, сохраняется порог 0.5.

Это применяется к миру/NPC/мешам, включая статическое освещение и native/legacy
fog, обычным спрайтам и модельному небу. Непрозрачный чёрный не считается дырой.
Проверяется преобразованная alpha с прежними правилами материала, а не только
исходный ARGB или `RawImage.alphaMixing`. Для уменьшенных NPOT-спрайтов признак
определяется по уже выбранным texel уменьшенной копии; сам ресемплинг не менялся.

На cache hit используется готовый float-признак: per-frame сканирования нет.
Новая текстура/mip/кадр анимации или замена массива `RawImage.img` получают
собственные метаданные при upload. Для изменения массива **на месте** сохраняется
прежний контракт: нужен `g3d.releaseRenderer()`, иначе и текстура, и её метаданные
остаются кэшированными. Исходные пиксели оптимизацией не изменяются.

ALPHA blending, ADD, fog-mask проходы и экранные эффекты сохраняют прежнюю
прозрачность.
Пакеты учитывают alpha threshold в ключе состояния; порядок opaque/cutout
и прозрачных объектов не меняется. Сокращение draws сохранено, дополнительных
upload/readback нет. Software и CPU replay не менялись. Это устранение лишнего
alpha-test состояния, а не гарантия ускорения на каждой реализации JSR-184;
FPS и визуальная проверка на реальном устройстве пока не выполнялись.

### Объединённый проход неба и уровня

В игровом `House.renderSkybox` немедленный `g3d.render()` заменён на
`g3d.renderBackground()`. В рабочем M3G это **не draw**, а сохранение уже
подготовленного неба в переиспользуемую отдельную prefix-очередь. Затем House
собирает мир, а существующий финальный `GameScreen → g3d.render()` выполняет
сначала sky prefix, затем независимо отсортированную очередь мира.

Небо не получает искусственную глубину и не участвует в world sort: даже
полигоны с предельным sz остаются поверх фона. Проекция, перспективная коррекция,
материалы, туман, Z-test и исходный порядок внутри каждой очереди не меняются.
SkyMesh хранит копию матрицы; PanoramaSky — снимок viewport/UV-layout, поэтому
сборка комнат и нового portal viewport не меняет уже подготовленный фон.

При прогретом кэше и полностью native-геометрии это один target bind/release,
один финальный readback и один frame backup, вместо отдельных транзакций неба
и мира. Для полного opaque SolidSky/PanoramaSky/SkyFlash не нужен старый upload
кадра. Промежуточный readback/upload **из-за самой границы небо→мир** удалён.
Модельное небо также может продолжаться уровнем в том же bound target, после
восстановления world camera. Выход из House без комнат не теряет sky-only prefix:
его обрабатывает тот же финальный render. Пустой следующий кадр его не повторяет.

Это не удаляет необходимые CPU-барьеры: неподдерживаемый материал/спрайт всё ещё
вызывает finish перед CPU. Cache miss по-прежнему может потребовать finish,
чтобы безопасно загрузить новую текстуру вне bound target. Поэтому первый кадр,
смена animation textures или переполнение кэша могут иметь больше одного обмена.
CPU fallback фон сохраняется при следующем native bind. Постобработка,
погодный overlay, итоговый readback и MIDP flush остаются как прежде.

При ошибке draw/clear/readback/OOM восстанавливаются пиксели **до неба**, затем
оба этапа повторяются на CPU: сначала sky prefix, потом мир. Ошибка мира не
оставляет частично аппаратный фон. Prefix очищается вместе с основной очередью
в finally; ссылки на sky/texture освобождаются. Resize/destroy удаляют старые
очереди. При невозможности выделить prefix-буфер остаётся прежний немедленный
sky-pass. Software/debug/flushAlpha изначально работают в прежнем immediate-пути.

Внешний код, использующий renderBackground(), должен вызвать render() перед
чтением display/постобработкой/overlay, как это делает GameScreen. Прямой вызов
sky.render(...); g3d.render() также поддерживается для самостоятельного sky-pass.
FPS и визуальная проверка на устройстве не проводились; проверены счётчики
native-передач и порядок/откат в контрактных тестах.

### Общие рёбра и небо

Сначала квантуется однородный вес `q`, затем short-координаты вычисляются как
`X=(sx-cx)*q`, `Y=(cy-sy)*q`, `Z=-q`. Их проекция возвращает исходные целочисленные
экранные вершины даже при разных масштабах соседних полигонов. Раньше независимое
округление X/Y/Z допускало ошибку до 0.75 px на полигон: общие рёбра могли
расходиться и открывать фон. Если точные экранные координаты не помещаются в short
или относительная ошибка веса больше `1/128`, полигон остаётся на CPU, а не
передаётся в M3G с деформированной геометрией/перспективой.

### 3D-небо через M3G

Принудительный CPU-проход неба убран. `Skybox` передаёт модель отдельным
`SkyMesh`; `M3GSkyRenderer` получает **видовые координаты до проекции**, а не
пытается восстановить грани за камерой из испорченных экранных координат.

- На CPU остаются преобразования вершин и отсечение треугольников по `rz=0`
  и границам viewport. UV пересчитываются на пересечениях; буферы отсечения
  переиспользуются. Циклов программного текстурирования пикселей здесь нет.
- Для неба используется геометрическая перспектива с весом `distY-rz` и учётом
  отдельного `distX`. Это отдельный путь, а не веса `TexturingPers.move` для
  уже спроецированной геометрии уровня. Перспективная коррекция M3G включена.
- Однородные координаты нормализованы относительно экрана, а один short-масштаб
  используется для **всей модели неба**. Пересечения общих рёбер вычисляются в
  одинаковом направлении, чтобы соседние грани не расходились из-за округления.
- Растеризацию, текстурирование, alpha test/blending выполняет M3G. Обычная
  камера уровня восстанавливается после неба; Fog уровня на небо не переносится.
  Кэш текстур общий с уровнем, включая анимацию и замену RawImage.
- Поддержаны стандартные треугольники/четырёхугольники с материалами 0/1/2/4/7/10
  (11/12 как 0) —
  обычный загрузчик неба создаёт его при `standartDrawmode=0`. Другие материалы,
  неизвестные классы и непредставимые текстуры/веса сохраняют исходный CPU-путь
  **для всей модели**, а не для отдельных граней. При сбое native draw весь
  текущий проход откатывается; фон и мир повторяются исходным рендером.

Software по-прежнему рисует небо оригинальным кодом. Однотонный 2D-фон
`Skybox` (mode 1) в M3G теперь использует цвета вершин, как описано ниже.
Панорамное 2D-небо (mode 2) теперь имеет отдельный M3G-путь ниже;
градиентное mode 3 в M3G заменено однотонным фоном (см. ниже).
M3G-путь убирает CPU-текстурирование модельного неба, но копирование/readback
кадра остаётся. FPS на телефоне 220 МГц без замеров не гарантируется.

### Однотонное 2D-небо: цвета вершин

`Skybox` mode 1 при выбранном M3G создаёт переиспользуемый `SolidSky`.
Это полный экран из двух треугольников в одном draw call, одинаковый исходный RGB
во всех четырёх вершинах, alpha 255. Нет Texture2D, чтения bitmap, UV-сэмплинга,
света, тумана, смешивания или Z-test. Используются единичные веса: фон не меняется
при FOV/повороте камеры. Небо рисуется в существующем проходе до уровня;
размер quad обновляется после resize. Как и старый `clearDisplay`, заливка
покрывает весь буфер независимо от портального viewport.

Старые пиксели не загружаются в target перед полной непрозрачной заливкой.
Резервная копия и итоговый readback объединённого прохода остаются,
поэтому выигрыш FPS не гарантируется. При ошибках draw/readback/OOM, debug/flushAlpha или отсутствии
API используется исходный CPU `clearDisplay` с тем же цветом.

Формат и источник цвета в ресурсах не менялись. Software и модельное небо
не затрагиваются. Замена градиентного mode 3 описана ниже. Панорамный mode 2 перенесён отдельно ниже. Грозовая вспышка остаётся
отдельной дешёвой `Graphics3D.clear` светло-серым цветом, без ветвей/засветки мира;
после неё снова рисуется обычный цвет однотонного неба.

### Градиентное небо заменено однотонным только в M3G

Без отдельного переключателя `Skybox mode 3` при **выбранном M3G** больше не
вызывает CPU `renderGradient`. Вместо этого используется тот же `SolidSky`,
что для mode 1: полный непрозрачный одноцветный фон, один untextured vertex-color
quad до мира, без texture upload, UV, blending и тумана. Пустой viewport ничего
не добавляет. Непустой, в том числе частичный, заменяется полным фоном, как mode 1.
Параметры горизонта, pitch/FOV и lowestDegree на эту плоскую заливку не влияют.

Цвет — RGB первого texel **текущей исходной** `tex.rImg`. Штатный loader продолжает
читать оригинальный ресурс; преобразовывать/заменять файлы уровней и текстур
не нужно. При render читается один цвет, не весь bitmap. `SolidSky` переиспользуется
при неизменном цвете и пересоздаётся только при его смене; исходные пиксели
и mode объекта не меняются. Панорамный mode 2 и модельный mode 0 не затронуты.

После грозовой вспышки возвращается эта однотонная заливка. Она остаётся
однотонной и при missing API, draw/readback/OOM, debug/flushAlpha fallback —
в CPU replay попадает `SolidSky`, не исходный градиент. Небо участвует в общем
sky/world проходе, дополнительных bind/readback не добавлено.

При выборе Software **тот же Skybox с теми же ресурсами** по-прежнему вызывает
исходный `renderGradient`, включая штатные параметры и грозу. Настройки/RMS
не расширяются; нового пункта меню нет. На устройстве/FPS не проверено.

### Панорамное 2D-небо через M3G

`Skybox mode=2` теперь создаёт переиспользуемый `PanoramaSky` и отправляет его
в sky prefix перед миром в объединённом проходе. `M3GPanoramaRenderer` рисует один
текстурированный прямоугольник панорамы и до двух одноцветных прямоугольников
сверху/снизу. Программного цикла выбора texel для каждого пикселя в успешном
native-пути больше нет. Буферы вершин, UV и цветов переиспользуются.

- Исходные вычисления rotateX/rotateY, FOV, horizonScale/horizonOffset,
  lowestDegree и portal viewport сохранены. Native-путь получает готовые
  origin/step исходного 12-битного sampler и учитывает центры пикселей.
- repeatX/repeatY задают UV, включая отрицательные и нулевые значения. Целые
  периоды удаляются перед float-конверсией, поэтому yaw вне 0..360 не требует
  копии/сдвига bitmap и не переполняет short UV. При непредставимом диапазоне
  повторов выбирается CPU fallback до любого native draw.
- Texture2D использует REPEAT/NEAREST, REPLACE, без Fog, освещения, Z-test/write.
  Все texel непрозрачны, включая исходный ноль/чёрный и дробную альфу: как у
  исходного панорамного sampler. Sprite cutout/alpha cache не переиспользуется.
- **Разрешение панорамы не уменьшается.** Берётся текущий texture.rImg,
  без sprite-downsample и без выбора polygon/sprite mip. Текстура загружается
  один раз и переиспользуется при вращении; замена RawImage/img создаёт запись
  общего ограниченного кэша. Исходные текстуры/файлы/параметры не изменяются.
- Поддерживаются POT-изображения в пределах maxTextureDimension/262144 texel
  и представимости UV. NPOT и слишком большие изображения рисуются исходным
  CPU-кодом, без принудительного уменьшения или потери фона. Разбиения большой
  панорамы на аппаратные texture tiles пока нет.
- Полностью непрозрачное небо на весь экран не загружает старый CPU-кадр в
  native target. При частичном portal viewport или отсечении lowestDegree
  старые пиксели вне области сохраняются через исходный upload.
- При сбоях любого из трёх draw, readback/OOM или отсутствии API весь проход
  откатывается и повторяется оригинальным render2D. flushAlpha и debug-overwrite
  используют CPU-путь. Software сохраняет исходный painter.
  Светло-серая M3G-грозовая вспышка по-прежнему заменяет только небо; после неё
  панорама возвращается, без ветвей молнии или засветки мира.

Backup/readback объединённого sky/world прохода и итоговый MIDP flush остаются. Наличие M3G
не гарантирует аппаратный GPU на каждом устройстве и не обещает прирост FPS.
Nearest sampling/округление на границах texel может отличаться от fixed-point
CPU; визуальная проверка на телефоне и замер FPS не выполнялись.

### Дождь и снег: M3G RGB-полосы

При выбранном M3G дождь снова рисуется **нативными полосами**, а не LCDUI.
`prepareM3G` собирает дождь и снег в переиспользуемый ScreenLines без рисования,
а `renderGameFrame` отправляет его после post-effect/flash перед финальным readback.
`paintM3G` сохранён как standalone-обёртка для старых внешних вызовов. `paintAfterScene` при успешном native-проходе больше
не рисует частицы повторно. Координаты framebuffer-local; screenY учитывается
только при flush или LCDUI fallback, а не в native-вершинах.

- Не более **16 дождевых капель** на кадр; лимит симуляции также сохранён.
- Восстановлены исходные диагональный наклон, длина по rainSize/depth,
  цвет rainColorNear/rainColorFar по глубине и белый цвет во время грозы.
- Каждая капля — нетекстурированная RGB-полоса шириной 1 пиксель:
  4 вершины/2 треугольника, до 32 частиц на native draw. Чистый дождь до 16
  капель помещается в один draw; снег использует тот же batch без лимита 16.
- Нет Texture2D/UV/alpha-компонент; `REPLACE`, alpha test 0, без Fog/Z-test/
  Z-write. Массивы переиспользуются, хвост вырожденный, полосы не соединяются.
- Снег сохраняет прежние RGB-прямоугольники и размер/цвет по глубине.
  При пустом кадре старый batch очищается.
- При native/readback ошибках, flushAlpha, debug или отсутствии JSR-184
  используется LCDUI fallback: исходный снег и до 16 дешёвых вертикальных
  дождевых линий. Успешный native-проход никогда не дублируется через LCDUI.

В GameScreen дождь/снег входят в транзакцию мира: отдельного weather backup,
upload/readback больше нет. Standalone paintM3G/renderScreenLines по-прежнему
создают самостоятельный overlay для совместимости. Это **не гарантирует FPS**
на устройстве; исходный LCDUI fallback остаётся.

Лимит теперь действует **и на симуляцию**: создание частиц, update, все шесть
движений камеры, snow-поиск и painter работают по активному списку. При чистом
M3G-дожде это максимум 16 слотов независимо от исходного качества/числа частиц.
Остальной дождь не перемещается, не перегенерируется и не рисуется. При остановке
генерации (`generate=0`) ограничение сохраняется; снег (`generate=2`) работает
по прежнему полному массиву.

Список строится однократным обходом исходных массивов при входе в M3G-дождь,
после clear/замены массивов или возвращения из Software/снега. Обычные кадры
не сканируют неактивный хвост. При смешанных частицах все живые снежинки
добавлены в активный список сверх 16 дождевых слотов и продолжают двигаться;
после исчезновения удаляются из горячего списка, не создавая безлимитный дождь.
В режиме M3G-дождя один Random переиспользуется при update/create/move/moveB,
вместо новых объектов на каждом вызове. Массивы coords/info не обрезаются:
при возвращении в Software возобновляется работа со всей исходной плотностью,
включая ранее приостановленные капли. Формулы движения активных частиц, крыша,
зум и грозовые таймеры сохранены; сами таймеры вызываются даже при пустом списке.

В M3G дождь остаётся редким, но использует исходную форму/цвет капель.
Реальный FPS надо измерять на телефоне; ограничены и native-геометрия,
и горячая симуляция именно дождя.

Software сохраняет прежнюю полную плотность, глубинные цвета, диагональные длины
и порядок рисования; файлы настроек погоды не меняются. Ветви молнии в M3G
отключены, вспышка меняет только фон неба. В Software гроза прежняя.
Отдельный M3G-проход снега всё ещё требует backup/copy/readback кадра.

Поддерживаются стандартные Polygon3V/Polygon4V и их Lighted/ColorLighted варианты:

| Режим материала | Путь |
| --- | --- |
| 0: обычная текстура с прозрачным нулевым пикселем | M3G, alpha test только при наличии дыр |
| 1: бывший аддитивный туман | M3G ALPHA по альфа-каналу текстуры, без Fog; также CPU fallback/replay |
| 2: аддитивная текстура поверх кадра | M3G, CompositingMode.ALPHA_ADD, маска нулевых texel |
| 3: цветной туман | M3G Fog.LINEAR, включая affine/LQ |

| 5: плоское ambient + directional | Native Light.AMBIENT 25% + Light.DIRECTIONAL 75%, короткий weapon OMNI, белый Material, face normals; без Fog |
| 6: чёрный дистанционный туман | M3G Fog.LINEAR чёрного цвета |
| 7: стекло | M3G, текстура с MODULATE; умножение также при CPU fallback/replay |

### Режим 5: native ambient + directional и вспышка OMNI

Вместо `MathUtils.calcLight` и CPU-множителя вершин используется белый Material
с AMBIENT/DIFFUSE, без SPECULAR/EMISSIVE и vertex-color tracking. Свет белый:
AMBIENT 0.25 + DIRECTIONAL 0.75. Формула: `0.25 + 0.75 * max(0, N dot L)`.
Нормали каждой грани нормализуются/упаковываются в short на CPU, затем M3G
вычисляет освещение. Вне импульса выстрела позиции/проекция прежние: нормали и lightdir остаются
в общей исходной системе нормалей, без зависимости от камеры или позиции.
Направление local -Z светильника противоположно lightdir (направлению к свету).
Нулевой lightdir выключает directional. Нулевая нормаль даёт только ambient:
на GPU передаётся единичная нормаль против света, без неопределённого normalize(0).

Плоское затенение сохраняется через независимые нормали треугольников пакета.
Материал/направление входят в state snapshot: другой свет разделяет пакеты,
но совместимые 100 triangles по-прежнему дают 2 draws. Добавляется одна загрузка
массива нормалей на пакет; native буферы/светильники переиспользуются.
Перед unlit world/sky/sprites/post/weather свет снимается, Material у них
отсутствует. После нового bind свет восстанавливается только для режима 5.
Режим 5 не зависит от fogQ и не получает distance blackout. Фонарь и размещённые
point lights не добавлены; статические режимы 9/13 не меняются.

`Weapon` вызывает `startWeaponLight()` только при настоящем выстреле
и `shootLight`. Hook запускает белый Light.OMNI только для режима 5:
120 мс, линейная интенсивность от 1 до 0, повторный выстрел перезапускает таймер.
Положение фиксировано относительно камеры `(40, -40, -120)`, как приближение
позиции дульного среза: новых координат в файлах оружия не требуется.
Attenuation `(1, 0, 1 / 1000^2)` — половина интенсивности на расстоянии 1000,
без жёсткой границы и теней/проверок преград. Фейковый additive blob удалён;
OMNI не требует попадания луча и не создаёт экранный спрайт.

Нельзя применять OMNI к прежним нормированным экранным позициям: масштаб каждого
полигона и affine depth делали бы радиус разным. Поэтому только активные
pulse-пакеты режима 5 используют метрические eye-space позиции: Z = rz,
X = `(sx-centreX)*(distX-rz)/distX`, Y = `(centreY-sy)*(distX-rz)/distY`.
Нормали и directional одновременно поворачиваются world->eye, сохраняя их dot.
Проекция делит на `distX-rz`, позиции квантуются на общей сетке 0.25 единицы.
Проверенная погрешность endpoints <=0.15 px в fixtures. Это не полная GPU-камера
для остального мира. Перспективный UV-вес в импульсе меняется с `move-rz` на
`distX-rz`, также в CPU recovery; affine и HW OFF сохраняются. Поэтому возможна
смена перспективной интерполяции текстуры на время вспышки. Координаты вне
short-сетки (примерно +/-8191 единицы) уходят в CPU material fallback, без wrap
и без отключения backend. Это может добавить CPU barriers во время выстрела.

Интенсивность фиксируется один раз перед сценой и сохраняется при полном replay,
включая отказ третьего addLight после частично отрисованной сцены. CPU-путь
использует ту же формулу по вершинам и исходные серые interpolators, без Fog и
без изменения глобальных fogQ/move/номера текстуры. Следующие выстрелы продолжают
работать при выбранном M3G даже после отказа native backend; Software неизменён.
Смерть/resize/смена renderer очищают импульс. Light/camera сбрасываются перед
другими материалами, sky/sprites/post/weather; light-ресурсы переиспользуются.
Совместимые 100 triangles во время вспышки по-прежнему дают 2 draws в тесте.

При ошибке native setup/render/readback и без JSR-184 API-free CPU-путь выбранного
M3G воспроизводит ambient + directional + активный OMNI (64..256 в исходных /256 samplers).
Software сохраняет свою старую формулу и bypass перспективного fogQ=0.
Контрактные тесты проверяют уравнение, ориентацию, нулевые/крайние векторы,
6 классов полигонов, batching, изоляцию и атомарное восстановление. Это не GPU
визуальная проверка или замер FPS на телефоне; ускорение не гарантируется.

### Спрайты сцены через M3G

`M3GSpriteRenderer` получает все `Meshes.Sprite` из общего dispatch, в том числе
анимированные NPC, предметы и эффекты. Их `SpriteObject`/анимация/проекция,
портальная видимость, addsz и painter-order не меняются. Это не отдельный overlay:
спрайты остаются в отсортированной очереди между полигонами уровня, Z-test/write
отключены. Четыре вершины и два треугольника используют уже вычисленный экранный
прямоугольник. Растяжение, mirX/mirY и отсечение viewport пересчитывают UV, а не
выполняют программное текстурирование каждого пикселя. Буферы переиспользуются.

- `mode=0`: binary cutout, прозрачность только для нулевого texel; непрозрачный
  чёрный сохранён. Альфа ненулевого texel не превращает режим в полупрозрачный.
- `mode=1`: аппаратный ADD с насыщением. Как в оригинале, игнорирует флаг fog
  и дробную альфу исходного изображения. Возможны различия low bits до единицы
  канала: аппаратное смешивание не маскирует младшие биты фона.
- `mode=3`: ALPHA для RawImage.alphaMixing, иначе прежний binary cutout.
- `fog=true`: native Fog.LINEAR по pos.rz/fDist, независимо от polygon fogQ.
  Один проход для цветного/чёрного тумана, без CPU коэффициента или fog-mask.
  Все четыре вершины имеют общий реальный eye-Z: общий масштаб XYZ сохраняет
  экранный прямоугольник и UV. При стандартном режиме 6 цвет Fog чёрный, иначе FOGC.
  Fog применяется к источнику до ALPHA blending, сохраняя дырки/дробную альфу.
  ADD/MUL-спрайты туман не получают; fDist=0, как раньше, выключает sprite fog.
  Отрицательная дальность/непредставимые eye-Z/range возвращают CPU fallback.
- `mode=2` (MUL, `color=0..6`): один native `CompositingMode.MODULATE`
  вместо нестандартного насыщаемого MUL. В копии текстуры яркость берётся из
  синего канала, как в исходном формате, и применяется ко всем RGB (color 0)
  или только R/G/B/RB/RG/GB (color 1..6); прочие каналы имеют множитель 255.
  Нулевой texel и исходный нейтральный ключ `blue=69` преобразуются в белый,
  поэтому сохраняют фон без чёрного прямоугольника. Частичная alpha не управляет
  смешиванием. MUL, как ADD, игнорирует fog. Исходный bitmap не меняется.
  Конвертация и NPOT-уменьшение происходят только при cache miss; color включён
  в ключ общего ограниченного кэша. CPU recovery выбранного M3G выполняет то же
  умножение без возврата к legacy MUL, с исходной CPU-выборкой/clip/mirror.
  **Намеренно изменён вид:** вместо старого усиления около `brightness/64`
  используется `brightness/255` — обычный MODULATE не осветляет и выглядит темнее.
  В выбранном Software исходные saturating MUL/color операторы остаются без изменений.
  Неизвестные sprite modes/color сохраняют исходный CPU fallback.

Выбирается текущий `textures[anim_index]` и его mip[0], как у исходного painter,
а не mip-подбор полигонов. Render не меняет anim_index и не продвигает анимацию.
Нестепенные размеры разрешены: при первом upload **копия** изображения
уменьшается до ближайших меньших степеней двойки по каждой оси:
70×90 → 64×64, 127×65 → 64×64, 3×5 → 2×4. Округления вверх и padding больше
нет. POT-размеры не меняются: 64×128 остаётся 64×128, 128×128 — 128×128.
Это не принудительный лимит 64×64 для всех спрайтов.

Используется дешёвый nearest-neighbor по центрам texel, без смешивания RGB
прозрачных пикселей. Fog не требует отдельной копии текстуры;
cutout/ADD/alpha сохраняют прежние правила прозрачности. UV покрывают всю
уменьшенную копию; wrapping CLAMP, фильтр NEAREST. Геометрия/размер/пропорции
спрайта на экране не меняются: меняется детализация текстуры, мелкие элементы
могут исчезнуть. Ресемплинг выполняется только на cache miss, не каждый кадр.
Исходные RawImage, массивы, размеры, настройки scale и файлы не меняются;
Software и CPU fallback используют исходное разрешение. Если и полученная
POT-копия превышает maxTextureDimension/лимит кэша, спрайт остаётся на CPU.

Кэш общий по лимиту с уровнем: 16 записей/262144 texel; учитывается размер
именно уменьшенной копии, а не исходника. Sprite cutout/alpha/ADD имеют отдельные ключи,
чтобы их wrapping/альфа не портили материалы уровня. Повторные кадры и возврат
к уже закэшированному animation frame не требуют нового upload. Замена img,
RawImage или размеров создаёт новую запись; in-place изменение пикселей, как
и прежде, требует releaseRenderer(). Resize/переключение режима освобождают кэш.
На cache miss загрузка выполняется только вне bound target, с сохранением
порядка. На прогретом кэше переход полигон→спрайт→полигон сам по себе больше
не вызывает CPU readback/upload-барьер. Все поддерживаемые спрайты, включая Fog,
требуют один draw на объект; batching между объектами нет.

Software, HUD и LCDUI-оружие не меняются. При draw/readback/OOM/отсутствии API
весь проход откатывается и повторяется исходным CPU-кодом. flushAlpha и карта
перерисовки сохраняют программный путь. Пиксельное совпадение не обещается:
GPU nearest sampling/границы зеркалирования могут отличаться от старого
fixed-point/modulo sampler, fog/alpha — округлением на 1–2 единицы канала.
На телефоне визуальная проверка и замер FPS не проводились.

### Материалы 2, 5 и 8

- **2**: один аддитивный M3G-проход с насыщением. Нулевой texel остаётся
  прозрачным, любой ненулевой — непрозрачным источником независимо от дробной
  альфы исходного пикселя. RGB источника кэшируется с маской `0xfefefe`, как
  в Software. M3G не может сбросить младший бит каналов уже нарисованного фона:
  на образце texel результат может отличаться на **1 единицу канала** от CPU.
  Текстура загружается один раз на вариант кэша, не пересчитывается каждый кадр.
- **5**: один проход `texture × vertex RGB`, один коэффициент на весь полигон.
  Используется исходный `MathUtils.calcLight(normal, DirectX7.lightdir)`;
  native `Light`, выстрел, фонарь и camera-vector light не добавляются.
  Сохранена особенность оригинала: при `fogQ=0` perspective-путь не затемняет,
  а affine продолжает затемнять. Исходное деление на 256 аппроксимируется
  ближайшим восьмибитным M3G-множителем; разница на образце — до 1 единицы канала
  без учёта точности конкретного GPU. Это не затрагивает статические режимы 9/13.
- **8**: CPU только выбирает один цвет из исходной текстуры/выбранного mip,
  растеризация — M3G без загрузки `Texture2D`. Сохранены масштабирование UV,
  endpoint `255→256` для малых текстур и исходная wrap-маска. Нулевой пиксель
  означает **непрозрачную чёрную заливку**, а не отверстие. Для quad сохранены
  ABD/BCD: первая грань берёт цвет UV вершины A, вторая — B. Если цвета совпадают,
  достаточно одного draw call; иначе используются два. Освещение/туман не применяются.

Все три режима используют существующие painter-order, CPU-барьеры и полный откат
кадра при ошибке M3G/readback. Software и исходные файлы материалов не меняются.
Ограничения геометрии/точности и CPU fallback сохраняются; 2/5 также сохраняют
ограничения размеров M3G-текстур. У режима 8 такого ограничения на bitmap нет,
так как bitmap не передаётся в JSR-184.

### Отключённый dithering: материалы 11 и 12

При выборе M3G номера 11/12 считаются **алиасами режима 0**. Вместо узора
и градиента рисуется обычная текстура с маской нулевого пикселя. Нет расчёта
покрытия по вершинам, `waterDistance` или `fDist`, alpha-перехода или отдельной
Bayer-текстуры. Это сознательное отключение эффекта, а не его имитация.
Выбор mip/перспективы, геометрия, цвета вершин и кэш — как у материала 0;
отдельные варианты Texture2D для 11/12 не создаются. Модельное небо также
принимает эти номера как обычную текстуру.

CPU fallback и аварийный replay при выбранном M3G тоже используют режим 0,
чтобы при отказе native backend дизеринг не возвращался. Для этого только на
время CPU-вызова номер материала подменяется и восстанавливается в `finally`.
Оригинальные файлы/поля материалов не меняются постоянно; при переключении
на Software исходные 11/12 работают по-прежнему. Старые функции дизеринга
не удалены, поскольку нужны Software. Общие геометрические/текстурные ограничения,
fallback для неподдерживаемых спрайтов и debug/alpha-барьеры остаются.

### Материал 10: MODULATE_X2

При выбранном M3G материал 10 использует `CompositingMode.MODULATE_X2`:
`min(255, source * background * 2 / 255)` поканально. Средний серый примерно
нейтрален, тёмные участки затемняют, светлые осветляют до насыщения.
Нулевой texel — cutout, непрозрачный чёрный даёт чёрный. Частичная alpha
не регулирует смешивание RGB. Fog и динамическое освещение не добавляются.

Используются исходная текстура, UV, обычный mip-выбор и perspective-настройки,
общий opaque/cutout-кэш. Сохранены culling, painter-order и ordered batching;
пакеты разных blend (0/7/10) не смешиваются. Дополнительного захвата фона нет.
CPU affine/perspective fallback, debug/flushAlpha, отсутствие API и полный
аварийный replay выбранного M3G выполняют то же умножение ×2 с насыщением,
без возврата к дизерингу. Номер материала и исходный bitmap не подменяются.
При выбранном Software материал 10 сохраняет оригинальный dithering и mip-выбор.
Материал 1 остаётся ALPHA, 2 — ADD, 7 — обычным MODULATE.

`ModulateX2Test` проверяет уравнение/clamp, cutout/чёрный/белый/серый/частичную
alpha, все шесть типов полигонов, HW ON/OFF, affine/perspective/fogQ/mip,
кэш/batching и сохранение 2/7. CPU recovery сравнивается попиксельно с независимым
эталоном для узорчатой текстуры и mip-цепочки, включая draw/readback/OOM,
геометрический/debug fallback и отсутствие JSR-184. Сохранён отдельный тест
исходного Software. Это contract-тесты, не замер FPS или GPU-визуализации.

### Материал 1: ALPHA

При выбранном M3G материал 1 использует `CompositingMode.ALPHA` по исходному
альфа-каналу текстуры: 0 сохраняет фон, 255 закрывает его, промежуточные значения
смешивают RGB. Фиксированная общая прозрачность не добавляется: полностью
непрозрачная исходная текстура остаётся непрозрачной. Fog/FOGC/FOGD и fogQ
не управляют видом этого материала. Режим 2 остаётся ADD, 7 — MODULATE.

UV/mip/перспектива, culling, painter-order, batching сохранены. Используется
общий с режимом 4 ALPHA-кэш, alpha test выключен, исходная alpha читается даже
при false в `RawImage.alphaMixing`. Нет дополнительных проходов или снимков фона.
Номер материала и bitmap не подменяются и в ресурсах менять их не нужно.

CPU fallback/debug/flushAlpha и полный аварийный replay выбранного M3G направляют
материал 1 в существующий ALPHA-сэмплер режима 4, без прежнего тумана.
Его legacy integer-округление `/256` может отличаться от native ALPHA примерно
на единицу канала. Оригинальный Software-режим 1 сохраняет прежний туман.

`AlphaModeTest` проверяет шесть типов полигонов, HW ON/OFF, affine/perspective,
fogQ/mip, уравнение native ALPHA и крайние значения alpha, stale alphaMixing,
кэш/batching и CPU replay после ошибок draw/readback/OOM, debug/геометрический
fallback, сохранение Software. Отсутствие JSR-184 покрыто `MissingM3GTest`.

### Материал 7: MODULATE

При выбранном M3G материал **7 использует `CompositingMode.MODULATE`**:
RGB фона умножается поканально на RGB исходной текстуры. Белый сохраняет фон,
серый затемняет, цветной texel тонирует и затемняет. Нулевой texel — cutout
(фон не меняется), непрозрачный чёрный затемняет до чёрного. Частичная alpha
не управляет прозрачностью: это умножение RGB, а не ALPHA-смешивание.

Сохраняются исходные UV, mip, перспективная интерполяция, painter-order,
GPU culling и ordered batching. Отдельного снимка фона для преломления нет;
материал 7 использует обычный opaque/cutout-кэш текстур. Blend отличается
от материалов 0 и 2, поэтому их пакеты не смешиваются. Режим 2 остаётся ADD.
Туман и динамический свет к материалу 7 не добавляются.

При CPU fallback, debug/flushAlpha, отсутствии API и полном аварийном replay
выбранного M3G affine/perspective-сэмплеры режима 7 также умножают RGB
(`source * background / 255`) без преломления и без отдельного framebuffer.
Исходный номер материала не подменяется. При выбранном Software те же сэмплеры
выполняют оригинальное преломление. Исходные ресурсы не меняются.
FPS/внешний вид на телефоне не проверены; слои всё ещё увеличивают overdraw.

### Статические лайтмапы в M3G

Используется выбранный вариант **только статического освещения**: исходные
`LightedPolygon3V/4V.la/lb/lc/ld` и `ColorLightedPolygon3V/4V` RGB передаются
в M3G через `VertexArray` цветов. Сами исходные файлы `LIGHTMAP`, загрузчик
и поля моделей не меняются; перезапекать или конвертировать ресурсы не нужно.

- Материал 9 использует серую яркость. Материал 13 теперь также растеризуется
  M3G и сохраняет RGB при `fogQ=2`; при `fogQ=1` цвета усредняются в серый,
  как в исходном рендере. `fogQ=0` по прежней семантике отключает и освещение:
  текстура рисуется с белыми цветами вершин.
- В M3G-пути 9/13 не вызывается динамический `getLight`: выстрел, фонарь и
  camera-vector light **не меняют** статическое освещение. Это относится
  к обычному, affine/fast и mip-путям. Нативных `M3G Light`/point light нет.
- Чёрный native Fog и дистанционное затухание из 9/13 удалены: остаётся
  только текстура × исходные baked цвета. Это действует и в CPU fallback/replay
  выбранного M3G: scalar/RGB static scope лишь ограничивает каналы 0..255,
  без visibility, умножения или деления на fDist. Исходные поля/файлы не меняются.
  fDist<=1 больше не отправляет эти материалы на CPU; геометрические/текстурные
  ограничения остаются. Прежние fogQ=0 bypass и fogQ=1 RGB->gray сохранены.
  Без ограничений Fog-scale совместимые 0/9/13 с общей текстурой могут оказаться
  в одном ordered-пакете, сохраняя разные цвета каждой грани.
- Если выбран M3G, но конкретная геометрия/текстура ушла на CPU либо native
  draw завершился ошибкой, scoped static-путь 9/13 также исключает динамику.
  Флаги выстрела, фонаря и глобальный camera-vector light не подменяются;
  scope восстанавливается в `finally`, включая исключения и вложенный dispatch.
- При выборе **Software** всё работает по-старому: исходный `getLight`, реакция
  на выстрелы и фонарь сохранены. Полного совпадения M3G/Software теперь
  намеренно нет: выбранный M3G-вариант статический. Округление цветов и
  интерполяция M3G также могут отличаться от исходного растеризатора.

### Фейковое additive-освещение удалено

Экранный `MuzzleGlow` удалён: нет процедурной радиальной RGBA-текстуры,
её отдельного native-кэша/upload и дополнительного additive draw после мира.
Игровой кадр больше не вызывает косметический raycast для этого эффекта.
Сохранены настоящий короткий OMNI режима 5, обычные ADD-спрайты и материал 2.
`SHOOT_LIGHT` по-прежнему управляет импульсом реального света при выстреле.

Для совместимости `startMuzzleGlow()` делегирует только `startWeaponLight()`,
а `renderMuzzleGlow(house,part)` всегда возвращает false без рисования/запроса луча.
Оригинальный Software, оружие и формат ресурсов не менялись.

## Туман в M3G

Для поддерживаемых полигонов **3/6** и fog-спрайтов используется
`javax.microedition.m3g.Fog.LINEAR`, один проход. CPU не считает distance visibility,
flat/additive coefficients, не домножает baked RGB на расстояние и не загружает
белые fog-mask текстуры. Растеризация тумана выполняется JSR-184, не CPU-растеризатором.

Сохраняются исходные `DirectX7.fDist` / `fogc` из `FOGD`, `FOGC` или
`FOGCR/FOGCG/FOGCB`, режимы материалов в ресурсах и загрузчики. Новых ключей нет.
Материал 3 использует FOGC, 6 — чёрный Fog. В 9/13 оставлены только baked цвета:
нет ни native Fog, ни дистанционного затемнения в selected-M3G CPU replay.
Для полигонов `fogQ=0` отключает Fog; 1 и 2 включают тот же плавный native Fog.
Флаг LQFOG больше не заставляет native путь считать плоский fog на CPU.
Остаётся исходное LQ усреднение baked RGB в материале 13.

**Намеренные отличия:** mode 1 теперь ALPHA без Fog, не насыщаемое ADD;
LQ туман остальных fog-материалов плавный, не по самой дальней вершине каждой половины quad. Mode 6 больше
не вычисляет legacy camera-vector lighting в native пути. HQ тоже может отличаться
округлением, интерполяцией и clamp на границе дальности. Это согласованный перенос
на стандартный Fog, не обещание пиксельного совпадения с Software.

Восстановленная eye-distance равна `1 - rz/TexturingPers.move`: near = `1`,
far = `1 + fDist/TexturingPers.move`. Параметр far кэшируется по обоим входам;
цвет обновляется из текущего материала. FOV не меняет единицы Fog. Affine/fast
полигоны с Fog также получают реальные неодинаковые Z, без flattening весов.
Отдельный PolygonMode запрашивает affine UV (perspective correction OFF), чтобы
не принуждать PERSQ к другому значению. M3G-драйвер вправе игнорировать affine hint.
Для perspective материалов HW perspective продолжает работать как раньше.
Небо, HUD и остальные материалы Fog не получают; состояние не протекает между draws.

Спрайты используют свой fog-флаг, независимо от polygon fogQ: см. раздел выше.
ADD-спрайты по-прежнему без Fog. В native Fog нет полноэкранной пелены и заполнения
дыр: прежние cutout/ALPHA правила сохраняются в том же проходе.

При fDist<=1 у fog-полигонов, непредставимом native range, геометрии или текстуре
остаётся исходный CPU fallback. Draw/readback/OOM откатывают всю очередь кадра,
включая уже нарисованные объекты, на прежний Software/static-only replay.
Software не менялся: там остаются оригинальные LQ, ADD, camera-vector fog и формулы.
Fallback может выглядеть иначе, чем стандартный native Fog.

Native Fog пакеты требуют точно одинакового фактического eye-space масштаба.
Общая бинарная сетка теперь сокращает несовместимые масштабы, но fallback/разные
bins могут по-прежнему **увеличивать число draw** относительно non-Fog пути.
Они не объединяются ценой неправильного масштаба глубины. Для ранее
двухпроходного/quad LQ тумана теперь достаточно одного draw, fog-mask upload убраны.
Реальный баланс CPU/GPU и FPS нужно проверить на телефоне; GPU-снимков и замеров нет.

### Самая простая гроза: светлый фон неба

При выбранном M3G вспышка только заменяет фон неба на `0xe5e5e5` на прежние
135 мс. `Skybox` не рисует модель/градиент/skyLighting в эти кадры, не генерирует
ветви молнии. Засветка поверх мира отключена в GameScreen и дополнительно в
WeatherGenerator, в том числе после отказа native backend. Стены и предметы
не светлеют; если небо не видно, эффект может быть совсем незаметен.

`SkyFlash` передаётся в существующий проход неба перед уровнем. M3G выполняет
`Graphics3D.clear(Background)` с отключённой очисткой глубины: **без треугольников,
текстур, alpha blending и отдельного overlay поверх мира**. Background и объект
эффекта переиспользуются. При привязке target для такой очистки пропускается
загрузка старого CPU-кадра: он полностью заменяется цветом. Уровень после этого
отрисовывается обычным способом, закрывая фон. По окончании вспышки автоматически
возвращается выбранный обычный вид неба.

Остаются резервная копия и итоговый readback объединённого sky/world прохода:
это не полный отказ от обмена кадром между M3G и MIDP. При clear/readback/OOM ошибке проход
откатывается, SkyFlash выполняет обычный `clearDisplay` тем же цветом.
Debug/flushAlpha/отсутствие API также сохраняют простое светлое небо, **не**
возвращая ветви или дорогую засветку. Software сохраняет исходную грозу целиком:
настроенный skyLighting, болты молнии и градиентную засветку вне крыши.
Оригинальные ресурсы/таймеры/погода не меняются. Предыдущие StormFlash и
M3GStormFlash с отдельным additive overlay удалены. FPS на телефоне не измерялся.

## Совместимость ресурсов

Форматы моделей, QCT/обычных текстур, уровней, скриптов и игровых сохранений не
изменены. Конвертация в M3G-объекты выполняется в памяти **после** штатной загрузки;
перепаковывать модели в `.m3g` не нужно. Мип-уровни выбираются из исходных RawImage,
анимация текстур использует текущий RawImage. Текстуры загружаются в RGBA без
изменения оригинального массива. Для mode 0/3/6/9 ненулевой пиксель остаётся непрозрачным,
для mode 4 сохраняется дробная альфа.

Для полигонов текстуры с размерами, не являющимися степенями двойки,
превышающие аппаратный лимит или лимит одного cache entry (262144 пикселя),
обрабатываются программно. Для спрайтов действует описанное выше уменьшение
NPOT-копий до меньших POT-размеров. То же касается
вершин за камерой и случаев, когда short-координаты M3G не позволяют сохранить
точные экранные координаты и достаточно стабильные веса перспективы. Ресурс не отвергается и не заменяется
пустой текстурой.

Кэш ограничен 16 записями и 262144 пикселями суммарно. Замена `RawImage` или
его `img` создаёт новую запись. Если пользовательский код меняет содержимое
публичного массива `RawImage.img` **на месте**, нужно вызвать `g3d.releaseRenderer()`
для сброса кэша. Изменение размера экрана, смена backend и `destroy()` освобождают
его автоматически.

## Кадровый буфер и отказоустойчивость

M3G рисует в mutable LCDUI Image. Перед native-сегментом без полного opaque sky
он получает текущие CPU-пиксели; перед CPU-объектом target освобождается и результат
возвращается через `Image.getRGB` в **тот же** `DirectX7.display`.
GameScreen использует `renderGameFrameImage`: виньетка/урон/смерть и native weather
рисуются вместе с миром, завершённый Image выводится через `drawImage` без финального
getRGB. `getDisplay()` материализует пиксели для паузы/CPU writer. Без гарантированного
полного фона предыдущий Image читается перед повторным использованием для правильного
backup/replay. Подробности и поведение при позднем snapshot failure —
[Image presentation](m3g-image-presentation.md). Legacy `render()` и `renderGameFrame`
по-прежнему завершаются eager getRGB. Bloom/doubleBright в M3G отключены; HUD и меню
остаются LCDUI и не окрашиваются post-effect.

`flushAlpha=true` и отладочная карта перерисовки целиком используют Software:
mutable Image не гарантирует сохранение исходной альфы, а счётчик перерисовки
требует CPU-растеризации.

До M3G-прохода сохраняется копия пикселей. При отсутствии JSR-184, исключении
native API, ошибке промежуточного/eager финального readback или OutOfMemoryError текущий target освобождается,
восстанавливается исходный буфер и **вся очередь** данного прохода повторяется
программно. Backend отключается для этого экземпляра до явного повторного выбора
или resize. Sky prefix и world queue, а также внутренняя очередь MeshImage,
очищаются и при исключении. Не используются повторные попытки M3G каждый кадр.

### BLOOM — только Software

Оригинальный ключ `BLOOM` по-прежнему читается из уровня/общих настроек,
но `fastbloomScr` вызывается только при `g3d.getRenderer()==DirectX7.SOFTWARE`.
При выбранном M3G CPU bloom полностью пропускается, в том числе при отсутствии
JSR-184, native-ошибке или другом CPU fallback. Проверяется запрошенный backend,
а не `isM3GActive()`.

Сам флаг `GameScreen.bloom` не сбрасывается: после переключения на Software
снова действует исходное значение уровня без его перезагрузки. Формат и название
ключа не изменены, нового пункта меню нет. Постэффекты M3G отдельно заменены
быстрым combined overlay (ниже); погода сохраняется в общем проходе. Source-guards
проверяют Software-only условие, единственное место вызова и прежний loader ключа.
FPS/визуальная проверка на телефоне не проводились.

### Виньетка, урон и смерть: один дешёвый native post-effect

Для **выбранного M3G** `GameScreen` передаёт маску/флаги в `DirectX7.renderGameFrame`.
Прежний renderWithEffects сохранён для callers без погоды.
Эффект не сортируется с миром: после sky/world/nested queues, до единственного
финального `SceneRenderer.finish/getRGB` вызывается `FrameEffects`. Подготовка
его кэша выполняется **до любого native scene draw**, поэтому даже холодный upload
маски сам по себе не добавляет bind/readback. CPU-материалы/холодные мировые текстуры
по-прежнему могут создавать свои прежние барьеры. После post-effect идут
weather draws в том же target, затем единственный finish и LCDUI оружие/HUD.

`M3GFrameEffects` рисует **один quad / один draw для всех трёх эффектов вместе**:

- CompositingMode.MODULATE, Z-test/write OFF, CULL_NONE, Fog/alpha-test OFF.
  Не выполняются три ALPHA-overlay и не создаются варианты текстуры по флагам.
- Исходный byte[] виньетки конвертируется только при смене ссылки/размера framebuffer.
  Маска уменьшается по центрам texel до POT не более 64×64 и maxTextureDimension,
  LUMINANCE (1 байт на texel, до 4096 байт входных данных), LINEAR/CLAMP.
  Внутреннее GPU-хранение зависит от драйвера. Сохранён выбор пар коэффициентов
  исходного unrolled applyVignette; d/256 переводится в ближайший byte/255.
  Высокочастотные детали исходной маски сглаживаются; это не pixel-exact замена.
- Урон — красный multiply-фильтр `(255,64,64)`, без непрозрачной/alpha заливки:
  он не добавляет красный к чёрному, а подавляет green/blue. Смерть — чёрный
  затемняющий overlay, эквивалентный множителю 128/255, **не grayscale**.
  При обоих флагах tint `(128,32,32)`. Все множители совмещаются в default vertex RGB.
- Quad/UV и буферы переиспользуются. Геометрия обновляется только при resize/смене
  центра проекции, default color — при смене tint, текстура — при смене маски/размера.
  На обычном прогретом кадре нет pixel loops, VertexArray.set и mask upload.
  Временно выключенная маска остаётся кэшированной; пустая маска/отсутствие флагов
  полностью пропускают draw. Для in-place изменения vignette нужен releaseRenderer.
- DoubleBright пропускается по **запрошенному** M3G, даже после native-отказа.
  Ключ/флаг не удаляется: при возврате в Software снова действует исходный выбор.

`FrameEffects` не содержит optional API. При missing JSR-184, draw/readback/OOM
сохраняется прежний атомарный rollback/replay всей очереди, **затем** ровно один
объединённый CPU-цикл новых эффектов. flushAlpha/debug/непредставимый native quad
также используют fused CPU fallback, без возврата к старому death/damage/doubleBright.
CPU fallback использует исходные коэффициенты полноразмерной виньетки, без downsample;
его результат может отличаться от сглаженной native маски. Полного удаления CPU
обработки при отказе native backend не обещается.

Software оставлен исходным: applyVignette, grayscale deathScr, damageScr, applySub
и BLOOM в прежнем порядке. Форматы/загрузчики VIGNETTE и настроек не менялись.
Новая маска имеет отдельный ограниченный кэш, не вытесняет 16 мировых текстур.
Dispose/resize/смена backend освобождают native mask/буферы. FPS/визуальная проверка
на телефоне не выполнены: один дополнительный fullscreen fill всё равно стоит GPU.

### Откат CPU-оптимизаций после KVM (18.10.2026)

Восстановлены реализации до KVM (`c981fce`): OMNI packing/shading и mode5Shade
без новых кэшей, арифметический FrameEffects без tint-LUT, native-нормали без
нового normal cache, исходный ordered append без bulk-copy fast paths.
Из последующих изменений игрового кода оставлен только Image presentation.
Точные regression-тесты сохранены и адаптированы к исходным private-реализациям.
[Состав и проверки](m3g-pre-kvm-rollback.md). Старые KVM-результаты — архив,
не описание текущей сборки и не измерение её FPS.

### Единая игровая транзакция с погодой

`DirectX7.renderGameFrameImage(vignette,dead,damaged,house,part,weather)` в GameScreen обрабатывает:

1. Подготовку кэшированной маски и weather helper buffers
   **до первого native bind**.
2. Sky prefix, отсортированный мир и вложенные MeshImage в исходном порядке.
3. Совмещённый MODULATE post-effect.
4. Пакеты RGB погоды (по 32 частицы), затем finishImage/releaseTarget и drawImage.

На прогретом кэше полностью native-сцены с полным opaque sky — **один backup,
один bind/release, без финального getRGB и без чтения предыдущего Image**,
а не отдельные транзакции post/weather. Непрозрачное полное
небо не загружает старый CPU framebuffer в target; без такого неба
остаются необходимые чтение предыдущего Image и загрузка фона.
Legacy `renderGameFrame` сохраняет один финальный eager readback. Количество GPU draw не сводится к одному:
batching/слои/погодные packets остаются отдельными вызовами.

Выстрел не создаёт overlay-текстур и не вытесняет мировой FIFO из 16 текстур.

`WeatherGenerator.prepareM3G` делает только snapshot полос из текущей симуляции.
Тот же ScreenLines и массивы переиспользуются, старый count очищается. Нет второго
update/random/camera move. Сохранены 16 rain slots, полный snow pool, RGB/depth/
thunder, screenY только в flush/LCDUI fallback. drawPortals/flushAlpha/debug или
неактивный backend сохраняют прежний fallback/порядок.

Результат renderGameFrameImage означает, можно ли пропустить LCDUI weather. Флаг true
возвращается после успешного **завершения всех draws и releaseTarget**, не после первой
погодной порции (legacy renderGameFrame также проверяет финальный readback); пустой кадр без частиц не требует submission. Unsupported weather возвращает
false без отключения успешно нарисованного мира. При exception/OOM/readback failure
в любом этапе освобождается target, восстанавливается pre-frame backup и один раз
повторяются sky/world/post на CPU. ScreenLines погоды не отправляется в CPU replay: после flush рисует исходный LCDUI snow и
ограниченный rain. Нет дублирования частично успешных native particles.

Standalone renderOverlay/renderScreenLines/paintM3G сохранены,
но GameScreen больше их не вызывает. Они по-прежнему отдельные транзакции для
внешних callers. Software GameScreen остаётся исходным. Не устраняются необходимые
CPU-барьеры/загрузки холодных мировых текстур. Скорость на устройстве не измерена.

## Ограничения и производительность

Это совместимый гибридный backend, а не полностью аппаратный scene graph.
Часть сложных материалов остаётся на CPU. Виньетка/урон/смерть уже native; копирование/readback
и чередование CPU/M3G могут сделать его **медленнее** исходного рендера, особенно
на сценах с чередованием неподдерживаемых спрайтов и native-материалов. Требуются дополнительный
Image и резервный int[] кадра. Ускорение и побитовое визуальное совпадение не
гарантируются. Способ перспективной интерполяции/выбора mip и округление могут
отличаться. Наличие JSR-184 само по себе не гарантирует аппаратное ускорение.

Оригинальный экспериментальный `Meshes.M3GParser` оставлен для совместимости,
но новый backend его не использует.

## Сборка и тесты

Используется тот же `scripts/build_cldc.py`, что описан в
[инструкции сборки](build-cldc.md). В API classpath нужен JSR-184.
Software использует исходный MIDP `Graphics.drawRGB`; GameScreen M3G —
`Graphics.drawImage`, с drawRGB для CPU/eager/fallback путей.
Nokia DirectGraphics удалён, Nokia UI API для сборки и работы не требуется.
Обфускация выключена; при её включении дополнительно сохраните имя/конструктор:

```text
-keep class code.Rendering.M3GSceneRenderer { public *; }
```

После сборки на desktop JDK:

```sh
python3 tests/m3g/run.py
python3 tests/framebuffer/run.py
python3 tests/settings/run.py
```

Поддерживаются `JAVA`/`JAVAC` или `JAVA`/`ECJ_JAR`. M3G-тесты используют
инструментированные API-заглушки вне `src/`: они проверяют вызовы настоящего backend,

## Аудит оптимизаций после переназначения режимов

Проверка режимов 1→ALPHA, 7→MODULATE, 10→MODULATE_X2 и MUL-спрайтов выявила
и исправила регрессию модельного неба: прежняя проверка 0/4 отклоняла новый 10
(ранее alias 0). Нативное небо теперь принимает 0/1/2/4/7/10 и aliases 11/12,
с соответствующими blend и общим кэшем мира; Fog в небо не переносится.

CPU replay SkyMesh теперь использует общий CPU-only dispatch: сохраняются
переназначения 11/12 и static-lightmap scope, без повторного входа в M3G и без
смешивания native/CPU граней одного fallback-неба. У всех шести типов полигонов
убран ненужный расчёт старого additive Fog для выбранного M3G ALPHA-режима 1.
Software сохраняет эти расчёты и прежнюю семантику.

`ModeOptimizationAuditTest` проверяет все мировые режимы 0..13 и HW ON/OFF:
100 совместимых треугольников с разными bounds/глубинами → 2 native draws,
на прогретом кадре B=0, T=0, один bind/readback. Проверяются общий ALPHA-кэш
и batching для 1/4, обязательные границы blend для 7/10, native sky/world,
полный rollback новых sky-режимов, CPU sky aliases (включая missing API),
отсутствие старой Fog-подготовки 1 и общий кадр новых мировых материалов с
MUL-спрайтом, post-effect и RGB weather. Это синтетические contract-тесты,
не доказательство FPS/визуального результата на телефоне.

Оставшиеся штатные затраты: холодные/вытесненные текстуры требуют uploads и
могут потребовать барьер; разные blend нельзя смешивать в один пакет даже при
одном bitmap. Режим 7 теперь текстурированный, в отличие от старой одноцветной
имитации стекла; ALPHA и слои MODULATE добавляют overdraw. Цветовые варианты MUL
имеют отдельные записи в том же ограниченном кэше. Эти затраты не скрываются
и не отменяют сохранённые оптимизации batching/общей транзакции.

### Native-подготовка после отката

Кэш нормалей и ускоренная блочная сборка пакетов отменены. Производственные
`M3GMode5Lighting` и `M3GPolygonBatch` побайтно совпадают с версией `c981fce`.
Лимит пакета, painter order и native draw semantics сохранены.
Архив отменённого эксперимента: [отчёт](native-prep-optimizations.md).
