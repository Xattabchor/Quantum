# Второй рендер: M3G / JSR-184 (экспериментальный)

## Включение

В настройках добавлен пункт **Renderer: Software / M3G (experimental)**.
Переключение клавишами влево/вправо действует со следующего игрового кадра, в том
числе после выхода из паузы. По умолчанию остаётся Software.

В оригинальный `/setting.txt` при желании можно добавить:

```ini
RENDERER=M3G
```

Сохранённый выбор из меню имеет приоритет. Он хранится в отдельном RMS-хранилище
`Quantum.Renderer`; порядок и содержимое полей оригинального файла настроек/RMS
сохранений не менялись. Старые конфигурации без нового ключа работают как прежде.

### Аппаратная перспективная коррекция

После выбора M3G сразу под Renderer появляется **HW perspective: ON / OFF**.
Влево — выключить, вправо — включить; FIRE/SELECT переключает состояние.
По умолчанию **ON**, как в предыдущих сборках. Изменение применяется к следующему
native-проходу, в том числе при возврате из настроек паузы, без перезапуска игры.
При выборе Software строка скрывается, но выбранное значение сохраняется.

Настройка меняет `PolygonMode.setPerspectiveCorrectionEnable` у всех native
appearance: мир, модельное небо, спрайты, панорама и погодные полосы. У плоских
экранных примитивов глубина одинакова, поэтому заметной разницы не ожидается.
Кэшированные PolygonMode обновляются только при изменении выбора; геометрия,
UV, исходные цвета освещения, текстуры и буферы не перестраиваются. Общий проход
неба/мира не разделяется и дополнительных upload/readback не добавляется.
OFF разрешает аффинную интерполяцию M3G: на наклонных поверхностях текстура может
искажаться. Реальный результат и скорость зависят от реализации JSR-184;
ускорение на телефоне не измерено.

Это отдельная настройка, не замена исходному **PERSQ**: его значение, подготовка
однородных координат/тумана и Software не меняются. Аварийный CPU replay по-прежнему
использует прежнее качество Software, даже при HW perspective OFF.

Необязательный ключ `/setting.txt`: `M3G_PERSPECTIVE=1` (ON) или `0` (OFF).
Выбор сохраняется при выходе из настроек в отдельной однобайтовой RMS-записи
`Quantum.M3GPerspective`, с приоритетом над конфигурацией. Отсутствующая/некорректная
запись игнорируется. Оригинальные настройки, сохранения и `Quantum.Renderer`
не получают новых полей. Для перевода подписи можно добавить в языковой файл
`M3G_PERSPECTIVE=Аппаратная перспектива`; без ключа используется `HW perspective`.
Исходные языковые файлы не обязательны к изменению.

Для программного выбора:

```java
g3d.setRenderer(DirectX7.M3G);       // или DirectX7.SOFTWARE
```

Игровой экран синхронизирует этот выбор с `Main.renderer` каждый кадр. Программный
benchmark остаётся на Software. `getRenderer()` возвращает запрошенный режим,
`isM3GActive()` — наличие успешно созданного M3G backend, `getRendererError()` —
причину последнего отключения M3G. При ошибке не меняется пользовательская
настройка, но экземпляр рендера продолжает работу программно. Повторную попытку
можно разрешить переключением Software → M3G или изменением размера буфера.

## Что делает M3G

Новый `M3GSceneRenderer` использует `Graphics3D.render` с `VertexBuffer`,
`VertexArray`, `TriangleStripArray`, `Texture2D` и `CompositingMode`. Это отдельный
растеризатор, а не только вывод готовых CPU-пикселей через M3G.

Оставлены исходные загрузчики, преобразования моделей/анимаций, камера,
сортировка и видимость комнат/порталов. Backend получает уже спроецированные
вершины из общей очереди, восстанавливает однородные координаты и передаёт
геометрию в M3G. Благодаря этому сохраняется нестандартная проекция Quantum.
Для текстур с перспективной коррекцией восстанавливаются веса
`1 - rz/TexturingPers.move`, соответствующие знаменателю `move - rz` исходного
`TexturingPers`, а не фокусному расстоянию `distY`. Сохраняются исходные пороги
экранного размера для переключения affine/perspective и режим `persQ=4`;
для fast/affine-пути используются единичные веса. Преобразования и отсечение
остаются на CPU; растеризация поддерживаемых полигонов выполняется через JSR-184.

Сохраняется исходный painter-order; аппаратный Z-test намеренно выключен.
Это позволяет смешивать M3G-полигоны/спрайты с CPU-материалами без потери порядка.
Для четырёхугольников сохраняется исходный выбор диагонали: обычно ABD/BCD,
но базовый Polygon4V в режимах тумана 3/6 может использовать ABC/ACD в зависимости
от глубин вершин. Lighted/ColorLighted и fast-путь сохраняют ABD/BCD.

### Объединённый проход неба и уровня

В игровом `House.renderSkybox` немедленный `g3d.render()` заменён на
`g3d.renderBackground()`. В рабочем M3G это **не draw**, а сохранение уже
подготовленного неба в переиспользуемую отдельную prefix-очередь. Затем House
собирает мир, а существующий финальный `GameScreen → g3d.render()` выполняет
сначала sky prefix, затем независимо отсортированную очередь мира.

Небо не получает искусственную глубину и не участвует в world sort: даже
полигоны с предельным sz остаются поверх фона. Проекция, перспективная коррекция,
материалы, туман, Z-test и исходный порядок внутри каждой очереди не меняются.
SkyMesh хранит копию матрицы; PanoramaSky — снимок viewport/UV-layout, поэтому
сборка комнат и нового portal viewport не меняет уже подготовленный фон.

При прогретом кэше и полностью native-геометрии это один target bind/release,
один финальный readback и один frame backup, вместо отдельных транзакций неба
и мира. Для полного opaque SolidSky/PanoramaSky/SkyFlash не нужен старый upload
кадра. Промежуточный readback/upload **из-за самой границы небо→мир** удалён.
Модельное небо также может продолжаться уровнем в том же bound target, после
восстановления world camera. Выход из House без комнат не теряет sky-only prefix:
его обрабатывает тот же финальный render. Пустой следующий кадр его не повторяет.

Это не удаляет необходимые CPU-барьеры: неподдерживаемый материал/спрайт всё ещё
вызывает finish перед CPU. Cache miss по-прежнему может потребовать finish,
чтобы безопасно загрузить новую текстуру вне bound target. Поэтому первый кадр,
смена animation textures или переполнение кэша могут иметь больше одного обмена.
Градиентный/CPU fallback фон сохраняется при следующем native bind. Постобработка,
погодный/muzzle overlay, итоговый readback и MIDP flush остаются как прежде.

При ошибке draw/clear/readback/OOM восстанавливаются пиксели **до неба**, затем
оба этапа повторяются на CPU: сначала sky prefix, потом мир. Ошибка мира не
оставляет частично аппаратный фон. Prefix очищается вместе с основной очередью
в finally; ссылки на sky/texture освобождаются. Resize/destroy удаляют старые
очереди. При невозможности выделить prefix-буфер остаётся прежний немедленный
sky-pass. Software/debug/flushAlpha изначально работают в прежнем immediate-пути.

Внешний код, использующий renderBackground(), должен вызвать render() перед
чтением display/постобработкой/overlay, как это делает GameScreen. Прямой вызов
sky.render(...); g3d.render() также поддерживается для самостоятельного sky-pass.
FPS и визуальная проверка на устройстве не проводились; проверены счётчики
native-передач и порядок/откат в контрактных тестах.

### Общие рёбра и небо

Сначала квантуется однородный вес `q`, затем short-координаты вычисляются как
`X=(sx-cx)*q`, `Y=(cy-sy)*q`, `Z=-q`. Их проекция возвращает исходные целочисленные
экранные вершины даже при разных масштабах соседних полигонов. Раньше независимое
округление X/Y/Z допускало ошибку до 0.75 px на полигон: общие рёбра могли
расходиться и открывать фон. Если точные экранные координаты не помещаются в short
или относительная ошибка веса больше `1/128`, полигон остаётся на CPU, а не
передаётся в M3G с деформированной геометрией/перспективой.

### 3D-небо через M3G

Принудительный CPU-проход неба убран. `Skybox` передаёт модель отдельным
`SkyMesh`; `M3GSkyRenderer` получает **видовые координаты до проекции**, а не
пытается восстановить грани за камерой из испорченных экранных координат.

- На CPU остаются преобразования вершин и отсечение треугольников по `rz=0`
  и границам viewport. UV пересчитываются на пересечениях; буферы отсечения
  переиспользуются. Циклов программного текстурирования пикселей здесь нет.
- Для неба используется геометрическая перспектива с весом `distY-rz` и учётом
  отдельного `distX`. Это отдельный путь, а не веса `TexturingPers.move` для
  уже спроецированной геометрии уровня. Перспективная коррекция M3G включена.
- Однородные координаты нормализованы относительно экрана, а один short-масштаб
  используется для **всей модели неба**. Пересечения общих рёбер вычисляются в
  одинаковом направлении, чтобы соседние грани не расходились из-за округления.
- Растеризацию, текстурирование, alpha test/blending выполняет M3G. Обычная
  камера уровня восстанавливается после неба; Fog уровня на небо не переносится.
  Кэш текстур общий с уровнем, включая анимацию и замену RawImage.
- Поддержаны стандартные треугольники/четырёхугольники с материалами 0/4 —
  обычный загрузчик неба создаёт его при `standartDrawmode=0`. Другие материалы,
  неизвестные классы и непредставимые текстуры/веса сохраняют исходный CPU-путь
  **для всей модели**, а не для отдельных граней. При сбое native draw весь
  текущий проход откатывается; фон и мир повторяются исходным рендером.

Software по-прежнему рисует небо оригинальным кодом. Однотонный 2D-фон
`Skybox` (mode 1) в M3G теперь использует цвета вершин, как описано ниже.
Панорамное 2D-небо (mode 2) теперь имеет отдельный M3G-путь ниже;
градиентное mode 3 остаётся на исходном CPU-пути.
M3G-путь убирает CPU-текстурирование модельного неба, но копирование/readback
кадра остаётся. FPS на телефоне 220 МГц без замеров не гарантируется.

### Однотонное 2D-небо: цвета вершин

Только `Skybox` mode 1 при выбранном M3G создаёт переиспользуемый `SolidSky`.
Это полный экран из двух треугольников в одном draw call, одинаковый исходный RGB
во всех четырёх вершинах, alpha 255. Нет Texture2D, чтения bitmap, UV-сэмплинга,
света, тумана, смешивания или Z-test. Используются единичные веса: фон не меняется
при FOV/повороте камеры. Небо рисуется в существующем проходе до уровня;
размер quad обновляется после resize. Как и старый `clearDisplay`, заливка
покрывает весь буфер независимо от портального viewport.

Старые пиксели не загружаются в target перед полной непрозрачной заливкой.
Резервная копия и итоговый readback объединённого прохода остаются,
поэтому выигрыш FPS не гарантируется. При ошибках draw/readback/OOM, debug/flushAlpha или отсутствии
API используется исходный CPU `clearDisplay` с тем же цветом.

Формат и источник цвета в ресурсах не менялись. Software, градиентный mode 3
и модельное небо не затрагиваются. Панорамный mode 2 перенесён отдельно ниже. Грозовая вспышка остаётся
отдельной дешёвой `Graphics3D.clear` светло-серым цветом, без ветвей/засветки мира;
после неё снова рисуется обычный цвет однотонного неба.

### Панорамное 2D-небо через M3G

`Skybox mode=2` теперь создаёт переиспользуемый `PanoramaSky` и отправляет его
в sky prefix перед миром в объединённом проходе. `M3GPanoramaRenderer` рисует один
текстурированный прямоугольник панорамы и до двух одноцветных прямоугольников
сверху/снизу. Программного цикла выбора texel для каждого пикселя в успешном
native-пути больше нет. Буферы вершин, UV и цветов переиспользуются.

- Исходные вычисления rotateX/rotateY, FOV, horizonScale/horizonOffset,
  lowestDegree и portal viewport сохранены. Native-путь получает готовые
  origin/step исходного 12-битного sampler и учитывает центры пикселей.
- repeatX/repeatY задают UV, включая отрицательные и нулевые значения. Целые
  периоды удаляются перед float-конверсией, поэтому yaw вне 0..360 не требует
  копии/сдвига bitmap и не переполняет short UV. При непредставимом диапазоне
  повторов выбирается CPU fallback до любого native draw.
- Texture2D использует REPEAT/NEAREST, REPLACE, без Fog, освещения, Z-test/write.
  Все texel непрозрачны, включая исходный ноль/чёрный и дробную альфу: как у
  исходного панорамного sampler. Sprite cutout/alpha cache не переиспользуется.
- **Разрешение панорамы не уменьшается.** Берётся текущий texture.rImg,
  без sprite-downsample и без выбора polygon/sprite mip. Текстура загружается
  один раз и переиспользуется при вращении; замена RawImage/img создаёт запись
  общего ограниченного кэша. Исходные текстуры/файлы/параметры не изменяются.
- Поддерживаются POT-изображения в пределах maxTextureDimension/262144 texel
  и представимости UV. NPOT и слишком большие изображения рисуются исходным
  CPU-кодом, без принудительного уменьшения или потери фона. Разбиения большой
  панорамы на аппаратные texture tiles пока нет.
- Полностью непрозрачное небо на весь экран не загружает старый CPU-кадр в
  native target. При частичном portal viewport или отсечении lowestDegree
  старые пиксели вне области сохраняются через исходный upload.
- При сбоях любого из трёх draw, readback/OOM или отсутствии API весь проход
  откатывается и повторяется оригинальным render2D. flushAlpha и debug-overwrite
  используют CPU-путь. Software и градиентный mode 3 сохраняют исходный painter.
  Светло-серая M3G-грозовая вспышка по-прежнему заменяет только небо; после неё
  панорама возвращается, без ветвей молнии или засветки мира.

Backup/readback объединённого sky/world прохода и итоговый MIDP flush остаются. Наличие M3G
не гарантирует аппаратный GPU на каждом устройстве и не обещает прирост FPS.
Nearest sampling/округление на границах texel может отличаться от fixed-point
CPU; визуальная проверка на телефоне и замер FPS не выполнялись.

### Дождь и снег: M3G RGB-полосы

При выбранном M3G дождь снова рисуется **нативными полосами**, а не LCDUI.
`paintM3G` собирает дождь и снег в один ScreenLines batch до flush сцены,
после постобработки. `paintAfterScene` при успешном native-проходе больше
не рисует частицы повторно. Координаты framebuffer-local; screenY учитывается
только при flush или LCDUI fallback, а не в native-вершинах.

- Не более **16 дождевых капель** на кадр; лимит симуляции также сохранён.
- Восстановлены исходные диагональный наклон, длина по rainSize/depth,
  цвет rainColorNear/rainColorFar по глубине и белый цвет во время грозы.
- Каждая капля — нетекстурированная RGB-полоса шириной 1 пиксель:
  4 вершины/2 треугольника, до 32 частиц на native draw. Чистый дождь до 16
  капель помещается в один draw; снег использует тот же batch без лимита 16.
- Нет Texture2D/UV/alpha-компонент; `REPLACE`, alpha test 0, без Fog/Z-test/
  Z-write. Массивы переиспользуются, хвост вырожденный, полосы не соединяются.
- Снег сохраняет прежние RGB-прямоугольники и размер/цвет по глубине.
  При пустом кадре старый batch очищается.
- При native/readback ошибках, flushAlpha, debug или отсутствии JSR-184
  используется LCDUI fallback: исходный снег и до 16 дешёвых вертикальных
  дождевых линий. Успешный native-проход никогда не дублируется через LCDUI.

В отличие от предыдущего LCDUI-дождя native-путь снова требует транзакцию
backup/upload/readback кадра. Дождь и снег используют общую транзакцию,
но восстановление M3G **не означает гарантированного ускорения** на устройстве.

Лимит теперь действует **и на симуляцию**: создание частиц, update, все шесть
движений камеры, snow-поиск и painter работают по активному списку. При чистом
M3G-дожде это максимум 16 слотов независимо от исходного качества/числа частиц.
Остальной дождь не перемещается, не перегенерируется и не рисуется. При остановке
генерации (`generate=0`) ограничение сохраняется; снег (`generate=2`) работает
по прежнему полному массиву.

Список строится однократным обходом исходных массивов при входе в M3G-дождь,
после clear/замены массивов или возвращения из Software/снега. Обычные кадры
не сканируют неактивный хвост. При смешанных частицах все живые снежинки
добавлены в активный список сверх 16 дождевых слотов и продолжают двигаться;
после исчезновения удаляются из горячего списка, не создавая безлимитный дождь.
В режиме M3G-дождя один Random переиспользуется при update/create/move/moveB,
вместо новых объектов на каждом вызове. Массивы coords/info не обрезаются:
при возвращении в Software возобновляется работа со всей исходной плотностью,
включая ранее приостановленные капли. Формулы движения активных частиц, крыша,
зум и грозовые таймеры сохранены; сами таймеры вызываются даже при пустом списке.

В M3G дождь остаётся редким, но использует исходную форму/цвет капель.
Реальный FPS надо измерять на телефоне; ограничены и native-геометрия,
и горячая симуляция именно дождя.

Software сохраняет прежнюю полную плотность, глубинные цвета, диагональные длины
и порядок рисования; файлы настроек погоды не меняются. Ветви молнии в M3G
отключены, вспышка меняет только фон неба. В Software гроза прежняя.
Отдельный M3G-проход снега всё ещё требует backup/copy/readback кадра.

Поддерживаются стандартные Polygon3V/Polygon4V и их Lighted/ColorLighted варианты:

### Спрайты сцены через M3G

`M3GSpriteRenderer` получает все `Meshes.Sprite` из общего dispatch, в том числе
анимированные NPC, предметы и эффекты. Их `SpriteObject`/анимация/проекция,
портальная видимость, addsz и painter-order не меняются. Это не отдельный overlay:
спрайты остаются в отсортированной очереди между полигонами уровня, Z-test/write
отключены. Четыре вершины и два треугольника используют уже вычисленный экранный
прямоугольник. Растяжение, mirX/mirY и отсечение viewport пересчитывают UV, а не
выполняют программное текстурирование каждого пикселя. Буферы переиспользуются.

- `mode=0`: binary cutout, прозрачность только для нулевого texel; непрозрачный
  чёрный сохранён. Альфа ненулевого texel не превращает режим в полупрозрачный.
- `mode=1`: аппаратный ADD с насыщением. Как в оригинале, игнорирует флаг fog
  и дробную альфу исходного изображения. Возможны различия low bits до единицы
  канала: аппаратное смешивание не маскирует младшие биты фона.
- `mode=3`: ALPHA для RawImage.alphaMixing, иначе прежний binary cutout.
- `fog=true`: общий коэффициент по pos.rz/fDist, независимо от polygon fogQ.
  RGB исходной текстуры умножается цветом вершин. Цветной fog добавляется вторым
  masked-ADD проходом, сохраняя дырки и дробную альфу; при стандартном режиме 6
  остаётся чёрное затухание в один проход. ADD-спрайты туман не получают.
- `mode=2` (MUL со всеми color-вариантами) остаётся на точном исходном CPU-пути:
  это нестандартное насыщаемое поканальное преобразование фона, не обычный
  `src*dst`. Неизвестные режимы также возвращают false в общий CPU-dispatch.

Выбирается текущий `textures[anim_index]` и его mip[0], как у исходного painter,
а не mip-подбор полигонов. Render не меняет anim_index и не продвигает анимацию.
Нестепенные размеры разрешены: при первом upload **копия** изображения
уменьшается до ближайших меньших степеней двойки по каждой оси:
70×90 → 64×64, 127×65 → 64×64, 3×5 → 2×4. Округления вверх и padding больше
нет. POT-размеры не меняются: 64×128 остаётся 64×128, 128×128 — 128×128.
Это не принудительный лимит 64×64 для всех спрайтов.

Используется дешёвый nearest-neighbor по центрам texel, без смешивания RGB
прозрачных пикселей. Цвет и fog mask выбирают одни и те же исходные texel;
cutout/ADD/alpha сохраняют прежние правила прозрачности. UV покрывают всю
уменьшенную копию; wrapping CLAMP, фильтр NEAREST. Геометрия/размер/пропорции
спрайта на экране не меняются: меняется детализация текстуры, мелкие элементы
могут исчезнуть. Ресемплинг выполняется только на cache miss, не каждый кадр.
Исходные RawImage, массивы, размеры, настройки scale и файлы не меняются;
Software и CPU fallback используют исходное разрешение. Если и полученная
POT-копия превышает maxTextureDimension/лимит кэша, спрайт остаётся на CPU.

Кэш общий по лимиту с уровнем: 16 записей/262144 texel; учитывается размер
именно уменьшенной копии, а не исходника. Sprite cutout/alpha/ADD/fog masks имеют отдельные ключи,
чтобы их wrapping/альфа не портили материалы уровня. Повторные кадры и возврат
к уже закэшированному animation frame не требуют нового upload. Замена img,
RawImage или размеров создаёт новую запись; in-place изменение пикселей, как
и прежде, требует releaseRenderer(). Resize/переключение режима освобождают кэш.
На cache miss загрузка выполняется только вне bound target, с сохранением
порядка. На прогретом кэше переход полигон→спрайт→полигон сам по себе больше
не вызывает CPU readback/upload-барьер. Fog обычно требует два draw, остальные
поддерживаемые спрайты — один draw на объект; batching между объектами нет.

Software, HUD и LCDUI-оружие не меняются. При draw/readback/OOM/отсутствии API
весь проход откатывается и повторяется исходным CPU-кодом. flushAlpha и карта
перерисовки сохраняют программный путь. Пиксельное совпадение не обещается:
GPU nearest sampling/границы зеркалирования могут отличаться от старого
fixed-point/modulo sampler, fog/alpha — округлением на 1–2 единицы канала.
На телефоне визуальная проверка и замер FPS не проводились.

### Материалы 2, 5 и 8

- **2**: один аддитивный M3G-проход с насыщением. Нулевой texel остаётся
  прозрачным, любой ненулевой — непрозрачным источником независимо от дробной
  альфы исходного пикселя. RGB источника кэшируется с маской `0xfefefe`, как
  в Software. M3G не может сбросить младший бит каналов уже нарисованного фона:
  на образце texel результат может отличаться на **1 единицу канала** от CPU.
  Текстура загружается один раз на вариант кэша, не пересчитывается каждый кадр.
- **5**: один проход `texture × vertex RGB`, один коэффициент на весь полигон.
  Используется исходный `MathUtils.calcLight(normal, DirectX7.lightdir)`;
  native `Light`, выстрел, фонарь и camera-vector light не добавляются.
  Сохранена особенность оригинала: при `fogQ=0` perspective-путь не затемняет,
  а affine продолжает затемнять. Исходное деление на 256 аппроксимируется
  ближайшим восьмибитным M3G-множителем; разница на образце — до 1 единицы канала
  без учёта точности конкретного GPU. Это не затрагивает статические режимы 9/13.
- **8**: CPU только выбирает один цвет из исходной текстуры/выбранного mip,
  растеризация — M3G без загрузки `Texture2D`. Сохранены масштабирование UV,
  endpoint `255→256` для малых текстур и исходная wrap-маска. Нулевой пиксель
  означает **непрозрачную чёрную заливку**, а не отверстие. Для quad сохранены
  ABD/BCD: первая грань берёт цвет UV вершины A, вторая — B. Если цвета совпадают,
  достаточно одного draw call; иначе используются два. Освещение/туман не применяются.

Все три режима используют существующие painter-order, CPU-барьеры и полный откат
кадра при ошибке M3G/readback. Software и исходные файлы материалов не меняются.
Ограничения геометрии/точности и CPU fallback сохраняются; 2/5 также сохраняют
ограничения размеров M3G-текстур. У режима 8 такого ограничения на bitmap нет,
так как bitmap не передаётся в JSR-184.

### Отключённый dithering: материалы 10, 11 и 12

При выборе M3G номера 10/11/12 считаются **алиасами режима 0**. Вместо узора
и градиента рисуется обычная текстура с маской нулевого пикселя. Нет расчёта
покрытия по вершинам, `waterDistance` или `fDist`, alpha-перехода или отдельной
Bayer-текстуры. Это сознательное отключение эффекта, а не его имитация.
Выбор mip/перспективы, геометрия, цвета вершин и кэш — как у материала 0;
отдельные варианты Texture2D для 10/11/12 не создаются. Модельное небо также
принимает эти номера как обычную текстуру.

CPU fallback и аварийный replay при выбранном M3G тоже используют режим 0,
чтобы при отказе native backend дизеринг не возвращался. Для этого только на
время CPU-вызова номер материала подменяется и восстанавливается в `finally`.
Оригинальные файлы/поля материалов не меняются постоянно; при переключении
на Software исходные 10/11/12 работают по-прежнему. Старые функции дизеринга
не удалены, поскольку нужны Software. Общие геометрические/текстурные ограничения,
fallback для MUL/неподдерживаемых спрайтов и debug/alpha-барьеры остаются.

### Быстрая имитация стекла (материал 7)

Выбран самый простой вариант: **одноцветный полупрозрачный полигон без текстуры**.
Один ALPHA-проход на стандартный triangle/quad, постоянный серо-голубой цвет
`0xb0beca` и alpha `32/255` (около 12,5%). Это тонированное стекло,
**без разводов и настоящего преломления**.

Не используются исходные пиксели, UV, mip, Texture2D, фильтрация, освещение,
туман или снимок фона. Нет конвертации текстур, upload и места в кэше для этого
материала. Вершинные массивы переиспользуются, веса геометрии единичные:
перспективная интерполяция текстуры здесь не нужна. Сохраняются исходная геометрия
и painter-order; сквозь стекло виден ранее нарисованный мир.

Общий обмен framebuffer между M3G и MIDP **остаётся**: исключён только захват
кадра специально для преломления и CPU fallback из-за номера материала 7.
Ограничения геометрии, debug/flushAlpha и аварийный fallback сохраняются;
ограничений M3G-текстуры для стекла больше нет, поскольку она не используется.
При отказе M3G весь кадр переигрывается исходным Software, включая старое
искажение стекла. Исходные файлы и обычный Software-режим не менялись.
FPS/внешний вид на телефоне не проверены; большое число прозрачных слоёв всё ещё
увеличивает overdraw.

### Статические лайтмапы в M3G

Используется выбранный вариант **только статического освещения**: исходные
`LightedPolygon3V/4V.la/lb/lc/ld` и `ColorLightedPolygon3V/4V` RGB передаются
в M3G через `VertexArray` цветов. Сами исходные файлы `LIGHTMAP`, загрузчик
и поля моделей не меняются; перезапекать или конвертировать ресурсы не нужно.

- Материал 9 использует серую яркость. Материал 13 теперь также растеризуется
  M3G и сохраняет RGB при `fogQ=2`; при `fogQ=1` цвета усредняются в серый,
  как в исходном рендере. `fogQ=0` по прежней семантике отключает и освещение:
  текстура рисуется с белыми цветами вершин.
- В M3G-пути 9/13 не вызывается динамический `getLight`: выстрел, фонарь и
  camera-vector light **не меняют** статическое освещение. Это относится
  к обычному, affine/fast и mip-путям. Нативных `M3G Light`/point light нет.
- Дистанционное затухание сохранено отдельно: `visibility = 255 - clamp(-rz *
  255 / fDist)`, результат — `bakedRGB * visibility / 255`. При `fDist<=1`
  дополнительного затемнения нет. Коэффициент вычисляется один раз на вершину,
  без пересчёта текстур и без временных RGB-массивов в native-пути.
- Если выбран M3G, но конкретная геометрия/текстура ушла на CPU либо native
  draw завершился ошибкой, scoped static-путь 9/13 также исключает динамику.
  Флаги выстрела, фонаря и глобальный camera-vector light не подменяются;
  scope восстанавливается в `finally`, включая исключения и вложенный dispatch.
- При выборе **Software** всё работает по-старому: исходный `getLight`, реакция
  на выстрелы и фонарь сохранены. Полного совпадения M3G/Software теперь
  намеренно нет: выбранный M3G-вариант статический. Округление цветов и
  интерполяция M3G также могут отличаться от исходного растеризатора.

### Additive blob при выстреле

В M3G добавлен косметический `MuzzleGlow`: один quad / два треугольника с
процедурной тёплой радиальной RGBA-текстурой 32×32, bilinear-фильтрацией и
`CompositingMode.ALPHA_ADD`. Дополнительные игровые ресурсы не нужны.

- Импульс запускается только при успешном выстреле с существующим
  `SHOOT_LIGHT=1`. Сухой спуск/перезарядка его не запускают. `SHOOT_LIGHT=0`
  отключает и этот эффект, новых обязательных ключей нет.
- Длительность 120 мс, яркость быстро затухает по времени и уменьшается с
  расстоянием. Луч из текущей камеры ищет ближайшую коллизионную поверхность
  в пределах 5000 игровых единиц. В пустоте/при дальней стене blob не рисуется.
- Результат луча кэшируется на время импульса при неизменной позиции/оси камеры
  и комнате; новый выстрел, движение камеры или смена комнаты вызывают новый
  запрос. Это не постоянный дополнительный raycast каждый кадр. Косметический
  запрос не перезаписывает список видимых комнат/порталов и игровые scratch vectors.
- Blob рисуется после уровня/постобработки, перед погодой, flush, экранными
  overlay, HUD и 2D-оружием. Центр немного ниже середины вида; координаты локальны
  framebuffer, `screenY` применяется обычным flush. При смерти игрока он скрыт.
- Это **экранное свечение с проверкой близкой поверхности**, не decal и не
  настоящий M3G Light. Оно не учитывает форму стены/углы внутри всего пятна и
  не освещает модель оружия или лайтмапы. Кэш луча также не отслеживает движение
  дверей при неподвижной камере в течение короткого импульса.
- Текстура/геометрия переиспользуются; CPU не перекрашивает пиксели радиальной
  текстуры каждый кадр. Смена backend/resize/destroy сбрасывает старый импульс.
  В Software нового blob нет: прежний свет от выстрела остаётся без изменений.
- Ошибка native draw/readback/OOM восстанавливает исходный кадр и пропускает
  косметический эффект. При отсутствии JSR-184, framebuffer alpha или отладочной
  CPU-перерисовке он также не добавляется. Аддитивное состояние не переносится
  на следующие обычные материалы.

Один quad не означает бесплатный эффект: погодный и flash overlay-проходы
сейчас отдельные, с копированием/резервированием и readback кадра. FPS на 220 МГц
и качество картинки без проверки на телефоне не гарантируются.

## Туман в M3G

Используются существующие `DirectX7.fDist` / `fogc`, загружаемые из `FOGD`,
`FOGC` или `FOGCR/FOGCG/FOGCB`. Новых форматов ресурсов и обязательных ключей нет.
Туман применяется по исходному режиму материала, **не** накладывается глобально
на HUD или весь кадр. `Main.fogQ=0` отключает его без лишних проходов.

- **Mode 3, HQ perspective:** используется `javax.microedition.m3g.Fog` в режиме
  `LINEAR`. В восстановленной геометрии расстояние до камеры равно
  `1 - rz/TexturingPers.move`, поэтому near задаётся как `1`, far — как
  `1 + fDist/TexturingPers.move`.
  Передавать `FOGD` напрямую в эти координаты нельзя. Пересчёт выполняется при
  каждом материале, включая изменение цвета и дальности между кадрами.
  Изменение FOV само по себе не меняет веса UV или степень тумана.
- **Mode 3, affine/HQ или LQ:** постоянный Z affine-геометрии не подходит для
  штатного Fog. Вместо изменения перспективы текстуры используются два M3G-прохода:
  `texture * visibility`, затем `fogColor * (1 - visibility)` через `ALPHA_ADD`.
  Второй проход использует белую текстуру с исходной бинарной alpha-mask, чтобы
  туман не заполнял прозрачные отверстия. CPU вычисляет лишь коэффициенты вершин;
  текстурирование, интерполяцию и смешивание выполняет M3G. Цвета пикселей текстур
  на CPU не пересчитываются. Маска кэшируется независимо от цвета тумана.
- **LQ / LQFOG:** для цветного тумана сохраняется плоский коэффициент по самой
  дальней вершине каждой грани. Четырёхугольник обрабатывается по двум треугольникам
  выбранной исходным рендером диагонали. Сохранён старый целочисленный делитель `fDist/255`, включая нулевой
  делитель при малой положительной дальности. `forceLQFog` учитывается; affine
  mode 6, как в оригинале, использует HQ при `fogQ=2` независимо от этого флага.
- **Mode 6:** HQ perspective без camera-vector lighting использует линейный
  M3G Fog чёрного цвета, независимо от `FOGC`. Другие варианты используют
  умножение текстуры на серые цвета вершин через M3G. Для perspective/HQ с
  `LightMapper.cameraVectorLight` сохранён исходный расчёт направленного света.
- **Mode 1:** это не линейный туман, а насыщаемое сложение с постоянным RGB,
  вычисляемым из исходного fog color и глубины полигона. Используется
  `Texture2D.FUNC_ADD`; прозрачные нулевые пиксели остаются прозрачными.

Перед обычными материалами Fog, alpha blending, альфа вершин и texture function
устанавливаются заново: параметры тумана не переходят на последующие объекты.
Двухпроходный туман участвует в общей транзакции кадра: сбой даже во втором
проходе освобождает target и повторяет весь проход на исходном CPU-рендере.

При `fDist<=1` и включённом mode 3/6 используется CPU, поскольку старые affine
и perspective-пути по-разному обрабатывают такие значения. При непредставимом
native fog range используется M3G-путь по коэффициентам, а не недопустимый Fog.
Общие ограничения геометрии и текстур по-прежнему могут вызвать CPU fallback.

Побитового совпадения не обещается: M3G Fog использует интерполированную глубину,
а исходный HQ вычисляет и ограничивает коэффициенты по вершинам; округление и
интерполяция на границе дальности могут отличаться. Mode 1 также может отличаться
на младший бит цвета из-за старой битовой арифметики. Двухпроходный вариант требует
дополнительной mask-текстуры и draw calls; лимит кэша общий для всех типов текстур.
Спрайтовый туман пока остаётся на CPU. Dithering-материалы 10/11/12 в M3G
намеренно заменены режимом 0, а не перенесены как точечный эффект.

### Самая простая гроза: светлый фон неба

При выбранном M3G вспышка только заменяет фон неба на `0xe5e5e5` на прежние
135 мс. `Skybox` не рисует модель/градиент/skyLighting в эти кадры, не генерирует
ветви молнии. Засветка поверх мира отключена в GameScreen и дополнительно в
WeatherGenerator, в том числе после отказа native backend. Стены и предметы
не светлеют; если небо не видно, эффект может быть совсем незаметен.

`SkyFlash` передаётся в существующий проход неба перед уровнем. M3G выполняет
`Graphics3D.clear(Background)` с отключённой очисткой глубины: **без треугольников,
текстур, alpha blending и отдельного overlay поверх мира**. Background и объект
эффекта переиспользуются. При привязке target для такой очистки пропускается
загрузка старого CPU-кадра: он полностью заменяется цветом. Уровень после этого
отрисовывается обычным способом, закрывая фон. По окончании вспышки автоматически
возвращается выбранный обычный вид неба.

Остаются резервная копия и итоговый readback объединённого sky/world прохода:
это не полный отказ от обмена кадром между M3G и MIDP. При clear/readback/OOM ошибке проход
откатывается, SkyFlash выполняет обычный `clearDisplay` тем же цветом.
Debug/flushAlpha/отсутствие API также сохраняют простое светлое небо, **не**
возвращая ветви или дорогую засветку. Software сохраняет исходную грозу целиком:
настроенный skyLighting, болты молнии и градиентную засветку вне крыши.
Оригинальные ресурсы/таймеры/погода не меняются. Предыдущие StormFlash и
M3GStormFlash с отдельным additive overlay удалены. FPS на телефоне не измерялся.

## Совместимость ресурсов

Форматы моделей, QCT/обычных текстур, уровней, скриптов и игровых сохранений не
изменены. Конвертация в M3G-объекты выполняется в памяти **после** штатной загрузки;
перепаковывать модели в `.m3g` не нужно. Мип-уровни выбираются из исходных RawImage,
анимация текстур использует текущий RawImage. Текстуры загружаются в RGBA без
изменения оригинального массива. Для mode 0/1/3/6/9 ненулевой пиксель остаётся непрозрачным,
для mode 4 сохраняется дробная альфа.

Для полигонов текстуры с размерами, не являющимися степенями двойки,
превышающие аппаратный лимит или лимит одного cache entry (262144 пикселя),
обрабатываются программно. Для спрайтов действует описанное выше уменьшение
NPOT-копий до меньших POT-размеров. То же касается
вершин за камерой и случаев, когда short-координаты M3G не позволяют сохранить
точные экранные координаты и достаточно стабильные веса перспективы. Ресурс не отвергается и не заменяется
пустой текстурой.

Кэш ограничен 16 записями и 262144 пикселями суммарно. Замена `RawImage` или
его `img` создаёт новую запись. Если пользовательский код меняет содержимое
публичного массива `RawImage.img` **на месте**, нужно вызвать `g3d.releaseRenderer()`
для сброса кэша. Изменение размера экрана, смена backend и `destroy()` освобождают
его автоматически.

## Кадровый буфер и отказоустойчивость

M3G рисует в mutable LCDUI Image. Перед native-сегментом он получает текущие
CPU-пиксели; перед CPU-объектом и в конце `render()` M3G target освобождается, а
результат возвращается через `Image.getRGB` в **тот же** `DirectX7.display`.
Таким образом виньетка, эффекты урона/смерти, bloom, погодные эффекты и фон паузы
продолжают работать через исходный кадровый буфер. HUD и меню остаются на LCDUI.

`flushAlpha=true` и отладочная карта перерисовки целиком используют Software:
mutable Image не гарантирует сохранение исходной альфы, а счётчик перерисовки
требует CPU-растеризации.

До M3G-прохода сохраняется копия пикселей. При отсутствии JSR-184, исключении
native API, ошибке readback или OutOfMemoryError текущий target освобождается,
восстанавливается исходный буфер и **вся очередь** данного прохода повторяется
программно. Backend отключается для этого экземпляра до явного повторного выбора
или resize. Sky prefix и world queue, а также внутренняя очередь MeshImage,
очищаются и при исключении. Не используются повторные попытки M3G каждый кадр.

## Ограничения и производительность

Это совместимый гибридный backend, а не полностью аппаратный scene graph.
Постобработка и сложные материалы остаются CPU-операциями. Копирование/readback
и чередование CPU/M3G могут сделать его **медленнее** исходного рендера, особенно
на сценах с чередованием CPU-MUL/неподдерживаемых спрайтов и native-материалов. Требуются дополнительный
Image и резервный int[] кадра. Ускорение и побитовое визуальное совпадение не
гарантируются. Способ перспективной интерполяции/выбора mip и округление могут
отличаться. Наличие JSR-184 само по себе не гарантирует аппаратное ускорение.

Оригинальный экспериментальный `Meshes.M3GParser` оставлен для совместимости,
но новый backend его не использует.

## Сборка и тесты

Используется тот же `scripts/build_cldc.py`, что описан в
[инструкции сборки](build-cldc.md). В API classpath нужен JSR-184.
Вывод обоих backend использует исходный MIDP `Graphics.drawRGB`.
Nokia DirectGraphics удалён, Nokia UI API для сборки и работы не требуется.
Обфускация выключена; при её включении дополнительно сохраните имя/конструктор:

```text
-keep class code.Rendering.M3GSceneRenderer { public *; }
```

После сборки на desktop JDK:

```sh
python3 tests/m3g/run.py
python3 tests/framebuffer/run.py
python3 tests/settings/run.py
```
