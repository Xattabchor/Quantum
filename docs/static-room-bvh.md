# BVH / Grid — отсечение геометрии, alpha test всегда включён

Пользователь попросил попробовать другой вид отсечения геометрии, оставить
alpha test включённым и убрать код его отключения. Предыдущий замер Alpha:
A OFF N82/I109, B ON N85/I109, FPS9/8 — устойчивый выигрыш не установлен.

Новый эксперимент — **BVH frustum culling** вместо крупных пространственных
групп 4×4. Это **не occlusion culling** и не смена winding/back-face режима.
Грани, закрытые стеной, специально не ищутся: перекрытие решает depth buffer.

## Скачать и сравнить

[JAR](../downloads/Quantum_StaticRoom_Bvh.jar) ·
[JAD](../downloads/Quantum_StaticRoom_Bvh.jad) ·
[Состав и SHA256](../downloads/Quantum_StaticRoom_Bvh.build-report.json)

- По умолчанию **A BVH** — дерево полных bounding box граней, максимум 8
  полигонов в листе. Вне frustum исключаются целые поддеревья.
- **0 → B GRID** — прежняя консервативная сетка 4×4; повторное нажатие — A.
- Alpha test всегда использует исходный порог текущего изображения:
  **0,5 для cutout**, 0 для полностью непрозрачного. Переключателя alpha нет.
  Это не принудительный порог0,5 на каждой непрозрачной текстуре.
- **Near128 / far60000** одинаковы в A и B, как у Depth по умолчанию.
  **5 ничего не меняет**. Байты конфига с исходным DIST68500 сохранены.
- `4/6` — поворот, `2/8` — движение, `7/9` — вбок, `#` — выход.

Встаньте на одном месте, подождите 5–10 секунд в каждом режиме, повторите A/B/A.
Пришлите **FPS, N, I, T и V** из одной и той же позиции/направления.
N — весь render, включая Java-подготовку и native API/release, не чистое GPU-время.
I — интервал кадров. T — треугольники отправленных strips; V — число проверок
bounding box (узлов BVH или групп сетки), **не число вершин**.

## Реализация и неизменённые параметры

Дерево строится один раз при загрузке. Разбиение — по медиане центров полных
face-AABB вдоль самой длинной оси. Узлы хранятся в плоских int-массивах, не в
объектном графе. Bounding box листа охватывает полные грани, а не только их
центры: длинные стены и полы, пересекающие несколько регионов, не обрезаются
по центроиду. Используется прежняя консервативная проверка шести плоскостей
реальной native-проекции и квантованной матрицы камеры.

Обход дерева лишь отмечает грани. Список индексов формируется **в исходном
порядке**, без перестановки strip/triangles и без перекадровой сортировки.
Тот же cache из **двух** selection-index buffers на пакет разделяется между
BVH и Grid: отдельного неограниченного кэша BVH нет. Точное совпадение byte-mask
видимых граней позволяет повторно использовать индексы. В фиксированном режиме
после прогрева индексы/вершины/текстуры не создаются заново. При новой маске
во время движения возможны allocation/upload **индексов**, как и у сетки.

**Не менялись:**

- исходные модель и `.vla`: 4750 полных треугольников, 10032 угла в vertex buffers;
- XYZ/UV/baked-RGBA, текстуры/их RGBA/анимация, nearest/base-level без mipmap;
- blending REPLACE и исходный MODULATE реки; depth test / depth write;
- `CULL_BACK`, `WINDING_CW`, perspective correction;
- Image target, culling вне frustum, near/far, максимум 3 native calls;
- все 172 класса и все 10 ресурсов базового Depth (кроме нового manifest).

Это **не полигональный LOD**: новый оптимизатор моделей здесь не применяется.
Уменьшается список отправленных примитивов вне камеры. Полные vertex buffers
остаются прежними; будет ли M3G преобразовывать только используемые вершины,
зависит от реализации. Меньше T не является доказательством большего FPS.

В новой сборке **нет StaticRoomAlpha-классов и API setAlphaTestEnabled**:
код отключения alpha не переносился. Новый renderer основан непосредственно
на исходном Depth, а не на Alpha. Старый Alpha JAR и его исторический overlay
оставлены отдельно только для воспроизводимости и отката, не входят в новый JAR.

## Ограничения и память

BVH делает больше CPU-проверок и занимает дополнительный heap при загрузке.
На E65 это может оказаться как выгоднее, так и медленнее. Во время движения
более точная видимость может чаще менять маски и увеличивать работу с индексами.
Сами vertex/texture uploads остаются cold-only.

При **OOM selection-index cache** до bindTarget сохраняется целиком готовый
native whole-room путь: все 4750 треугольников, alpha test включён, без CPU
raster fallback и без повторных попыток аллокации масок. HUD `MEM->whole`
означает, что сравнение отсечения уже недействительно. Дерево при этом
освобождается. Это не обработчик OOM любой стадии: нехватка памяти при
первоначальном создании геометрии/дерева завершит загрузку с ошибкой.
Старый Depth/Alpha остаётся внешним откатом в таком случае.

Не является исправлением Z-buffer/просвечивания стен, пересчётом коллизий,
проверкой аппаратного ускорения или доказательством растрового совпадения E65.

## Проверки source и packaged JAR

- **208** random/coincident tree cardinality cases: нет пропавших/дублированных
  граней, полные face/child AABB, <=8 граней/лист, bounds источника не меняются,
  некорректная матрица камеры консервативно оставляет всё.
- **864** реальные комбинации: 3 позиции × 3 pitch × 24 yaw × 4 кадра реки.
  Каждый отброшенный треугольник независимо проверен double homogeneous clipping.
  Ни один видимый тестовый треугольник не отброшен. Сохраняются исходный порядок,
  координаты, UV, свет, texture RGBA, alpha/blending/depth/projection.
- B GRID побитово совпадает по native draw-пакетам с исходным Depth при тех же
  near128/far60000. Fixed A/B после прогрева не создают новые native indices.
- Холодный Viewer: все 6 изображений, A BVH по умолчанию, key0 roundtrip,
  правильные HUD/near/far, key5 no-op; alpha-disable API отсутствует.
- Native bind/viewport/clear/render/OOM/release failures освобождают target.
  Index-mask OOM сохраняет complete native whole room и не повторяет allocation.
- Прежние 3456 Depth near/far/pose/frame cases, 9 resource tests и 7 immutable
  rollback checkpoints; preverify CLDC1.1 / class47.0, 180 классов.
