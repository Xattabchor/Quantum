# Quantum Model Optimizer 1.0

Отдельный офлайн-оптимизатор **собственного формата Quantum `.3d`**. Это не
Autodesk `.3ds`, не универсальный конвертер и не модификация игры.

## Быстрый запуск

**Браузер:** откройте `Quantum_Model_Optimizer.html` из архива двойным щелчком.
Это один самодостаточный файл: интернет, сервер и npm не нужны. Или откройте
`model-optimizer/index.html`, сохранив рядом остальные файлы этой папки.
Нужен современный браузер с WebAssembly; это инструмент для ПК/современного
браузера, **не приложение для Nokia E65 / Java ME**.

1. Выберите `.3d` и соответствующую исходную `.vla`, если есть baked-свет.
   Для текущей деревни: `maps/kordos/kordos.3d` и `lightmap/kordod.vla` из JAR,
   формат **DMODE9**, а не RGB. JAR можно открыть ZIP-архиватором.
2. Укажите долю треугольников, которую хотите **оставить**. Начните с 75%,
   ошибки 5 и бережного режима. Цель может оказаться недостижимой.
3. Внесите индексы всех прозрачных/водных/анимированных материалов в список
   защиты. По умолчанию защищён 4 — река текущего sym9. Это индексы текстур,
   **не номера DMODE**. Для других моделей список нужно уточнять вручную:
   `.3d` не содержит информацию о типах смешивания и анимации материалов.
4. Подтвердите, что это статическая визуальная модель. Создайте копию.
5. Скачайте **оба** новых файла и JSON-отчёт. Каркас помогает сравнить
   геометрию, но не показывает текстуры/свет/коллизии. Обязательно осмотрите
   результат в отдельном тесте игры, сохранив оригиналы для отката.

Если baked-свет не используется или будет запечён заново, явно выберите
работу без lightmap. **Прежняя `.vla` не подходит изменённой топологии.**
Перенос сэмплов не является повторным расчётом света: после упрощения может
измениться интерполяция и вид теней даже при сохранении исходных значений.

Все вычисления происходят локально в памяти браузера; сетевых запросов и
отправки выбранных файлов нет. Скачивание — создание нового файла; browser
может предложить имя с суффиксом, если такой файл уже есть.

## Режимы и ошибка

- **Бережный / safe:** атрибутное упрощение, защита границ и швов.
- **Умеренный / balanced:** `Permissive` с дополнительной защитой UV-швов
  (`vertexLock=2`): допускает схлопывание вдоль, но не произвольно поперёк швов.
  Атрибуты baked-света учитываются в метрике, не гарантируются визуально.
- **Экспериментальный / experimental:** `Permissive` без защиты UV-швов.
  Требуется отдельное явное согласие `allowSeamChanges`. Возможны изменение
  разрывов UV, растяжение текстур и повреждение теневых переходов.
  Границы материалов и выбранные защищённые материалы остаются защищены.

Ошибка — **приближённая комбинированная квадричная метрика meshoptimizer**,
`ErrorAbsolute`, в исходной системе координат, до масштаба из конфига.
Это **не** проверенный максимум расстояния до поверхности, Hausdorff,
максимальное смещение каждой вершины или ошибка в пикселях. Для деревни scale6:
число 1000 в интерфейсе не означает безопасный допуск 1000 мировых единиц.
UV и RGB участвуют с весами 1/256 и 1/255; CLI позволяет увеличить эти веса.
Большой допуск может сильно испортить модель. Для чисто плоских сеток
геометрическая ошибка может быть почти нулевой и при большом сокращении.

## CLI (Node.js 18+)

Никакого `npm install` не требуется. Из папки `model-optimizer`:

```sh
node cli.cjs inspect original.3d --lightmap original.vla --format gray9

node cli.cjs optimize original.3d --output reduced.3d \
  --lightmap original.vla --lightmap-output reduced.vla --format gray9 \
  --static --ratio 0.75 --error 5 --mode safe --protect-materials 4
```

Без baked-карты вместо двух аргументов lightmap нужно `--without-lightmap`.
`--format color13` читает/записывает RGB с переменными `colored`-флагами.
`--report report.json` задаёт путь отчёта; иначе это `reduced.3d.report.json`.
`--uv-weight 2 --light-weight 2` усиливает учёт атрибутов, не даёт строгой
гарантии их интерполяции. `--protect-materials ""` снимает пользовательскую
защиту целых материалов; фиксированные границы материалов остаются.

Для экспериментального режима нужны **оба** параметра:
`--mode experimental --allow-seam-changes`. Осторожно с допуском ошибки.

CLI отказывается перезаписывать **любые** существующие файлы, включая отчёт,
входную модель, карту и симлинки. Имена выходов должны отличаться.
В случае ошибки записи удаляются только новые файлы, созданные этим запуском.

## Что именно сохраняется

- Раздельные меши, индексы материалов 0..255, big-endian int16 координаты.
- Используются только исходные позиции и исходные UV/RGB сэмплы углов.
  Новые координаты, UV, значения света и текстуры не генерируются.
- Материалы обрабатываются отдельно; общие позиции на границах материалов
  фиксированы. Защищённые материалы не упрощаются. Их corner-данные и порядок
  внутри секций triangle/quad сохраняются; номера вершин могут уплотняться.
- Открытые границы `LockBorder`, `PreserveFolds`, якорный треугольник на каждую
  компоненту связности по позиции. Нет `Prune`, `Sloppy` и намеренного удаления
  мелких отдельных предметов. Это НЕ полная топологическая сертификация.
- При неизменённой итоговой геометрии возвращаются исходные файлы побайтно.
- Lightmap переставляется в новый порядок мешей/полигонов/углов движка.
  Gray9 — XOR128. RGB13 — красные углы, bool colored, затем G/B каждого угла.
- После экспорта результат заново разбирается и проверяется.

## Почему считаем не только полигоны

В native-рендере текущей диагностики один quad — 4 угла и 2 треугольника.
Простая замена на два triangle даёт **6 углов**, хотя треугольников столько же.
Утилита восстанавливает неизменённые исходные quad-пары. Также может объединить
две соседние в потоке копланарные выпуклые треугольные грани: строго те же два
ориентированных треугольника, UV/свет и диагональ. Проверяется нативная
диагональ **ABD / DBC**, не обычный fan ABC / ACD.

Если кандидат не уменьшил **и** треугольники, **и** expanded-corners, исходный
меш сохраняется. Это защита от очевидного увеличения native-потока, **не**
измерение скорости GPU, индексов Strips, draw calls или трафика памяти E65.
Draw calls могут вообще не уменьшиться. Меньшая модель или JAR ≠ больший FPS.

## Проверка на исходной деревне

Только офлайн-проверка копии `kordos.3d` + `kordod.vla` из неизменённого
`Quantum_StaticRoom_Depth.jar`. Цель во всех строках — оставить 50%, материал4
защищён. FPS и внешний вид на телефоне **не проверялись**.

| Режим | Ошибка | Треугольники | Углы native-кэша | Удалено треугольников |
|---|---:|---:|---:|---:|
| Исходник | — | 4750 | 10032 | — |
| safe | 5 | 4742 | 10024 | 0,17% |
| balanced | 100 | 4692 | 9954 | 1,22% |
| experimental | 100 | 4130 | 9278 | 13,05% |
| experimental | 1000 | 2534 | 6692 | 46,65% |

Сильное сокращение получено **только с разрешением менять швы и большим
допуском**. Это не рекомендация сразу ставить последний вариант в игру.
Много UV-швов, материалов и мелких объектов ограничивает бережное упрощение.
Синтетические регулярные сетки сокращаются намного легче.

## Границы применения

Не использовать как автоматический оптимизатор кадров morph-анимации,
порядка вершин для внешних ссылок, порталов, маршрутов NPC, секций карты и
коллизий. Изменяются индексы вершин и порядок части непрозрачных граней.
Гарантий отсутствия самопересечений/изменений всех деталей нет. Если один файл
служит и картинкой, и коллизией, нужна отдельная проверка коллизий; утилита
не встраивает LOD в игру автоматически. Нельзя определить причину тормозов
или вылечить ошибки Z-buffer одним сокращением геометрии.

Поддерживаются до 256 мешей, int16 лимиты исходного формата, до 500000
треугольников суммарно, файл до 64 MiB. Это защитные лимиты утилиты, не новые
лимиты игрового формата. Соответствие модели и lightmap по смыслу и версии
нельзя доказать по одним байтам: проверяются формат и длина, выбирать надо
именно соответствующую оригиналу карту.
