# MDA Minimal Probe v1.0.0 — Nokia E65

Отдельный диагностический эксперимент, не исправление игры. Рабочий поток создаёт новый MDA player и вызывает Play непосредственно из успешного MapcInitComplete. Периодического poller, watchdog и self-completed AO в рабочем потоке нет. Одноразовый RTimer-bootstrap нужен для входа в startup под trap планировщика. Телеметрия и bootstrap всё ещё могут влиять на тайминг. При выходе из приложения незавершённый рабочий поток принудительно останавливается; это не проверка корректного завершения MDA.

## Проверка на телефоне

1. Установите SISX в память телефона C:. Проба отдельная, удалять игру и другие пробы не нужно. Файл звука — `C:\data\q41_min_shot.wav`. Если сертификат отклонён, сообщите об этом, не ослабляйте защиту.
2. Запустите **MDA Minimal**, нажмите **1**, послушайте и сфотографируйте экран после обновления примерно через 3 секунды. Если поток ещё работает, подождите и нажмите **0** для обновления; сфотографируйте снова.
3. После завершения потока нажмите 1 ещё несколько раз и сообщите, сколько раз слышен звук и появляется ли ошибка запуска -11. Пока поток работает, новая команда 1 игнорируется. Если зависает, выйдите Back/Esc и сообщите об этом. Если закрывается всё приложение, сообщите отдельно.

`O` — вызван OpenFileL; `I` — результат init; `P` — входов/возвратов Play; `C` — число callback завершения; `E` — его код; `T` и `TO` сохранены для сравнения и должны оставаться 0; `R` — результат потока только при штатном завершении или обработанном leave; `S` — стадия запуска. 9999 означает, что callback ещё не зарегистрирован. При panic начальное R=0 не означает успех. Экран обновляется по нажатию, не непрерывно.

## Статическая проверка

ARMv5T/EKA2, SDK 0.3.0; UID3 `0xE000A03A`, package UID `0xE000A03B`. Самоподписанный RSA-1024/SHA-1 сертификат 2000–2045; приватный ключ удалён. Writer сообщает signed/registered, 4 файла, статический MDA ordinal 35, без MIDI. Все 4 файла извлечены из SISX и совпали с входными байтами.
