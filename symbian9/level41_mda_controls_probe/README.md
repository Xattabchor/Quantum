# MDA Controls Probe v1.0.0 — E65

Отдельная диагностическая проба, не исправление игры. Каждый запуск создаёт новый поток. Во всех трёх режимах одинаковые одноразовый RTimer-bootstrap и четырёхсекундный таймер наблюдения, который запускается **до** открытия файла; периодического poller нет. Таймер и телеметрия могут изменить поведение по сравнению с Minimal Probe.

## Проверка

Установите SISX в память телефона **C:** и откройте **MDA Controls**. Это отдельное приложение; игру и старые пробы удалять не нужно. Звуковой файл устанавливается как `C:\data\q41_ctl_shot.wav`. Если сертификат отклонён, сообщите об этом, не меняя защиту телефона.

1. Нажмите **1** — только таймер, плеер не создаётся, звука быть не должно. Через примерно пять секунд экран обновится. Сфотографируйте его.
2. Нажмите **2** — создание плеера и открытие WAV, без Play; звука быть не должно. Сфотографируйте экран.
3. Нажмите **3** — открытие того же WAV и Play из успешного init callback. Сообщите, слышен ли звук, и сфотографируйте экран.
4. При возможности повторите каждый режим три раза. Если поток ещё работает, дождитесь завершения и нажмите **0** для перерисовки; нажатие 0 может не менять изображение, если показания прежние. Новая команда режима игнорируется, пока предыдущий поток работает. Если приложение зависло или закрылось, сообщите какой режим и что произошло. Выход Back/Esc принудительно останавливает незавершённый поток; таймер не может прервать синхронно зависший вызов.

`Mode` — режим; `Start` — результат создания потока. `Exit type/reason` и категория — результат потока, включая panic. `O` — OpenFileL вызван; `I` — код init callback; `P` — входов/возвратов Play; `C` — число callback завершения; `E` — его ошибка; `T` — оставшийся от предыдущей пробы счётчик, всегда 0; `TO` — общий таймер наблюдения сработал успешно (1) или нет (0), в случае ошибки отображает её код; `R` — результат при нормальном завершении, при panic начальный 0 ничего не доказывает; `S` — стадия запуска. `9999` означает, что callback ещё не получен. Даже при TO:1 дальнейшее удаление плеера может вызвать отдельную ошибку. Если timer сработал до успешного init, сравнение режима 2 или 3 не состоялось. Режим 3 сохраняет плеер до таймера даже после callback, поэтому TO:1 без panic не означает, что исходная проблема исправлена.

## Статическая проверка

ARMv5T/EKA2, SDK 0.3.0; UID3 `0xE000A03C`, UID пакета `0xE000A03D`. Самоподписанный RSA-1024/SHA-1 сертификат 2000–2045; приватный ключ удалён. Writer сообщает signed/registered, четыре файла, статический MDA ordinal 35, без MIDI. Все 4 файла извлечены и побайтово совпали с входными. SHA-256: SISX `bd406f1b09c9fa466609aba95c7fe62ba5c5d547c5a876429c33f01a8102f19e`, E32 `36b2fe31726b64a8529a811b99e4943b2b9201dfef5e5143dd2f57fc1e70651f`, WAV `99ef9989a3b17949a2bd4cfbadfa6b2f16d84f33b207a01b91b42d72c0e25d3b`. Эта сборка ещё не проверена на E65.
