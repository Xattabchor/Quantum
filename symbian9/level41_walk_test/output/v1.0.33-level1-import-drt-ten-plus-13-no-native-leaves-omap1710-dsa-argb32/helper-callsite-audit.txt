# DRT helper-callsite audit — v1.0.33

Result: **the final E32 address-retention probe contains no helper-call instruction, and the whole-image relocation audit finds no call relocation to any of the 12 added DRT helper ordinals.**

- Shipped E32: `quantum_level41_walk_test.exe`, 190,916 bytes; SHA-256 `0d23b4b408167a83870f1c2d577dd9d51a5f1155b51f7a461ea056e7e72fb2b4`.
- Instruction-level scan reads the original shipped E32 bytes at code base `0x8000`. The Thumb probe symbol is `0x00029e45` (VMA `0x00029e44`); its E32 file offset is `0x21ee0`, and its function size is 176 bytes.
- Capstone package 5.0.9 (engine 5.0.7) decoded the 128-byte executable body as 64 Thumb instructions. It found **0 `BL` and 0 `BLX`** instructions; the body returns with `BX LR`, followed by an alignment NOP. The remaining 48 bytes are the 12 `R_ARM_GOT_PREL` literal words and are treated as data, not instructions. Machine-readable results and the reproducible scanner are `final-e32-helper-instruction-scan.json` and `scan_e32_helper_instructions.py`.
- Address-retention function: `quantumDrtAdditional13AddressRetentionProbe`, linker-retained via `--undefined` only and unreferenced from startup/runtime code. The final-image disassembly, rather than the generated Thumb assembly, is the instruction-level evidence; `helper-address-probe.s` is retained as source provenance.
- Each added helper symbol has one `R_ARM_GLOB_DAT` relocation and zero `R_ARM_CALL`, `R_ARM_THM_CALL`, `R_ARM_JUMP24`, or `R_ARM_PLT32` relocations anywhere in the linked image.
- The final E32 has one import slot per added ordinal. These are GOT data fixups, not calls. The custom proxy DSO is link-time-only and is not packed into the SIS.
- The proxy labels these 12 exports `DATA 4` to model function addresses as GOT slots for conversion. The E32 import table carries the DLL/ordinal/fixup, without the proxy type annotation; no helper address is invoked by the launch path.
