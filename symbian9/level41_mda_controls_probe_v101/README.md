# MDA Controls Probe v1.0.1 — cleanup diagnostic

Отдельная проба, не исправление игры. В v1.0.0 режимы 1 и 2 дошли до таймера, но поток завершился с reason -6. Найдено возможное объяснение: два CActive объекта создавались через нативный `User::AllocZ`, а скомпилированные удаляющие деструкторы вызывали SDK `operator delete`, который ожидает собственный заголовок и при его отсутствии завершает поток с -6. Это сильная гипотеза для -6, не доказанная на устройстве, и не объяснение panic 46.

В этой версии только для двух объектов CActive пробы добавлено освобождение через `User::Free`, а также стадии очистки `K`. Три режима, bootstrap, четырёхсекундный таймер наблюдения и WAV оставлены по смыслу прежними, но сборка и телеметрия отличаются; влияние на timing возможно.

## Проверка

Установите SISX в память **C:**; это отдельное приложение **MDA Controls 101**, старые пробы и игру удалять не нужно. Файл звука `C:\data\q41_ct2_shot.wav`. Если телефон отклонит сертификат, сообщите об этом, не ослабляйте защиту.

Нажмите по очереди **1** (только таймер, звука нет), **2** (открытие без Play, звука нет), **3** (открытие и Play, должен быть звук). После каждого нажатия подождите около 5 секунд и сфотографируйте показания. Если поток ещё работает, подождите и нажмите 0 для обновления; команда следующего режима не запустится до завершения текущего. Если приложение зависло или закрылось — сообщите режим. Back/Esc принудительно останавливает незавершённый поток.

`O`, `I`, `P`, `C`, `E`, `TO`, `R`, `S` имеют прежний смысл: TO=1 означает срабатывание общего таймера, I/E=9999 — callback ещё не получен. `R` при panic не означает успех. Новое `K` — стадия очистки: 0 ещё не началась; 1 перед удалением bootstrap; 2 перед удалением observation; 3 перед удалением session/player; 4 перед удалением scheduler; 5 перед удалением trap cleanup; 6 всё это прошло. Она не гарантирует отсутствие ошибки после K=6. При успешной инициализации режима 2 timer может сработать прежде, чем init придёт: такой случай не доказывает успешное открытие.
